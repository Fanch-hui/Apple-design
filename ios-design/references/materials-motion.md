# 色彩、材质与动效

来源：《iOS 原生 App 视觉与交互设计规范》2026-10-28 研究版。沿用原文章节编号及【系统】【推荐】【条件】标记；文献标识对应[资料出处](sources.md)。

## 7. 色彩、圆角、边界、玻璃材质与模糊体系

### 7.1 颜色体系：语义先于十六进制

**【系统】优先使用系统语义颜色**，让页面跟随浅色/深色模式、高对比设置和系统状态。深浅两种模式分别审视文字、按钮、分割线、选中态和危险操作。[A17][A03]

| 视觉职责 | 推荐语义 | 用法 |
| --- | --- | --- |
| 页面底色 | System Background / Grouped Background | 选择普通或分组背景体系 |
| 内容表面 | Secondary System Background 等 | 仅用于需要显性分组的区域 |
| 主要文字 | Primary Label | 内容标题、正文、按钮文字 |
| 次要文字 | Secondary Label | 来源、时间、辅助解释 |
| 弱提示 | Tertiary Label | 非关键注释，保持可读性 |
| 细分隔线 | Separator | 列表中必要的视觉分隔 |
| 主品牌强调 | Tint / Accent | 主要按钮、可点链接、选中状态 |
| 成功状态 | 系统绿色等语义状态色 | 结合图标或文字，避免纯颜色判读 |
| 危险状态 | 系统危险红色 | 删除、严重失败、不可逆操作 |

**【推荐】单页面保持一个主要强调色，另有必要的语义状态色。** 不是每张卡片都要一个独立颜色；在常规设置列表和资料管理工具中，未染色或低饱和度图标通常更稳定。

### 7.2 背景分层和分割线

- **Level 0：主背景**。安静、连续的页面背景；大量日常 App 使用浅色/深色系统底色即可。
- **Level 1：内容分组**。通过系统 grouped list 或必要的次级背景区分。
- **Level 2：当前操作表面**。按钮、选择器、输入区域，有可感知交互状态。
- **Level 3：浮动系统控件**。Toolbar、Tab Bar、Sheet 等拥有独立的材质和遮挡关系。

**【推荐】结构的主要工具依次是：对齐 → 间距 → 字重/颜色 → 分组背景 → 分隔线 → 阴影。** 阴影用于真正悬浮的对象，普通静态列表无需每行有投影。

### 7.3 圆角、同心与视觉节奏

- 圆角是容器关系的表达：小标签约 8–12pt、普通自定义卡片约 12–16pt、较大媒体容器约 16–24pt。【推荐】
- 大容器内嵌小容器时，**内外圆角应呈自然递减关系**，并考虑内边距，视觉上形成相近的圆弧中心。
- 系统导航、Sheet、按钮和输入控件直接采用系统圆角与胶囊形状；避免把所有原生控件强行改成相同的 16pt 圆角。
- 同一页不宜同时存在大量互不相干的 8、12、17、23、30pt 圆角；自定义外形保持 2–3 个等级即可。

### 7.4 六种容易混淆的透明、玻璃与模糊效果

| 效果 | 原理与外观 | 适合用在 | 重要边界 |
| --- | --- | --- | --- |
| **Liquid Glass（regular）** | 动态透射/折射、适配背景光照的控件材质 | 系统工具栏、Tab、悬浮功能控件 | **导航/交互层**优先；系统组件自动采用 [A14] |
| **Liquid Glass（clear）** | 背景细节透过更多、透明感更强 | 照片、视频上的少量浮动控件 | 背景繁杂时补暗化，保证按钮清楚 [A14] |
| **Standard Material** | 系统磨砂、模糊和视觉融合 | 内容层的局部浮层、内容面板、说明衬底 | 遵循系统明暗与无障碍设置 [A14] |
| **Scroll Edge Effect** | 控件区与可滚动内容之间的边缘视觉过渡 | 顶部/底部浮动栏覆盖滚动内容处 | 自动样式优先；不用于纯装饰 [A15] |
| **Gaussian Blur** | 对整张图片/某个 View 均匀模糊 | 图片背景、失焦媒体、图像氛围 | 不适合模糊主要文字或操作控件 |
| **Masked / Progressive Blur** | 模糊量沿空间方向逐渐变化 | 图片边缘、媒体与文字的特定融合 | 自定义图片视觉可用；系统导航边界优先 Scroll Edge |

**这六项应按“功能职责”选择。** 普通内容区想获得一点半透明背景，使用系统 Material；内容滚动进入浮动栏时，使用 Scroll Edge；媒体图像需要氛围虚化时，用 Gaussian 或渐变遮罩；需要原生浮动控件层时由 Liquid Glass 承载。

### 7.5 Liquid Glass 的适用范围与密度

**【系统】Apple 的 Materials 文档明确将 Liquid Glass 视为导航和控件层，标准 Material 负责内容层的视觉分隔。** 系统组件可自动采用对应材质，应用不宜给所有普通卡片都叠加 Glass。[A14]

- **regular Glass**：首选。背景亮度变化时更容易保留前景文字与按钮的可读性；适合有文字的浮动控件。
- **clear Glass**：图片/视频等视觉丰富内容上方的少量控件。Apple 提到背景较亮时可考虑约 35% 暗化层，以提高对比；这是一个场景化建议，具体效果仍由系统、内容和用户透明度偏好决定。[A14]
- **容器组**：相关的系统 Toolbar 控件由系统形成共享材质组，避免每一个操作都叠一块单独玻璃胶囊。
- **层级控制**：一般页面只保留少量浮动玻璃区域，如顶部操作栏 + 底部 Tab；内容中不增加一整片玻璃卡片矩阵。
- **个性化与无障碍**：iOS 27 允许用户进一步调整玻璃透明与染色程度，设计需要适应该设置变化。[A26]

第三方 NNGroup 对 iOS 26 的分析指出，复杂背景与过量透明控件会损害可读性与可预测性；iOS 27 已对 Liquid Glass 对比与材质扩散作出改进。实际设计取舍应让内容始终居于视觉中心。[T01][A26]

### 7.6 Scroll Edge Effect：自动、soft、hard 的精确选择

**【系统】Scroll Edge Effect 用于“可滚动内容正在经过固定浮动控件下方”的交界处。** 它不同于覆盖一块固定半透明颜色或将整页模糊；它是专门解决层级可读性的系统效果。[A15]

| 样式 | 视觉特征 | 推荐使用 |
| --- | --- | --- |
| **automatic** | 由系统结合滚动、工具栏、文字和当前平台决定；iOS 27 有独立优化的视觉外观 | **默认首选** |
| **soft** | 靠近控件处有更自然的逐渐模糊，向内容区柔和消退 | 以图像、简单控件为主的轻盈过渡 |
| **hard** | 较不透明、边界清楚，能更强地把上层控件和文本与内容分开 | 工具栏控件密集、有裸露文字、固定表头等 |

**iOS 27 的重要变化：** `automatic` **不再只是从 soft/hard 中切换**，而是 Apple 为清晰度重新设计的独立默认效果；旧版本中习惯一律指定 `soft` 的视觉策略应根据当前设计语言重新考虑。[A25]

**边缘过渡的布局原则：**

- 上方有滚动标题栏/固定工具栏：交界处使用顶部系统 edge effect。
- 下方有底部工具栏/Tab 等浮动控件：由系统处理底部遮挡与过渡。
- 一块内容区原则上只使用一套滚动边缘效果，避免多个软、硬模糊层叠加。
- 如果没有浮动控件覆盖滚动内容，就不需要增加 edge effect 装饰。
- 浮动栏下的最后一行内容必须仍能滚动至完整可见的位置。

### 7.7 高斯模糊与自定义渐进模糊如何使用

**Gaussian Blur（高斯模糊）**是对所选图像/视图范围进行较均匀的视觉虚化。它适合**图片作为背景**的场景，例如专辑背景、照片详情的氛围图、模糊预览、背景弱化。

**【推荐】自定义图片虚化的起始参数（非 Apple 统一标准）：**

| 场景 | 可先尝试的模糊半径 | 注意 |
| --- | --- | --- |
| 保留形状的轻微图片柔化 | 4–8pt | 内容轮廓仍可辨识 |
| 图片背景与前景文字分离 | 8–16pt | 与暗化渐变或语义衬底配合 |
| 强氛围背景、专辑色彩扩散 | 16–32pt | 以色彩/大轮廓为主，不承担精确信息 |
| 更强的抽象背景 | 32pt 以上 | 仅在刻意追求抽象视觉时使用 |

**Progressive / Gradient Blur（渐进模糊）**指模糊强度**从 0 向某一值逐渐变化**，常用于照片底部由清晰过渡到模糊，或图像顶部自然融入文字区。它通常需要空间渐变控制或遮罩。建议过渡范围依据图片和文字块确定，常见可以从 **40–120pt** 的区域开始调整【推荐】，不要机械套在所有内容上。

**选择示例：**

- 相册详情页底部有照片说明：优先高对比文字衬底；背景仍需看见时考虑照片局部渐进模糊。
- 文章滚动到顶部工具栏下方：系统 Scroll Edge Effect。
- 项目详情中的一块普通透明说明面板：Standard Material。
- 需要创建类似系统胶囊的浮动导航：Liquid Glass 控件样式。

### 7.8 色彩与材质的透明度、阴影和对比

- **【系统】普通文字在混合背景上必须保持可读**。系统会依据用户的“增加对比度”“降低透明度”和 Liquid Glass 偏好调整材质；自定义透明区域也应有清楚的替代视觉。[A03][A14]
- **【推荐】纯色底 > 渐变底 > 玻璃底** 是普通工具页的一般优先顺序：越复杂的材质，越需要有明确的层级用途。
- 实际存在上下浮动关系时，可使用轻微阴影增强分离；Material、Glass 已提供层级感时无需再叠大幅投影。
- 不要将高饱和图片直接铺在整页正文背后；确有品牌背景时，为文本提供稳定的高对比表面。
- 卡片内不叠加多个渐变、描边、投影、玻璃与背景模糊效果来表达同一个层级。

## 8. 动画、手势、触觉反馈与状态变化

### 8.1 动画的作用

**【系统】动效应帮助用户理解动作因果、空间关系、状态反馈与内容切换。** Navigation Stack、Sheet、Tab、Toggle、Picker 默认拥有平台习惯的交互式运动；保留其原生节奏。[A19]

建议为自定义动画建立如下节奏，**这些时长是设计推荐起点，不是 Apple 强制参数**：

| 动画用途 | 【推荐】参考时长 | 推荐运动方式 |
| --- | ---: | --- |
| 轻触/按压反馈 | 100–180ms | 小幅透明度或高光/形态变化 |
| 选中态/开关旁附属提示 | 150–250ms | 颜色、图标与内容柔和过渡 |
| 图标替换、短提示出现 | 180–280ms | 淡入淡出、轻度缩放 |
| 小区域展开/折叠 | 200–350ms | 内容高度与透明度协同 |
| 卡片重排、插入/删除 | 200–400ms | 与布局变化同步，优先弹簧感 |
| 自定义面板、空间过渡 | 250–450ms | 距离与层级相符的移动/过渡 |
| 长流程、媒体主视觉 | 350–600ms，谨慎使用 | 仅在确有叙事或空间价值时 |

**【推荐】高频操作的动画要短且稳定。** 切换 Tab、列表选中、重复编辑不应持续出现夸张弹跳；系统组件的原生动画优先于统一“全站 300ms ease”。

### 8.2 动画与视觉层级的联系

- **进入下一层**：从当前位置进入详情，空间关系由原生 push/pop 表达。
- **临时覆盖**：Sheet/Popover 出现时，保留它与原页面的从属关系。
- **展开/折叠**：只改变当前对象的内容密度，不导致整页毫无规律地移动。
- **增删对象**：新条目从操作产生的位置进入列表；删除后相邻项目自然重新排列。
- **状态完成**：按钮/图标可短暂变化，任务结果在内容区更新。
- **滚动联动**：系统大标题收起、导航控件收缩等已有自然联动；避免叠加视觉无关的视差效果。

### 8.3 触觉反馈

**【系统】触觉用于强化有意义的操作与状态，而非给每一次触摸附加震动。**[A20]

| 场景 | 建议 |
| --- | --- |
| 在多个离散选项间切换 | 轻量 Selection 反馈 |
| 完成有明确结果的操作 | 一次轻量 Success 反馈 |
| 重要错误或不可继续 | 有节制的 Warning / Error 反馈 |
| 长按进入拖动/重新排序 | 进入交互态时给清楚反馈 |
| 普通列表滚动 | 通常不额外触觉 |
| 每次点击普通导航 | 原生按压视觉通常已足够 |

### 8.4 手势规范

- **侧边返回**：保留 iOS 熟悉的从边缘返回语义；避免用全屏横向拖动劫持返回手势。
- **滑动操作**：作为快捷入口，搭配可见替代路径。危险动作位置、颜色和可撤销行为明确。
- **长按菜单**：对具体对象的补充动作，例如复制、重命名、分享；主要功能不完全隐藏在长按里。
- **拖动排序**：给出拖动把手或明确可移动状态；结束后列表位置保持稳定。
- **捏合缩放**：图片、地图、画布等二维媒介适用；普通列表不需要自定义缩放。
- **下拉刷新**：适用于用户预期可手动更新的内容流，系统刷新指示自然出现；本地稳定数据无需每页强行下拉刷新。
- **滚动**：保留 iOS 弹性惯性，避免同方向 ScrollView 嵌套；有横向内容时显示局部露出的下一张卡片提示可滑动。[A21]

### 8.5 状态转移应保持布局稳定

- 按钮从“保存”变成“保存中”时保持大致位置和尺寸。
- 列表加载优先使用与最终行结构接近的占位布局，不反复触发全屏闪烁。
- 空状态 → 有数据状态，由当前内容自然过渡；避免所有元素大幅从屏幕外飞入。
- 对异步后台变化使用温和提示；重要状态改变要让用户看出发生了什么。
- 错误反馈贴近受影响对象，修复后自然恢复正常状态。
- 大型不可逆操作需要明确结果，同时让用户理解能否撤销。

### 8.6 减少动态效果与降低透明度

**【系统】尊重系统辅助功能偏好。** 用户开启 Reduce Motion 时，自定义大幅移动、重复缩放、强视差应改用更简单的淡入淡出或直接状态切换；减少透明度时保留足够清晰的不透明衬底。动态字体放大时，动效也应配合新的元素尺寸。[A03][A19]

### 8.7 主流工具类 App 的动画密度建议

- 常见导航、筛选、普通切换：**以系统原生效果为主**。
- 直接反馈（点击、选中、保存成功）：轻、短、清楚。
- 产品核心交互（可拖拽画布、项目卡片重排）：可增加针对性动作连续性。
- 首次引导和庆祝反馈：可有少量视觉个性，重复出现的频率降低。
- 持续背景漂浮、无意义光晕运动、每次都弹跳的按钮：只在明确的创意娱乐场景考虑。
