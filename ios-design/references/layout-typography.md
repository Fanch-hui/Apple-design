# 布局、尺寸与字体

来源：《iOS 原生 App 视觉与交互设计规范》2026-10-28 研究版。沿用原文章节编号及【系统】【推荐】【条件】标记；文献标识对应[资料出处](sources.md)。

## 1. 界面结构、信息层级与页面职责

### 1.1 设计的优先顺序

1. **任务与信息**：用户进入页面后，应迅速看到当前最重要的内容或操作。
2. **空间与层级**：用位置、对齐、尺寸、留白、字重表达重要程度；背景、描边和阴影作为辅助。
3. **系统行为**：遵从 iOS 的返回、滚动、拖动、弹层、键盘、选择、分享及状态反馈。
4. **品牌与精致感**：将品牌色、字体、图标、微动画集中在有辨识价值的区域。

【系统】Apple 的布局文档强调：相关内容应当分组，必要的信息要有足够空间，控件与内容形成可辨识的两个层级；当内容延伸到浮动导航下方时，用滚动边缘过渡维持可读性。[A02][A14]

### 1.2 页面类型与应有结构

| 页面类型 | 适合承载的内容 | 标题 | 内容形态 | 典型主要操作 |
| --- | --- | --- | --- | --- |
| 一级入口页 | 产品核心区域，如“记录、发现、消息、我的” | 大标题或清晰的紧凑标题 | 列表、概览、内容流 | 新建、搜索、筛选 |
| 列表/集合页 | 可重复浏览的一类对象 | 明确页面名称；一级页面可用大标题 | `List`、分组列表、网格 | 新建、排序、筛选 |
| 详情页 | 单个对象的详细内容与相关操作 | 通常为短标题；必要时可省略 | 纵向分区、媒体、属性行 | 编辑、分享、收藏 |
| 创建/编辑页 | 输入或修改一个对象 | 以对象/操作命名 | 表单、编辑画布 | 完成、保存、取消 |
| 临时任务页 | 选择范围、过滤、添加附件 | 简短标题或任务名称 | Sheet、系统选择器 | 选择、应用、完成 |
| 设置页 | 偏好、账户、通知、隐私 | “设置”或当前设置类目 | `Form` / grouped `List` | 开关、选择、进入子项 |
| 沉浸阅读页 | 文章、照片、视频、地图 | 通常用紧凑或可隐藏标题 | 全屏内容/阅读区 | 分享、标注、播放 |
| 空内容页 | 初始使用、无结果、无权限 | 传达当前状态 | 短说明 + 单一引导动作 | 创建、重新搜索、授权 |

**【推荐】单屏强调一个主任务。** 一级页面可以展示多个功能入口，但应有一个显著的阅读起点；编辑页明确“完成/保存”；详情页主要操作与当前对象相关。主操作、辅助操作、危险操作在位置和视觉重量上区分开。

### 1.3 页面层级与视觉优先级

- **第 0 层：全局结构**。Tab Bar / 侧边栏定义“我在哪个区域”；全局搜索或全局账户入口只保留清楚的固定位置。
- **第 1 层：当前页面**。页面标题、主要内容或搜索范围；操作栏用于“对当前页面做什么”。
- **第 2 层：内容分区**。分区标题、项目列表、筛选、图文对象；独立分区之间使用明显大于组内的间距。
- **第 3 层：局部信息**。正文、数值、时间、状态、辅助说明；以字体/颜色降低视觉权重，不把每个元信息做成彩色胶囊。
- **临时层：Sheet、Menu、Alert、Popover**。进入时应明确作用范围，结束后回到原上下文。

典型阅读顺序为**上→下、前缘 leading→后缘 trailing**；支持右向左书写的语言时顺序随系统变化。【系统】[A02]

### 1.4 主要内容与操作内容分层

在 iOS 26/27 的设计语言中，**内容层**呈现文字、照片、列表和可阅读对象；**控件层**承载系统导航、工具栏、Tab Bar 与浮动交互控件。控件层可以覆盖内容层，但内容须在靠近该边界时获得适当的淡出/模糊和避让。避免在同一视觉平面上叠放多个有透明背景的操作组。[A14][A15]

**【推荐】工具/效率类 App 的默认视觉风格：** 单一平静底色、系统分组列表、稳定的前缘对齐、少量强调色、低密度阴影。照片、视频、地图、可视化数据才值得使用更多全幅视觉与沉浸层次。

## 2. 尺寸系统、间距、留白、对齐与响应式布局

### 2.1 设计单位和屏幕边界

- **【系统】iOS 使用 pt** 进行界面设计，@2x/@3x 表示资源像素倍率。自定义组件的 16pt 间距在不同倍率设备上保持同样的逻辑尺寸。
- **【系统】遵守 Safe Area**：Dynamic Island、传感器区域、Home Indicator、系统导航与键盘都会影响安全范围。顶部/底部安全区高度以运行环境为准，**不统一写成固定数字**。[A02]
- **【系统】背景、摄影图和滚动内容可以延伸到边缘**，文字、主要按钮和输入控件优先对齐到安全区域内的内容边距。
- **【系统】避免固定 Navigation Bar、Tab Bar、状态栏的高度**。系统在滚动、动态字体、Liquid Glass 和尺寸变化时会调整表现。
- **【推荐】自定义常规页面左右边距为 16pt**，更具阅读感的页面可使用 20pt；分组 `List` / `Form` 优先采用系统 inset。横屏和宽屏根据内容宽度自动调整，而非把 16pt 直接同比放大。

### 2.2 全局间距等级

**【推荐】以 4pt 为基础节奏，实际使用离散间距，不在每个区域自创数字。Apple 没有要求所有 App 必须遵循 4pt 网格。**

| Token | 数值 | 最适合的关系 | 反例 / 注意 |
| --- | ---: | --- | --- |
| XXS | 2pt | 小型角标、紧密基线微调 | 不作为按钮间距 |
| XS | 4pt | 同一组小图标与短标注、状态值 | 不能承担分区分隔 |
| S | 8pt | 标题与说明、图标和标签、紧密控件 | 内容复杂时改为 12pt |
| M | 12pt | 列表行内部、输入控件与就地提示 | 大分区距离不够明显 |
| L | 16pt | 默认页面左右边距、卡片内边距 | 系统组件保留系统 inset |
| XL | 20pt | 舒适阅读边距、大对象内部 | 避免对窄屏过度压缩 |
| 2XL | 24pt | 普通不同模块之间 | 适合页面纵向分组 |
| 3XL | 32pt | 不同语义区域、标题区与正文区 | 不宜用于每一行之间 |
| 4XL | 40pt | 空状态文案上方、首屏大留白 | 应由布局关系决定 |
| 5XL | 48pt | 大型沉浸区和独立视觉区 | 应保留屏幕空间效率 |
| 6XL | 64pt | 极少数首屏主视觉/编辑画布间隔 | 工具页慎用 |

**实际组合推荐：**

- 一个图标与其文字：**8pt**；图标本身视觉大小约 **18–24pt**。
- 同一条内容的主标题与次要信息：**4–6pt**；信息行中不同组约 **12–16pt**。
- 分区标题至第一行内容：**8–12pt**；两个分区之间约 **24–32pt**。
- 卡片内边距：**12–16pt**；内容复杂的媒体/概览卡片 **20pt**。
- 分区底部到下一分区标题：优先 **24pt**，复杂内容可以 **32pt**。
- 相邻主次按钮纵向排列：**8–12pt**，应保持两者可独立点按。

这些数字用于**自定义容器与布局**；系统 `List`、`Form`、`NavigationStack`、`Toolbar` 的内边距遵守系统默认优先。[A02][A10]

### 2.3 尺寸与形状参考

| 元素 | 【推荐】视觉尺寸 / 间距 | 说明 |
| --- | --- | --- |
| iPhone 内容水平边距 | 16pt，舒适阅读可为 20pt | 与页面同侧内容共享起始线 |
| 点击区域 | **44×44pt 为默认目标【系统】** | Apple 无障碍表列 iOS 默认 44pt、特定场景最低 28pt；一般 UI 以 44pt 设计更稳妥 [A03] |
| 主要按钮 | 高 48–56pt | 一屏一个显著按钮，能随文字和动态字体增高 |
| 次要按钮 | 高 44–48pt | 系统文字按钮遵循自身内建区域 |
| 文本输入框 | 单行约 44–52pt | 多行输入自适应增长 |
| 紧凑单行列表 | 高约 44–52pt | 以系统行高与内容为准 |
| 常规图文列表 | 高约 52–64pt | 动态文字/双行信息自动增高 |
| 大型摘要列表 | 高约 72–96pt | 仅在图像、状态或说明确有需要时 |
| 图标视觉大小 | 18–24pt | 不等于可点击区域，配合 SF Symbols 字重 |
| 小型独立容器圆角 | 8–12pt | 标签、输入衬底、小预览 |
| 普通自定义卡片圆角 | 12–16pt | 有明确独立视觉身份时 |
| 大图 / 浮层圆角 | 16–24pt | 取决于媒介与容器尺度 |
| 列表分隔线 | 系统 `separator`，细线 | 无须固定为自定义灰色 |
| 表单说明与字段间距 | 4–8pt | 直接关联字段的提示 |
| 页面段落之间 | 12–20pt | 与系统字体行高协调 |

**【系统】圆角的具体数值随组件与系统风格变化。** 上表圆角只用于自定义表面，不覆盖系统 Button、Sheet、Search Field、Tab Bar 的自动形状。相邻嵌套容器应保持圆角同心、视觉上连续，而非重复使用完全相同的外圆角。[A22]

### 2.4 四条对齐规则

1. **文本以 leading 对齐**：页面标题、分区标题、列表主标题、表单标签和说明优先共享对齐轴。设置页内的右侧值、时间、计数器可以 trailing 对齐。
2. **列表建立隐形列线**：左侧图标/头像同列；标题与副标题同列；右侧箭头/开关/数值同列。图标行和纯文本行可采用不同内容起始位置，但分组内部需稳定。
3. **长文本避免居中**：长说明、正文、表单、错误消息以 leading 排列；居中适合空状态、成功反馈和一两句短文案。
4. **数字保持易比较**：金额、日期、计时等右侧数值对齐到同一末端，必要时用等宽数字；表格列对齐保证用户可以快速扫描。

避免在一行中同时塞下图标、两行标题、金额、状态、按钮和更多菜单。空间不足时让次要信息转到第二行，不要靠缩小到 11pt 硬塞。

### 2.5 留白的语义

**【推荐】留白本身属于结构信息。** 同组相关项距离应小于不同组距离。一个页面可用“12pt 组内间距 / 28pt 组间间距”产生足够层次；分割线只在有帮助时添加。

- **减法优先**：密集设置或功能入口优先 grouped list；不要把每个设置项包成独立的圆角卡片。
- **分区与标题**：有共同语义的一组控件用一个短标题与可选 Footer 说明，避免为每行都写解释。
- **容器的必要性**：内容需要独立触摸、预览、选择、拖动，或者具有明显的边界时才使用卡片。
- **上下滚动连贯**：长页使用连续内容流；避免多层高度固定的局部滚动区域争夺手势。
- **首屏视线焦点**：主要信息在安全区内优先出现；顶部大幅插画不应把核心操作挤到屏幕之外。

### 2.6 适配不同宽度与文本长度

- **窄屏**：图文并排优先让文本换行；两列操作必要时改为纵向堆叠；单个大按钮保持页面水平边距。
- **宽屏/横屏**：正文可以使用适宜的最大阅读宽度，列表/详情可以改为双栏。不要让正文横跨过宽的屏幕。
- **文字变大**：行高和卡片高度随内容增长；横向按钮可能改为竖向。动态字体不应以截断来维持固定盒子。
- **iOS 27 尺寸变化**：iPhone 镜像窗口和 iPhone App 在 iPad 上可以出现可调整窗口，布局依据实际可用宽度与 size class；原生 iPhone 底部 Tab 在宽屏时可以按产品选择适配 Sidebar。[A25]
- **本地化**：中文、英文、阿拉伯文及系统字号变化均影响布局；使用 leading/trailing 语义对齐，并为按钮标题预留扩展空间。

## 3. 字体、字号、字重、行高与标题规范

### 3.1 字体体系

**【系统】在 iOS 中优先使用系统语义字体和 Dynamic Type。** 拉丁字符使用 SF Pro 家族，中文由系统适配对应中文字体与回退机制；不建议为整个 App 强制安装或固定某一套中文字形。[A04]

- **SF Pro**：常规界面、标题、按钮、文字、列表。
- **SF Pro Rounded**：温和、亲和、轻松的产品可用于局部强调；不应把复杂办公表单统一改成圆体。
- **SF Mono / 等宽字体**：代码、日志、技术标识，或者强调字符精确排列的内容。
- **等宽数字**：金额、排行、计时、统计表；保持正文与数字的视觉一致性。
- **品牌字体**：封面、少量品牌标题、特殊创意模块可使用；一般控件和高频操作保留系统字体。

### 3.2 Apple 默认动态字号表

下表对应 iOS 默认内容大小类别 **Large** 下的语义类型。**数值作为视觉基准；真实界面随用户系统设置改变。**[A04]

| 系统文本样式 | 默认字号 | 系统默认行高约 | 默认视觉角色 | 建议使用位置 |
| --- | ---: | ---: | --- | --- |
| Large Title | 34pt | 41pt | 页面身份 | 一级页大标题 |
| Title 1 | 28pt | 34pt | 高优先级标题 | 独立页面主标题、重点模块 |
| Title 2 | 22pt | 28pt | 内容节标题 | 详细分区、空状态标题 |
| Title 3 | 20pt | 25pt | 局部标题 | 长详情模块小标题 |
| Headline | 17pt | 22pt | 强调正文，系统默认半粗 | 列表主信息、信息要点 |
| Body | **17pt** | 22pt | **普通正文基准** | 正文、列表、重要说明 |
| Callout | 16pt | 21pt | 小号主信息 | 简短说明、辅助文本 |
| Subheadline | 15pt | 20pt | 次级信息 | 列表副标题、摘要 |
| Footnote | 13pt | 18pt | 元数据 | 时间、来源、非关键状态 |
| Caption 1 | 12pt | 16pt | 细小标注 | 图表注释、可选辅助信息 |
| Caption 2 | 11pt | 13pt | 极小标注 | 极少量非关键标签 |

**【推荐】一张页面主要使用 3–4 个层级**：例如 34 / 17 / 15 / 13，或者 22 / 17 / 15 / 13。避免一页同时出现 34、28、24、22、20、18、17、15、14、13、12 等大量相近层级。

**尺寸取舍：**

- 用户要阅读或理解的正文：**17pt Body 优先**。
- 常规次级说明：**15–16pt**。
- 时间、来源、状态中的非核心元信息：**13pt**。
- 12pt、11pt 留给极少量辅助标记；对重要按钮、错误、帮助说明不采用极小字号。
- 页面内数字 KPI：根据视觉主次可采用 **22 / 28 / 34pt** 等 Title 级别，但数字标签仍用 13–16pt 形成层级。

### 3.3 字重怎么分配

| 字重 | 建议用途 | 使用频率 |
| --- | --- | --- |
| Regular（400） | 正文、普通列表、说明、输入值 | 最常用 |
| Medium（500） | 可点文本、短标签、次级重点 | 适量 |
| Semibold（600） | 关键列表标题、局部小标题、按钮、当前选中项 | 适量 |
| Bold（700） | 少量大标题、重要结果数字 | 节制 |
| Heavy 及以上 | 活动主视觉、营销或极强品牌图形 | 少量专用场景 |

**【推荐】优先通过字号和留白强调标题，字重作为第二层强调。** 过多 Semibold 会让整个页面像一片持续加粗的文字。对于层级清晰的常规正文，Regular 已经足够。

### 3.4 行高、字间距和中文排版

- 默认优先保留**系统语义字体附带的行高与字距**，正文参考 17/22pt 的节奏。
- 长段中文正文可以适度增加段落之间的空间，优先使用**段落间距**而不是人为大幅增加字间距。
- 标题与对应正文之间距离约 **8–12pt**；长内容段落之间约 **12–20pt**，章节之间 **24–32pt**。【推荐】
- 中英文混排与数字使用自然系统基线；表格数字需要可比性时使用等宽数字。
- 一般中文左对齐；避免长段文字两端强制拉伸产生不均匀空洞。
- 重要标题可换行，尤其中文对象名称；长文本中的中间省略号适合保留文件名首尾识别信息。
- 金额、账户标识、订单编号等关键可核验信息，不因视觉整齐而被不可逆截断；必要时提供展开、复制或详情。

### 3.5 标题到底要不要？

**【系统】Apple 的导航规范允许根据内容决定标题表现形式。** 标题的作用是帮助识别位置，不要求每个屏幕都重复显示大标题。[A09]

| 场景 | 建议标题 | 原因 |
| --- | --- | --- |
| 独立一级 Tab 页面 | 系统 Large Title 或明确 Inline Title | 快速识别一级区域 |
| 一级内容列表 | 常用 Large Title，可随滚动收起 | 适合列表入口 |
| 二级详情页 | Inline Title，使用对象名或简短类型名 | 节省空间并保持返回路径 |
| 编辑一条记录 | “编辑记录”或对象名 | 说明当前操作对象 |
| 临时筛选/创建 Sheet | “筛选”“新建项目”等短任务标题 | 减少用户迷失 |
| 图片/视频沉浸视图 | 可隐藏或在操作栏使用紧凑标题 | 让媒体成为主体 |
| 笔记正文/阅读页 | 内容有清楚文章标题时可省略重复导航标题 | 避免双重标题 |
| 登录/首次欢迎页 | 标题可以是任务文案而非导航标题 | 非常规层级流程 |

**【推荐】避免四种标题问题：** 同一短标题同时在导航栏和内容区重复；一级页永远只放 App 名称；每个分区都用过于醒目的 24pt 粗体；详情标题过长导致工具栏无法显示关键操作。

### 3.6 文本颜色与易读性

- 正文使用系统主要文本语义色；次级说明用 secondary label；更弱元信息可使用 tertiary label，但需验证实际对比。
- **【系统】常规小字对比应满足约 4.5:1；较大或加粗的文本在适用条件下可以采用 3:1。** 关键文本尽量使用系统语义色来随浅色/深色、高对比设置适配。[A03]
- 彩色底、照片、模糊层上的文字需要额外检查明暗关系；颜色不应成为唯一的错误/状态提示。
- 可点链接与普通正文应有可感知区别，必要时结合下划线、位置或明确的动作标签。
