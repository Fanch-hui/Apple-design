# 原生组件与内容状态

来源：《macOS 原生应用设计规范》2026 年 10 月深度研究版。沿用原章节号及〔Apple〕〔建议〕〔条件〕标记。文献标识对应[资料出处](sources.md)。

## 05 · 原生组件选择与详细规格

### 5.1 组件尺寸的总规则

**〔Apple〕** macOS 原生控件提供 Mini、Small、Regular/Large 等平台尺寸，自 macOS 26 起还增加了突出主任务的 Extra Large。新系统中小中尺寸控件高度已更新；布局应依据系统内在尺寸自适应。[A5]

**〔建议〕** 使用系统控件时不强制写死高度。仅在自绘控件或设计稿中采用下列参考区间：

| 自定义元素 | 建议外形尺寸 | 说明 |
|---|---|---|
| 紧凑辅助图标按钮 | 24–28pt 点击区 | 适于编辑器/Inspector，需准确反馈 |
| 常规图标按钮 | 28–32pt 点击区 | 工具栏附近常用区域 |
| 常规文本按钮 | 28–34pt 高 | 以系统控制大小为先 |
| 强调主操作 | 34–42pt 高 | 小工具欢迎页/关键提交等少量场景 |
| 搜索/文本输入框 | 28–34pt 高 | 系统默认高度优先 |
| 紧凑表格行 | 26–30pt 高 | 高密度数据，需要清晰选中状态 |
| 普通列表行 | 30–38pt 高 | 单行图标 + 文字 |
| 双行内容行 | 48–60pt 高 | 标题、补充信息、缩略图 |
| 正文图标 | 13–16pt 视觉尺寸 | 与当前字体字号协调 |
| 工具栏 SF Symbol | 14–18pt 视觉尺寸 | 依系统符号权重与控件样式调整 |

### 5.2 组件使用矩阵

| 功能需求 | 首选原生组件 | 放置位置 | 设计规则 |
|---|---|---|---|
| 新建对象 | Button、Toolbar Item、Menu Command | 工具栏 + File 菜单 | 动词+对象更明确 |
| 单项文字输入 | Text Field | 内容区 / Sheet / Inspector | 持续可见标签，提供明确焦点 |
| 多行编辑 | Text Editor / Text View | 主要内容区 | 可选择文本、复制、撤销与滚动 |
| 搜索内容 | Search Field | 工具栏尾端、侧边栏顶部 | 根据搜索范围选位置 |
| 二选一开关 | Checkbox / Switch | 内容区或设置窗格 | 一般设置优先 Checkbox |
| 多项互斥（少） | Radio Group / Segmented | 设置/局部工具 | 选项数少、意义清晰 |
| 多项互斥（多） | Pop-up Button / Picker | 表单/Inspector | 约 5 项以上优先收纳 |
| 小范围强相关切换 | Segmented Control | Toolbar / Inspector | 通常 2–5 项；宽界面上不超约 5–7 项 |
| 选择路径或文件 | Open/Save Panel | 系统文件对话框 | 使用标准文件系统行为 |
| 临时说明或操作 | Popover | 触发控件旁 | 只放少量相关内容 |
| 局部短任务 | Sheet | 父窗口内 | 阻断父窗口，不阻断其他 App 窗口 |
| 长编辑或复杂流程 | 新窗口 / Inspector / Panel | 独立窗口或常驻侧面 | 避免长流程都装进模态层 |
| 危险确认 | Alert | 当前窗口上方 | 标题具体，说明后果和选择 |
| 可排序数据 | Table | 主内容区 | 列标题、列宽、排序、选择与复制 |
| 层级数据 | Outline View / Sidebar | 主内容/侧边栏 | 使用展开箭头，避免伪装普通平铺列表 |
| 处理进度 | Progress Indicator | 受影响操作附近 | 优先确定型进度 |
| 当前对象属性 | Inspector / Form | 右侧 | 字段对齐、分组、自动更新 |
| 频繁就地命令 | Context Menu + 可见动作 | 内容项上 | 右键是辅助入口 |
| 常驻系统入口 | Menu Bar Extra / Dock Menu | 系统菜单栏、Dock | 不替代主工作区完整操作 |

### 5.3 按钮

**〔Apple〕** 按钮内容可用文本、符号或组合；表达含义最清楚的形式优先。macOS 对按钮提供悬停帮助。[A16]

**〔建议〕** 每个视觉区域最多一个最强强调按钮；多数工具栏按钮保持统一低强调风格。显著动作使用动词标签，例如「转换文件」「开始同步」「新建笔记」；对「确定」「提交」等缺乏对象信息的词，在结果不够明显时替换成更具体动作。

按钮应具备正常、Hover、Pressed、Selected（若适用）、Disabled、Focus 等视觉状态。禁用状态需要有条件说明或可发现的原因，不应把所有次要按钮都做成近乎透明。

### 5.4 Toggle、Checkbox、Radio

**〔Apple〕** macOS 中 Switch、Checkbox、Radio 都可用，但应放在窗口主体而非 Toolbar。Checkbox 更适合普通设置及层级选项；Switch 有更高视觉权重，适合重要设置或控制一组功能。多于约五项的互斥选择可考虑 Pop-up Button。[A17]

**〔建议〕** 选项不是全局行为时优先将控制放在其影响范围附近。每组只有一个需要突出的主状态，子选项可缩进。避免把多种层级的开关排成同样大小、同样颜色的长列。

### 5.5 Segmented Control、Tab 和 View 切换

**〔Apple〕** Segmented 适合紧密相关的选择或少量视图切换，可表示单选、多选或瞬时动作，但同一个控件不要混合这些模式。Apple 推荐宽界面不超过约 5–7 个分段；Mac 主内容区域的复杂视图切换通常优先 Tab View，Toolbar/Inspector 中才更常用 Segmented。[A18]

**〔建议〕** 「日/周/月」「列表/网格」「预览/编辑」适合短分段；「首页/项目/通知/账号/设置」这类不同业务领域应交给 Sidebar 或原生标签结构。

### 5.6 List / Table / Outline

**〔Apple〕** Mac 的数据表推荐支持点击列标题排序、拖拽列宽；宽表可考虑交替行底色；层级数据优先 Outline。导航列表应持续表示选中项。[A14]

**〔建议〕** 单行列表不需要每项都有卡片、圆角、图标背景。分隔线或交替淡底色通常足够；复杂列表可以在 Hover 时显示快捷操作，但核心操作在菜单栏、Toolbar 或右键菜单中仍须可用。

### 5.7 Popover、Sheet、Panel、Alert 的区别

| 类型 | 何时用 | 不适合 |
|---|---|---|
| Popover | 少量临时选项；锚定按钮；可自动关闭 | 多步骤表单、长期编辑、多个嵌套 Popover |
| Sheet | 与当前窗口相关的明确短任务；需取消/确认 | 需要长时间与父窗口并行比对的操作 |
| Panel / Inspector | 频繁修改参数并实时观察正文 | 仅一次性「确认」动作 |
| Alert | 严重问题、不可逆风险、必须决策 | 成功提示、普通帮助、每次保存通知 |
| 独立窗口 | 完整编辑工作流、多文档和复杂配置 | 仅用于两个选项的临时选择 |

**〔Apple〕** Mac 的 Sheet 只阻断其父窗口；其他应用窗口仍可操作。Popover 可考虑可拆卸成为 Panel。Sheet 不适合复杂长流程，Alert 应节制使用。[A19][A20][A21]

### 5.8 设置窗口与表单

**〔Apple〕** 全局设置入口应在 App 菜单，支持 **⌘,**；通常使用独立设置窗口和切换不同设置窗格的稳定导航。设置窗格应记住上次浏览位置，并同步更新窗口标题。SwiftUI 的 Form 在 Mac 上是对齐的表单栈，不是 iOS 的分组卡片列表。[A22][A23]

**〔建议〕** 短设置表单采用左标签—右控件结构，建议标签列 120–160pt、字段列 200–340pt，间距 12–16pt。需要较长文字、可变内容或窄窗口时，标签置于控件上方。全局偏好不应塞入主窗口工具栏；任务内切换和筛选就地提供。

### 5.9 空状态、加载和错误反馈

**〔建议〕** 空状态用「清晰说明 + 下一步行动」组合：如「还没有项目」+「新建项目」，且不重复展示五种无关建议。加载时保留窗口布局结构，避免出现明显的整页跳动；持续任务采用真实进度、数量或阶段名称。[A24]

**〔Apple〕** 已知进度优先使用 Determinate Indicator；未知进度用活动指示器。有状态变化时提供持续可理解的信息；不可逆操作才使用显著确认。[A24][A21]
