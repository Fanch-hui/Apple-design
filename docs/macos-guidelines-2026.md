# macOS 原生应用设计规范

> **2026 年 10 月 · macOS 27 为主，兼顾 macOS 26**  
> **适用范围：** 常规 Mac 原生桌面应用，包括效率工具、文件管理、内容阅读、数据管理、创作编辑、设置窗口及菜单栏轻应用。  
> **文档性质：** 视觉与交互设计规范。以 Apple Human Interface Guidelines（HIG）和 WWDC 资料为依据，补充专业 UX 研究和一套可统一采用的设计数值。

**规则标记**

- **〔Apple〕**：Apple 明确提供的系统样式、数值、交互约定或设计原则。
- **〔建议〕**：便于建立一致设计语言的推荐默认值，并非 Apple 强制规范。
- **〔条件〕**：按应用类型、信息密度、窗口尺寸或系统设置变化的规则。

**设计目标：** 清晰、克制、高密度但不拥挤；功能可发现、命令可预期、窗口可自由调整；所有平台特有组件尽量遵循 macOS 的系统行为。优秀的 Mac 应用不需要把 iPhone 页面拉宽，也不需要把网页装进桌面窗口。[A1][A2]

## 01 · 原生设计语言与界面层级

### 1.1 Mac 的设计重心

**〔Apple〕** Mac 常在多应用、多窗口、多显示器环境中使用。用户依靠键盘、鼠标、触控板进行精确操作，可能持续处理复杂任务数小时。因此 Mac 应用应优先满足：信息直接可见、多区域并行、可自由调整窗口、可通过菜单访问命令、可通过快捷键加速操作，以及重新打开后恢复原来的工作状态。[A1][A6]

**〔建议〕** 将典型界面分为四层：

| 层级 | 内容 | 设计方式 |
|---|---|---|
| L1 窗口与导航框架 | 原生窗口、标题栏、Toolbar、Sidebar、Inspector | 优先系统组件，承担稳定的整体结构 |
| L2 主要内容 | 列表、表格、文本、图片、画布、编辑器 | 优先可读性、信息密度、稳定滚动 |
| L3 就地操作 | 行内按钮、选中工具、弹出选择器、右键菜单 | 紧邻对象，随上下文出现 |
| L4 临时反馈 | Popover、Sheet、Alert、进度、提示 | 只在需要时介入，离开后保留上下文 |

**〔建议〕** 默认以「空间位置 → 字体层级 → 对齐 → 颜色或分割线」表达关系。只有独立模块具有明确容器语义时才使用边框和背景面板。避免把所有内容包装成悬浮卡片，尤其不要在侧边栏、工具栏、正文、弹窗四处重复施加玻璃效果。

### 1.2 导航、内容和控件的视觉分离

**〔Apple〕** Liquid Glass 是位于内容之上的功能层，适合导航、工具栏和主要交互控件；标准材质属于内容层，用来建立内部结构。长期存在的正文容器应优先保持稳定、可读，滚动边缘效果负责区分内容与浮动控件。[A7][A8]

**〔建议〕** 常规效率工具采用低饱和背景：系统侧边栏材质 + 清晰的内容背景 + 少量系统强调色。可视焦点主要由选中状态、标题、主内容与主要动作决定，而非由连续的阴影、描边、渐变决定。

### 1.3 原生与网页的思维差异

**〔建议〕** Mac 应用让「对象及操作」常驻在同一工作空间中；网页通常更依赖页面导航和纵向浏览。Mac 在宽窗口中优先展开展示列表与详情，在窄窗口中按重要性折叠次要区域；不要直接使用网页常见的顶部站点导航、巨型 Hero 标题、满屏 CTA、固定底部导航栏。

## 02 · 窗口、导航结构与页面层级

### 2.1 窗口应扮演什么角色

**〔Apple〕** macOS 的窗口有窗口框架（包含关闭、最小化、缩放及可能的工具栏）和内容区。用户能够拖动、调整大小、最小化、全屏、跨显示器移动，并在多个窗口间切换。窗口的主窗口和接收键盘输入的 Key 窗口可能不是同一个。[A9]

| 窗口类型 | 适用任务 | 设计建议 |
|---|---|---|
| 主窗口 | 应用的长期工作区 | 支持调整尺寸、全屏、侧边栏折叠、状态恢复 |
| 文档窗口 | 独立文件、项目、编辑对象 | 标题体现对象名称，支持多文档窗口及文件操作 |
| 设置窗口 | 全局偏好与账号 | 从 App 菜单或 ⌘, 打开；单独窗口/原生设置场景 |
| 检查器（Inspector） | 当前选中对象的属性 | 放在同一窗口的右侧；可隐藏、可调整宽度 |
| 浮动面板（Panel） | 需要持续参照的参数/工具 | 可与主窗口并行操作，弱于主窗口的视觉强调 |
| 菜单栏轻应用 | 快速状态、一次性动作 | 菜单栏入口 + 紧凑菜单/Popover，复杂工作可进入独立窗口 |
| Sheet | 当前窗口相关的短任务 | 只阻断父窗口；不承载长期编辑任务 |
| Popover | 临时设置或局部信息 | 尽量锚定触发控件，任务短、内容少 |

**〔建议〕** 为不同应用选择合适的初始窗口尺寸；以下仅是设计起点，按实际信息需求改变：

| 应用类型 | 初始窗口（宽×高，pt） | 建议最小有效宽度 |
|---|---:|---:|
| 单一功能工具 | 760×560 | 520–640pt |
| 侧边栏 + 详情 | 1000×680 | 660–760pt |
| 三栏内容管理 | 1180×740 | 约 820pt，变窄时先隐藏第三栏 |
| 创作/画布/编辑器 | 1200×800 | 依工具和内容约束决定 |
| 设置窗口 | 随所选设置窗格内容 | 不把所有设置强行塞进同一固定尺寸 |

**〔条件〕** 初始尺寸是布局建议，用户调整后的尺寸和位置更重要；支持状态恢复，避免每次重开都重置宽度、选中项或滚动位置。[A6]

### 2.2 标题栏与交通灯按钮

**〔Apple〕** 保留系统关闭、最小化和缩放控制，不在其覆盖区域布置自定义按钮。窗口标题可与工具栏合并，macOS 27 为标题栏、窗口圆角与侧边栏做了统一更新。[A9][A4]

**〔建议〕** 窗口标题的三种处理：

- **文档/项目类**：优先显示具体文件或项目名称，例如「周报.md」「项目 A」，必要时配合状态和文档菜单。
- **导航/管理类**：显示当前栏目或选中对象，侧边栏和正文已经说明位置时，标题可保持简洁。
- **沉浸创作类**：允许弱化标题，只保留系统窗口管理能力；避免自己绘制一条仿网页导航顶栏。

避免在标题栏下方再增加一行同名大标题。需要内容级标题时，应表达更具体的主体，例如「最近修改」「本周概览」。

### 2.3 推荐导航结构

| 内容结构 | 推荐布局 | 典型应用 |
|---|---|---|
| 功能少、单对象 | 单栏内容 + 系统 Toolbar | 转换器、计时器、简易工具 |
| 多个一级功能 | Sidebar + Content | 任务、笔记、资料库 |
| 集合→列表→详情 | Sidebar + List + Detail | 邮箱、文件、知识库 |
| 对象→属性 | Sidebar/Canvas + Inspector | 绘图、设计、媒体编辑 |
| 文档多标签 | 原生 Tab / Tab View | 浏览、代码和多文档工作流 |
| 只需临时状态 | Menu Bar Extra + Popover | 网速、同步、设备、快捷操作 |

**〔Apple〕** 侧边栏通常最多显示两层层级；更深时使用额外的内容列表列。侧边栏可以隐藏、重新排序和定制；在窗口缩小时可以自动收起。系统侧边栏的行高和图标尺寸由用户的侧边栏大小偏好控制。[A10][A11]

### 2.4 侧边栏（Sidebar）

**〔建议〕** 常规宽度 220–280pt；紧凑场景 180–220pt；复杂树结构可扩展至 300pt 以上。使用侧边栏标题、分组和树形展开按钮，导航默认显示「图标 + 文本」并突出当前选中项。应提供拖动调整与隐藏能力。

**〔Apple〕** 在 macOS 27，侧边栏延伸到窗口边缘，选中项文字采用半粗体强化；图标颜色恢复系统强调色的表达。图标颜色应遵循用户在系统中选择的 Accent Color，不要写死一个品牌蓝。[A4][A10]

**〔建议〕** 分组间距比同组行距大；分组标题可用 10–11pt 语义样式。顶部保留核心导航，较少使用的项目可折叠。不要把重要功能仅放在侧边栏最底部：窗口底部可能被移到屏幕之外。[A12]

### 2.5 工具栏（Toolbar）

**〔Apple〕** 工具栏属于窗口框架，可与标题栏整合。通常将返回、侧边栏开关与标题放在前导侧；主要工具位于中段；搜索和常用动作位于尾随侧。工具栏项目应能在 App 菜单栏中找到对应命令，防止用户隐藏或自定义工具栏后失去入口。[A13]

**〔建议〕** 工具栏最多形成约三个清晰的逻辑组；单一组中常见 1–4 个动作，总量以窗口缩小时不拥挤为界。减少「新建、导入、导出、同步、编辑、设置、更多、分享」等同时裸露。优先按任务放置：新建和编辑是常用动作；导出和偏好设置适合菜单入口。

**〔条件〕** macOS 26/27 系统会随窗口宽度折叠可自定义项目到溢出菜单。不要通过缩小系统按钮命中区域来硬塞更多图标。

### 2.6 窗口缩放与跨屏

**〔建议〕** 采用三级响应策略：

| 可用内容宽度 | 层级处理 | 适合方式 |
|---|---|---|
| ≥1100pt | 允许三栏同时呈现 | Sidebar + List + Detail/Inspector |
| 760–1099pt | 优先保留两栏，检查器收起或浮出 | Sidebar + Content |
| ＜760pt | 侧边栏可折叠、内容单列优先 | Content + 可恢复导航入口 |

这些值是布局断点**建议**，实际断点应由栏位最低可用宽度推导，而非直接复制网页的媒体查询断点。保持主内容稳定；缩小时先隐藏低优先级检查器，再压缩主要内容。处理多个显示器、Retina 缩放及窗口安全区域时，让尺寸随容器变化。

## 03 · 字体、字重、标题与文字说明

### 3.1 Apple 官方 macOS 字体等级

**〔Apple〕** 采用系统 San Francisco / 平台系统字体，并使用系统文本样式。中文由系统字体回退选择合适字形；避免整套 UI 强行使用网页品牌字体。Apple macOS 内建文字样式如下。[A3]

| 语义样式 | 字号 | 行高度 | 常规字重 | 强调字重 | 推荐用途 |
|---|---:|---:|---|---|---|
| Large Title | 26pt | 32pt | Regular | Bold | 欢迎页/独立内容页大标题 |
| Title 1 | 22pt | 26pt | Regular | Bold | 工作区主要内容标题 |
| Title 2 | 17pt | 22pt | Regular | Bold | 明显的次级内容标题 |
| Title 3 | 15pt | 20pt | Regular | Semibold | Section 标题 |
| Headline | 13pt | 16pt | Bold | Heavy | 列表或局部强调标题 |
| Body | 13pt | 16pt | Regular | Semibold | 通常正文、控件标签 |
| Callout | 12pt | 15pt | Regular | Semibold | 补充说明 |
| Subheadline | 11pt | 14pt | Regular | Semibold | 次级信息 |
| Footnote | 10pt | 13pt | Regular | Semibold | 辅助细节，谨慎使用 |
| Caption 1 | 10pt | 13pt | Regular | Medium | 简短元数据 |
| Caption 2 | 10pt | 13pt | Medium | Semibold | 次要标签 |

**〔Apple〕** macOS 推荐默认文字 13pt，推荐最小 10pt。这是平台基准，并不代表所有正文都适合 10pt。[A3]

### 3.2 统一字重规则

| 字重 | 建议场景 | 避免 |
|---|---|---|
| Regular (400) | 主体文本、描述、表格值 | 整个页面全部加粗 |
| Medium (500) | 简短的弱强调、小分组标题 | 用它替代高对比度文本颜色 |
| Semibold (600) | 当前选中项、区块标题、主要数值 | 所有列表行标题都默认加粗 |
| Bold (700) | 重要页面标题和关键动作 | 长段正文大面积 Bold |
| Heavy (800) | 极少数数字/品牌强调 | 系统常规工作区或检视器标签 |

**〔建议〕** 同一屏幕一般以 Regular + Semibold 为主。通过字号差、位置和语义色表达层级；如果 13pt Semibold 足够，就不要升级到 20pt Bold。

### 3.3 标题需要出现在哪里

| 场景 | 标题规则 | 推荐排版 |
|---|---|---|
| 常规主窗口 | 可以只有工具栏标题 | 避免内容区再重复 App 名称 |
| 一级栏目首页 | 可有 17–22pt 内容标题 | 与正文左边缘对齐 |
| 文件/内容详情 | 工具栏显示对象标题 | 内文可有 15–17pt 分区标题 |
| 设置窗口 | 顶部显示当前设置窗格名 | 表单项目由标签承担辨识 |
| 表格页面 | 表头优先于大标题 | 筛选和排序应比页面标题更易接近 |
| Sheet/Alert | 必须能明确识别当前任务或问题 | 标题简短具体 |
| 菜单栏 Popover | 可省略重复标题 | 状态值、首要控制占主要视觉权重 |

**〔建议〕** 一个视窗只保留一个主要视觉标题。若 Sidebar 选中“下载”、Toolbar 标题也是“下载”，内容区不必再放「下载」34pt 大字；可直接显示文件列表及必要的统计。

### 3.4 行长、行高和截断

- **〔建议〕** 长篇阅读文本采用 620–820pt 的阅读列最大宽度；复杂表格、时间线、编辑画布不受此限制。英文连续阅读宜控制在约 50–80 字符/行，中文以合适的单行字数和读距判断，不机械照搬英文字符数。[T5]
- **〔建议〕** 系统正文使用对应的行高度；自定义长文章可设约 1.35–1.55 倍字号，以阅读用途为准。控件标签优先依内建文本样式。
- **〔建议〕** 表格文件名、路径和长 ID 优先保留可识别部分：路径可中间省略，正文描述可末尾省略；需要完整查看时提供选择复制、Inspector 或上下文展示。[A14]
- **〔Apple〕** 支持系统文字缩放、增加对比度等辅助功能；不要用固定高度强行裁掉字号放大的内容。[A15]

### 3.5 说明文字的密度

**〔建议〕** 正文 13pt，辅助信息 11–12pt。静态标签通常比额外说明更有效：字段名已经解释用途时不重复一段话。出现权限、计费、覆盖、删除、同步范围等高风险或易误解行为时，应在控件旁持续显示必要说明，不只隐藏在 Tooltip 中。[T1]

## 04 · 间距、留白、对齐、尺寸与栅格

### 4.1 推荐间距尺度

**〔建议〕** 使用 4pt 主节奏，允许 2pt 微调。推荐基础 token：

| 间距 | 用途 |
|---:|---|
| 2pt | 图标与数字、紧凑元信息微调 |
| 4pt | 图标与短文本、紧密相关标签 |
| 6pt | 小型控件与文字的内部关系 |
| 8pt | 同组输入项、两项并列控件之间 |
| 12pt | 相关行/字段之间、轻量内容模块 |
| 16pt | 常规内容的左右内边距、紧凑分区 |
| 20pt | 主要内容区水平内边距 |
| 24pt | 页面块之间、设置分组之间 |
| 32pt | 大分区及明显语义切换 |
| 40–48pt | 欢迎界面、空状态等低密度场景 |

**〔建议〕** 「组内小、组间大」，例如字段到其说明为 4pt，字段到下一个字段为 12pt，组与组之间为 24pt。不要为了营造“高级感”把所有元素一律拉到 32pt。

### 4.2 各区域内边距

| 区域 | 建议默认 | 说明 |
|---|---:|---|
| 主内容页边距 | 20–24pt | 适合一般文字和控制台类首页 |
| 简洁工具窗口 | 16–20pt | 小窗口兼顾内容密度 |
| 紧凑数据表格 | 水平 8–12pt/单元格 | 行高与可扫描性共同决定 |
| 列表行文本 | 8–14pt | 由系统列表样式优先决定 |
| Inspector 面板 | 12–16pt | 高密度属性面板 |
| 设置窗格 | 20–28pt | 标签与控件列应对齐 |
| Popover | 12–16pt | 根据控件个数调整 |
| 空状态 | 32–48pt | 居中但不过分空旷 |

表格和侧边栏中的系统组件应采用其自身内边距；这里给出的值主要服务于自定义区域。

### 4.3 对齐方式

**〔Apple〕** 统一对齐帮助建立信息层级；遵循阅读方向、布局边距和安全区域，支持从右向左的本地化。[A12]

**〔建议〕**

- 正文、列表标题、侧边栏导航、分区标题都按统一的前导边缘对齐；中文、英文均优先使用阅读方向起点。
- 表格中的金额、百分比、耗时、可比较数值右对齐，文本与状态通常左对齐；列标题与数据对齐规则保持一致。
- 表单在宽窗口可采用**标签在左、控件在右**的双列网格；字段标签右对齐至统一边界，输入控件从同一列开始。窄窗口或标签较长时切换成标签置上。
- 图标与文本做光学对齐，而不是只以方形边框几何中心计算；相邻标签的文字基线优先于控件外框顶边。
- 使用分隔线时，优先划分真正不同的内容区域；不要为每一行都加明显边框。

### 4.4 列宽、数据密度与滚动

**〔建议〕** 分栏场景优先使用可拖拽分割线。内容列不应因侧边栏加宽而失去主要文本宽度；Inspector 可隐藏。多列数据表支持列宽调整、排序、选择与复制；横向内容超出时允许横向滚动，不将每一行转成移动端信息卡。[A14]

**〔Apple〕** 尊重系统滚动行为、弹性滚动和用户对滚动条显示的偏好；避免同方向滚动容器无意义嵌套。[A8]

### 4.5 内容与系统边缘

**〔Apple〕** 不要将关键功能或信息集中在窗口底部，因为用户可能把窗口下缘移出屏幕；还应尊重有摄像头开口的 Mac 顶部显示安全区域。[A12]

**〔建议〕** 需要长期可见的动作放在标题栏/Toolbar、内容顶部或对象附近；窗口底边适合状态信息、行数、缩放比例和可替代的轻量控制。

## 05 · 原生组件选择与详细规格

### 5.1 组件尺寸的总规则

**〔Apple〕** macOS 原生控件提供 Mini、Small、Regular/Large 等平台尺寸，自 macOS 26 起还增加了突出主任务的 Extra Large。新系统中小中尺寸控件高度已更新；布局应依据系统内在尺寸自适应。[A5]

**〔建议〕** 使用系统控件时不强制写死高度。仅在自绘控件或设计稿中采用下列参考区间：

| 自定义元素 | 建议外形尺寸 | 说明 |
|---|---|---|
| 紧凑辅助图标按钮 | 24–28pt 点击区 | 适于编辑器/Inspector，需准确反馈 |
| 常规图标按钮 | 28–32pt 点击区 | 工具栏附近常用区域 |
| 常规文本按钮 | 28–34pt 高 | 以系统控制大小为先 |
| 强调主操作 | 34–42pt 高 | 小工具欢迎页/关键提交等少量场景 |
| 搜索/文本输入框 | 28–34pt 高 | 系统默认高度优先 |
| 紧凑表格行 | 26–30pt 高 | 高密度数据，需要清晰选中状态 |
| 普通列表行 | 30–38pt 高 | 单行图标 + 文字 |
| 双行内容行 | 48–60pt 高 | 标题、补充信息、缩略图 |
| 正文图标 | 13–16pt 视觉尺寸 | 与当前字体字号协调 |
| 工具栏 SF Symbol | 14–18pt 视觉尺寸 | 依系统符号权重与控件样式调整 |

### 5.2 组件使用矩阵

| 功能需求 | 首选原生组件 | 放置位置 | 设计规则 |
|---|---|---|---|
| 新建对象 | Button、Toolbar Item、Menu Command | 工具栏 + File 菜单 | 动词+对象更明确 |
| 单项文字输入 | Text Field | 内容区 / Sheet / Inspector | 持续可见标签，提供明确焦点 |
| 多行编辑 | Text Editor / Text View | 主要内容区 | 可选择文本、复制、撤销与滚动 |
| 搜索内容 | Search Field | 工具栏尾端、侧边栏顶部 | 根据搜索范围选位置 |
| 二选一开关 | Checkbox / Switch | 内容区或设置窗格 | 一般设置优先 Checkbox |
| 多项互斥（少） | Radio Group / Segmented | 设置/局部工具 | 选项数少、意义清晰 |
| 多项互斥（多） | Pop-up Button / Picker | 表单/Inspector | 约 5 项以上优先收纳 |
| 小范围强相关切换 | Segmented Control | Toolbar / Inspector | 通常 2–5 项；宽界面上不超约 5–7 项 |
| 选择路径或文件 | Open/Save Panel | 系统文件对话框 | 使用标准文件系统行为 |
| 临时说明或操作 | Popover | 触发控件旁 | 只放少量相关内容 |
| 局部短任务 | Sheet | 父窗口内 | 阻断父窗口，不阻断其他 App 窗口 |
| 长编辑或复杂流程 | 新窗口 / Inspector / Panel | 独立窗口或常驻侧面 | 避免长流程都装进模态层 |
| 危险确认 | Alert | 当前窗口上方 | 标题具体，说明后果和选择 |
| 可排序数据 | Table | 主内容区 | 列标题、列宽、排序、选择与复制 |
| 层级数据 | Outline View / Sidebar | 主内容/侧边栏 | 使用展开箭头，避免伪装普通平铺列表 |
| 处理进度 | Progress Indicator | 受影响操作附近 | 优先确定型进度 |
| 当前对象属性 | Inspector / Form | 右侧 | 字段对齐、分组、自动更新 |
| 频繁就地命令 | Context Menu + 可见动作 | 内容项上 | 右键是辅助入口 |
| 常驻系统入口 | Menu Bar Extra / Dock Menu | 系统菜单栏、Dock | 不替代主工作区完整操作 |

### 5.3 按钮

**〔Apple〕** 按钮内容可用文本、符号或组合；表达含义最清楚的形式优先。macOS 对按钮提供悬停帮助。[A16]

**〔建议〕** 每个视觉区域最多一个最强强调按钮；多数工具栏按钮保持统一低强调风格。显著动作使用动词标签，例如「转换文件」「开始同步」「新建笔记」；对「确定」「提交」等缺乏对象信息的词，在结果不够明显时替换成更具体动作。

按钮应具备正常、Hover、Pressed、Selected（若适用）、Disabled、Focus 等视觉状态。禁用状态需要有条件说明或可发现的原因，不应把所有次要按钮都做成近乎透明。

### 5.4 Toggle、Checkbox、Radio

**〔Apple〕** macOS 中 Switch、Checkbox、Radio 都可用，但应放在窗口主体而非 Toolbar。Checkbox 更适合普通设置及层级选项；Switch 有更高视觉权重，适合重要设置或控制一组功能。多于约五项的互斥选择可考虑 Pop-up Button。[A17]

**〔建议〕** 选项不是全局行为时优先将控制放在其影响范围附近。每组只有一个需要突出的主状态，子选项可缩进。避免把多种层级的开关排成同样大小、同样颜色的长列。

### 5.5 Segmented Control、Tab 和 View 切换

**〔Apple〕** Segmented 适合紧密相关的选择或少量视图切换，可表示单选、多选或瞬时动作，但同一个控件不要混合这些模式。Apple 推荐宽界面不超过约 5–7 个分段；Mac 主内容区域的复杂视图切换通常优先 Tab View，Toolbar/Inspector 中才更常用 Segmented。[A18]

**〔建议〕** 「日/周/月」「列表/网格」「预览/编辑」适合短分段；「首页/项目/通知/账号/设置」这类不同业务领域应交给 Sidebar 或原生标签结构。

### 5.6 List / Table / Outline

**〔Apple〕** Mac 的数据表推荐支持点击列标题排序、拖拽列宽；宽表可考虑交替行底色；层级数据优先 Outline。导航列表应持续表示选中项。[A14]

**〔建议〕** 单行列表不需要每项都有卡片、圆角、图标背景。分隔线或交替淡底色通常足够；复杂列表可以在 Hover 时显示快捷操作，但核心操作在菜单栏、Toolbar 或右键菜单中仍须可用。

### 5.7 Popover、Sheet、Panel、Alert 的区别

| 类型 | 何时用 | 不适合 |
|---|---|---|
| Popover | 少量临时选项；锚定按钮；可自动关闭 | 多步骤表单、长期编辑、多个嵌套 Popover |
| Sheet | 与当前窗口相关的明确短任务；需取消/确认 | 需要长时间与父窗口并行比对的操作 |
| Panel / Inspector | 频繁修改参数并实时观察正文 | 仅一次性「确认」动作 |
| Alert | 严重问题、不可逆风险、必须决策 | 成功提示、普通帮助、每次保存通知 |
| 独立窗口 | 完整编辑工作流、多文档和复杂配置 | 仅用于两个选项的临时选择 |

**〔Apple〕** Mac 的 Sheet 只阻断其父窗口；其他应用窗口仍可操作。Popover 可考虑可拆卸成为 Panel。Sheet 不适合复杂长流程，Alert 应节制使用。[A19][A20][A21]

### 5.8 设置窗口与表单

**〔Apple〕** 全局设置入口应在 App 菜单，支持 **⌘,**；通常使用独立设置窗口和切换不同设置窗格的稳定导航。设置窗格应记住上次浏览位置，并同步更新窗口标题。SwiftUI 的 Form 在 Mac 上是对齐的表单栈，不是 iOS 的分组卡片列表。[A22][A23]

**〔建议〕** 短设置表单采用左标签—右控件结构，建议标签列 120–160pt、字段列 200–340pt，间距 12–16pt。需要较长文字、可变内容或窄窗口时，标签置于控件上方。全局偏好不应塞入主窗口工具栏；任务内切换和筛选就地提供。

### 5.9 空状态、加载和错误反馈

**〔建议〕** 空状态用「清晰说明 + 下一步行动」组合：如「还没有项目」+「新建项目」，且不重复展示五种无关建议。加载时保留窗口布局结构，避免出现明显的整页跳动；持续任务采用真实进度、数量或阶段名称。[A24]

**〔Apple〕** 已知进度优先使用 Determinate Indicator；未知进度用活动指示器。有状态变化时提供持续可理解的信息；不可逆操作才使用显著确认。[A24][A21]

## 06 · 功能入口分布、菜单栏、搜索和快捷键

### 6.1 功能入口分配矩阵

| 功能 | 第一入口 | 第二入口 | 不建议的默认方式 |
|---|---|---|---|
| 一级页面切换 | Sidebar / 原生 Tab | View 菜单、快捷键 | 网页式底部导航条 |
| 返回 / 前进 | Toolbar / 系统导航 | 快捷键、触控板手势 | 仅依赖左上角自定义箭头 |
| 新建 | Toolbar 主操作 | File 菜单、⌘N | 藏进设置页 |
| 打开文件 | File 菜单 / 主内容入口 | 拖放到窗口/Dock | 仅网页上传按钮 |
| 搜索全集 | Toolbar 尾随侧 | 菜单快捷键 | 页尾的小图标 |
| 筛选当前列表 | 列表标题旁 / Toolbar | 右键菜单（按需） | 全局设置窗格 |
| 排序 | Table 列标题 / View 菜单 | 局部更多菜单 | 另起设置页面 |
| 编辑选中对象 | Inspector / 就地编辑 | Edit 菜单、快捷键 | 每次都开全屏弹层 |
| 删除 | 内容命令 / Edit、File 菜单 | 右键、Delete 键 | 高频工具栏唯一大红按钮 |
| 导入/导出 | File 菜单 | 常用时放 Toolbar | 每个页面都放多个大按钮 |
| 偏好设置 | App 菜单（⌘,） | 独立 Settings Window | 固定占据主工具栏 |
| 帮助 | Help 菜单 | 上下文说明/帮助按钮 | 不可关闭的新手引导 |
| 当前任务详情 | Inspector / Panel | Popover | 新增一级页面 |
| 系统常驻状态 | Menu Bar Extra | 主窗口/Dock | 抢占侧边栏重要位置 |

**〔Apple〕** Mac 菜单栏应覆盖应用命令；工具栏可被隐藏或定制，因此不能成为命令的唯一位置。Context Menu 也只是快捷入口，相关命令要能在主界面或菜单栏找到。[A13][A25]

### 6.2 系统菜单栏

**〔Apple〕** 应遵循系统熟悉的菜单结构及快捷键，典型为 App、File、Edit、View、Window、Help，以及产品特有的必要菜单。最常用命令靠前，相近命令成组；不可用命令在主菜单里保留但置灰。需要补充输入后才能完成的命令，可使用省略号「…」。2026 年 HIG 明确建议**谨慎使用菜单项图标**：仅为重要且语义清晰的操作配置，并保持同组风格一致。[A25][A26]

**〔建议〕** 避免把每条菜单命令都配图标；常见剪切、复制、粘贴更需要标准位置、文案和快捷键，而不是彩色装饰。菜单标题词组应动词先行、清楚表达操作对象。

### 6.3 常用 Mac 快捷键

| 快捷键 | 预期行为 | 说明 |
|---|---|---|
| ⌘N | 新建窗口 / 文档 / 对象 | 按应用的主要对象定义 |
| ⌘O | 打开 | 文档类常用 |
| ⌘S | 保存 | 支持文档保存时应生效 |
| ⌘W | 关闭当前窗口 | 不等同于退出整个 App |
| ⌘Q | 退出应用 | 系统惯例 |
| ⌘, | 打开设置 | Mac 全局偏好入口 |
| ⌘F | 查找 | 搜索当前文档或上下文 |
| ⌘Z / ⇧⌘Z | 撤销 / 重做 | 编辑类必须保持预期 |
| ⌘C / ⌘V / ⌘X | 复制 / 粘贴 / 剪切 | 文本及可编辑对象 |
| ⌘A | 全选 | 当前焦点范围 |
| ⌘P | 打印 | 有可打印内容时支持 |
| Tab / ⇧Tab | 焦点前进 / 后退 | 支持完整键盘导航 |
| Esc | 退出当前临时状态 | 关闭 Popover / 退出编辑等按语境决定 |

**〔Apple〕** 自定义快捷键优先用 Command；Shift 用于相关变体，Option 留给较少使用的专业操作，避免滥用 Control。不要挪用已有标准快捷键去执行毫不相关的动作。[A27]

### 6.4 搜索入口定位

**〔Apple〕** Mac 搜索主要有三个自然位置：**工具栏尾随侧**（跨多个内容列搜索）、**侧边栏顶部**（筛选侧边栏内容或设置分类）、**独立搜索导航区**（搜索与探索本身是核心任务）。搜索框可提供实时结果、最近搜索、建议、Token 过滤和 Scope 筛选。[A28][A29]

**〔建议〕** 具体判定：

| 用户想找什么 | 搜索位置 | 结果呈现 |
|---|---|---|
| 整个应用的文档/项目 | Toolbar 尾随侧 | 主内容区、保留侧边栏上下文 |
| 当前集合中的内容 | 列表顶部 | 原列表内过滤 |
| 侧边栏里的设置项 | Sidebar 顶部 | 侧边栏过滤并定位到设置 |
| 主要产品体验是发现内容 | 独立搜索项 | 专门的搜索与推荐页 |
| 长文档中的特定文字 | 文档内查找条 | 选中和定位匹配结果 |

**〔建议〕** 工具栏搜索框可预留约 180–260pt，窗口压缩时折叠成搜索按钮。内容较复杂时提供范围标签，而不是让用户输入特殊命令才知道能搜索什么。

### 6.5 右键菜单与 Hover

**〔Apple〕** Context Menu 为当前对象提供少量常见动作，属于辅助入口。分组应精简，子菜单不宜过深；主菜单项中的不可用状态可置灰，而上下文菜单通常隐藏不相关动作。菜单中不需要重复展示快捷键，快捷键信息主要在顶部菜单中。[A30]

**〔建议〕** Hover 只用于预告和提高操作便利性，例如露出次级按钮、突出可拖拽区域、Tooltip。对象的主要可操作性不能依赖 Hover 才被发现。凡是鼠标 Hover 能看到的必要说明，键盘焦点也应能看到。[T1]

## 07 · SF Symbols、应用图标和文字标签

### 7.1 图标总原则

**〔Apple〕** 优先使用 SF Symbols 或系统提供的标准图标表达常见命令。图标的形状、重量与视觉尺寸应匹配其所在文字样式。macOS 27 的菜单项图标应节制使用。[A16][A26]

**〔建议〕** 在工具栏里优先选语义稳定、跨应用一致的符号：`plus`（新增）、`magnifyingglass`（搜索）、`sidebar.left`（侧边栏）、`square.and.arrow.up`（分享）、`trash`（删除）、`ellipsis`（更多）、`slider.horizontal.3`（筛选/调整，依语境）。同一功能全 App 使用同一种符号。

注意：同一个通用图标在不同应用中可能意味着完全不同的动作。例如「方框+箭头」可能是分享也可能是导出；如果行为不能由图标明确预测，应配上文字。

### 7.2 图标是否必须配文字

| 元素 | 推荐 | 原因 |
|---|---|---|
| Sidebar 导航项 | 图标 + 常显文字 | 辨识栏目最重要 |
| 高频标准 Toolbar 操作 | 允许单图标 + Tooltip | 空间珍贵且符号较熟悉 |
| 重要或陌生业务功能 | 明确文字标签 | 避免猜测 |
| 主要提交/创建按钮 | 动词文字，按需带图标 | 结果要可预期 |
| Context Menu | 文字必须可读，图标可选 | 菜单本身依赖可扫描文案 |
| 密集表格的行内操作 | 小符号可行，Hover+Tooltip | 仍需可发现的替代入口 |
| 风险操作 | 文字写清对象及后果 | 不只用红色垃圾桶传达危险 |
| 设置项 | 显示持续可见的完整标签 | 减少认知成本 |

**〔第三方研究〕** NNGroup 发现图标经常存在歧义，重要导航与任务入口应尽量提供常显文字；Tooltip 仅负责局部补充，不承载完成任务必需的信息。[T1][T2]

### 7.3 说明文字何时必须出现

**〔建议〕** 使用以下判断：

- 开关会影响其他数据、隐私或系统权限：在附近写清影响范围和条件。
- 会覆盖/清除/迁移/退出/购买：写清执行结果，必要时提示是否可撤销。
- 需要输入特殊格式：在输入前呈现格式要求；错误后在字段附近指出如何修正。
- 普通单义按钮，如「复制」「返回」「关闭」：无需在按钮下面重复解释。
- 陌生名词或专业参数：保留简短标签与可进一步查看的解释；可在 Inspector 显示语义说明。
- 复杂多选项设置：用 Section 标题说明范围，控件标签说明各自动作，避免逐项重复同一句解释。

### 7.4 Tooltip 与 Help

**〔Apple〕** Mac 按钮可悬停显示帮助；系统 Help 菜单与局部帮助内容应能解释复杂功能。[A16]

**〔第三方研究〕** Tooltip 应简短、贴近目标、不会遮挡操作，并支持鼠标 Hover 和键盘 Focus；与任务成败相关的规则应该留在界面里。[T1]

**〔建议〕** Tooltip 可写「显示检查器」「新建文件夹（⇧⌘N）」，不要写「点击这里可打开一个新窗口以便……」等长说明。

### 7.5 App Icon 与菜单栏状态图标

**〔Apple〕** 当前 Mac App Icon 推荐 1024×1024px 正方形分层素材，由系统统一蒙版成圆角，并支持不同明暗与着色外观。图形本身应简洁、轮廓清楚，尽量避免字体、截图、超细线条。[A31]

**〔建议〕** 菜单栏状态项以单色、识别度高、尺寸适宜的模板符号为主，避免彩色高细节 App Icon 直接塞入右上角。状态项只承担当前状态和高频快捷动作，冗长工作流进入主窗口。

## 08 · 颜色、圆角、Liquid Glass 与模糊效果

### 8.1 语义色，而非固定色块

**〔Apple〕** 使用系统动态颜色与系统强调色，适应 Light/Dark Mode、选中状态、失焦状态和系统外观设置。macOS 为文本、选中行、分隔线、控件及背景提供语义颜色，例如 `controlAccentColor`、`controlBackgroundColor` 等。[A32]

**〔建议〕** 让视觉重点集中于一个 Accent，辅助状态用语义颜色：成功、警告、错误分别表达状态，避免仅用颜色区分信息。通常单个内容页只有一个最强品牌强调，其他可交互元素优先维持系统样式。

### 8.2 四种常被混淆的模糊/材质

| 类型 | 核心视觉作用 | 正确场景 | 典型误用 |
|---|---|---|---|
| Liquid Glass | 控件/导航层的反射、折射、交互材质 | 系统 Toolbar、Sidebar 浮动控件 | 整页每个 Card 都是玻璃 |
| Standard Material | 稳定模糊、明度调整、Vibrancy | 面板、Popover、内容层分隔 | 仅因觉得某材质“更白”而选择 |
| Scroll Edge Effect | 滚动内容与上方控件之间的边界过渡 | 标题栏/工具栏覆盖滚动内容 | 页面无滚动也叠渐变模糊 |
| Gaussian Blur | 对图像/视频内容本身做模糊 | 背景媒体弱化、图像编辑、景深效果 | 用固定 blur 值仿制全部系统材质 |

**〔Apple〕** 标准材质应基于语义选择，不应按当前明暗外观去反推具体材质。`NSVisualEffectView` 支持与窗口后方或窗口内部内容混合；系统 Vibrancy 为材质上的文本和图标保持可读性。[A7]

### 8.3 Liquid Glass 的使用边界

**〔Apple〕** Liquid Glass 属于最上层的交互语言；内容层不要广泛铺设 Liquid Glass。普通正文和内容容器用标准材质，只有临时交互控件适合在交互时出现玻璃处理。[A33]

**〔建议〕** 单屏玻璃应主要集中于标题栏、Sidebar 上方的控制、必要的浮动按钮组。选中行属于选择状态，不需要再附加玻璃卡片浮层。复杂数据表与检查器应以对齐、分隔线和系统背景承载关系。

### 8.4 macOS 27 的具体改变

**〔Apple〕** macOS 27 更新了：统一的顶部 Toolbar 过渡、侧边栏延伸至窗口边缘、侧边栏图标颜色和半粗体选中态、更加统一的窗口圆角；还有仅适用于互动控件的轻微玻璃按压回弹。系统增加了对玻璃透明度个性化及显示边框辅助功能的支持。[A4][A34]

**〔第三方观察〕** macOS 27 的设计回归更明确的标题栏边界，改善了上一代部分透明区域的文字对比度。这意味着生产力应用不宜盲目追求彻底「无边界」的视觉效果。[T3]

### 8.5 Scroll Edge Effect：Automatic、Hard、Soft

**〔Apple〕** 首选系统 **Automatic**。Hard 产生更明确、偏不透明的过渡，适合 Mac 的文字标题、固定表头或密集控件；Soft 是连续的渐变模糊，适合少量浮动控件与有图像的背景。分栏各自可有独立 Scroll Edge Effect，但高度要协调；每个视图只应用一层，避免叠加。[A8][A4]

**〔建议〕** 对 macOS 27：窗口有文字标题、表头、工具栏时优先 Automatic（系统通常选择更强边界）；仅在确实需要展示底部图像连续性且控件对比充分时考虑 Soft。若没有滚动内容从控件下面通过，则省略滚动边缘效果。

### 8.6 高斯模糊与渐进模糊的区别

**〔建议〕** 高斯模糊是像素处理参数，主要控制视觉失焦；渐进模糊是空间过渡，视觉上随距离逐渐改变模糊强度/不透明度。二者都可能看起来“磨砂”，但用途不同。Mac 的窗口/侧边栏材质含 Vibrancy、背景取样和系统可访问性适配，不能等价于 CSS 或图像上直接加 `blur(20)`。

图片/视频背景若需高斯模糊，可先处理媒体，再确保前景文本对比；系统结构区域仍优先原生 Material 或 Scroll Edge Effect。

### 8.7 圆角、分隔线与阴影

**〔建议〕** 不要人工设置系统窗口外缘圆角；自定义内部控件可采用：4–6pt 用于紧凑状态标签，8–10pt 用于常规面板，12–16pt 用于独立媒体/内容面板。大面积视觉容器慎用夸张圆角，圆角应与父容器呈同心关系。

**〔Apple〕** macOS 27 AppKit 提供角部 Concentricity，使贴近容器角落的子元素圆角能与父容器协调。[A4]

**〔建议〕** 区域分隔优先轻微语义分割线；阴影仅用于真正浮起于内容之上的 Popover、Panel、拖动预览，不给每行数据添加厚阴影。

## 09 · 动画、鼠标键盘交互、反馈与无障碍

### 9.1 动画的用途与时长

**〔Apple〕** 系统动效优先；自定义动画应传达状态、位置关系和结果，且需响应 Reduce Motion。Mac 的触控板交互比触摸交互更克制，玻璃材质反馈也不应过度强调。[A35][A4]

**〔建议〕** 自定义动画时长参考：

| 动画类型 | 推荐区间 | 设计目的 |
|---|---:|---|
| Hover 颜色/边框响应 | 80–140ms | 迅速表明可以交互 |
| Button Press / 松开 | 80–160ms | 轻量回馈，不拖延任务 |
| 选择状态变化 | 120–200ms | 稳定强调当前对象 |
| Inspector 展开/收起 | 180–260ms | 帮助理解空间变化 |
| Popover 显示/关闭 | 优先系统动效 | 与触发控件有连续关系 |
| 自定义局部切换 | 160–260ms | 保持内容连续 |
| 大幅度转场/重排 | 220–320ms | 仅用于结构变化 |
| 加载/持续进度 | 系统组件决定 | 不把真实任务隐藏在长过渡后 |

这些时长均属设计建议，不是 Apple 对系统组件的硬编码要求。频繁操作的 Mac 工具不应为了“高级感”增加长距离大幅位移动画。

### 9.2 Hover、Pointer 和点击

**〔Apple〕** 鼠标/触控板具有高精度，支持单击、右键、滚动、拖动、系统手势；不要重定义 Mission Control 等系统级手势。自定义 Hover 反馈在密集行表中应以颜色为主，不应通过放大一整行压住邻项。[A36]

**〔建议〕** Hover 展现次级操作、控件可拖动性和点击热点。可点击对象的命中区域比图标可见轮廓更宽；Cursor 应反映对象类型和动作，但不要用所有元素统一手型鼠标光标来模拟网页。

### 9.3 选择、拖拽与右键

**〔Apple〕** 列表/表格需要清晰的持续选中状态。拖放时提供跟随光标的预览，展示可以接收的目标与插入位置；应兼容系统的复制/移动语义及 Option 等修饰键。能够接受文件的 Mac App 应优先支持从 Finder 拖入。[A14][A37]

**〔建议〕** 拖拽与点击需有明确区分：拖拽中的目标区域高亮，放置成功或失败都有结果反馈。支持按住 Command 多选、Shift 连续选区等桌面用户习惯（适用时）。

### 9.4 键盘焦点与可访问性

**〔Apple〕** 支持完整键盘访问；Tab / Shift-Tab 顺序与视觉顺序一致，按钮、列表、搜索、表单和弹窗可仅使用键盘操作。macOS 27 的 AppKit 专题强调现代输入、选择与状态恢复。[A27][A4]

**〔建议〕**

- 焦点环要明显，选中态和键盘焦点态不能混淆。
- 所有纯图标按钮提供可朗读的语义标签、操作提示和可预测的快捷键。
- 支持浅色/深色、减少透明度、增强对比度、显示边框及减少动态效果。
- 不仅通过颜色传达错误、成功或选中，辅以文字或形状。
- 字体放大后允许控件换行、窗口调整，不用固定高度截断说明。
- 把 Auto/Reduced Motion 和 Reduce Transparency 当成实际呈现状态设计，而不是仅在视觉定稿后再覆盖一个设置开关。[A15][A35]

### 9.5 反馈与系统持续性

**〔Apple〕** 持续运行和任务状态要能被理解，关闭与再次打开后应尽量回到先前窗口状态。非必要的模态弹层不应阻止应用平顺退出；高价值任务能恢复选择、工作区和窗口布局。[A4][A24]

**〔建议〕** 成功操作用局部状态或自然内容更新说明结果，不频繁弹出确认；失败时说明原因和可执行补救；后台长任务可在 Toolbar、列表行或菜单栏提供准确状态与进度。

## 10 · 常见应用页面模板、Mac 与 iOS/Web 对照及依据

### 10.1 通用效率工具主窗口

```text
┌──────────────────────── macOS 系统窗口 ─────────────────────────┐
│ ● ● ●   [侧栏]  当前工作区         [搜索]   [新建]  [更多]       │
├───────────────┬───────────────────────────────────────────────┤
│ 收藏           │  本周任务（17pt）                             │
│ 最近           │  筛选 / 排序                                  │
│ 项目 A         │  ─────────────────────────────────────────  │
│ 项目 B         │  [状态] 任务名称                截止时间      │
│               │  [状态] 任务名称                截止时间      │
│               │  [状态] 任务名称                截止时间      │
├───────────────┴───────────────────────────────────────────────┤
│ （可选）状态信息：项目数、同步情况、缩放比例                  │
└───────────────────────────────────────────────────────────────┘
```

**〔建议〕** Sidebar 240pt；主区边距 20pt；列表行 32–40pt；标题 17pt；正文 13pt；搜索在 Toolbar 右侧。侧栏可关闭，功能菜单通过顶部系统菜单栏访问。

### 10.2 文件 / 邮件 / 知识库三栏

```text
┌───────────────┬─────────────────────┬────────────────────────┐
│ 导航 Sidebar  │ 集合/条目列表       │ 详细内容 / 预览        │
│ 文件夹/标签   │ 标题 / 时间 / 状态  │ 对象标题 / 内容        │
│               │ 可排序 / 可多选     │ 可复制、编辑、导出     │
└───────────────┴─────────────────────┴────────────────────────┘
```

**〔建议〕** 左栏 220–260pt，中栏 300–380pt，详情占剩余宽度。缩小时先折叠不关键的栏；右栏始终保持合理正文宽度。行的选中态应持续显示，对象切换不强制覆盖整个视窗。

### 10.3 编辑器 / 创作型应用

```text
┌────────────────────── 系统 Toolbar ───────────────────────────┐
│ 导航 / 文档名             编辑工具 / 视图控制           分享   │
├──────────┬────────────────────────────────┬─────────────────┤
│ 资源/图层│         主要画布 / 编辑器        │ Inspector 属性  │
│ 文件树   │  对象选择、拖动、精确操作        │ 参数、格式、状态│
│          │                                │                 │
└──────────┴────────────────────────────────┴─────────────────┘
```

**〔建议〕** Toolbar 提供常用工具，右侧 Inspector 为可折叠的属性编辑区域；中央画布不强制最大宽度，支持缩放和明确的光标状态。减少滚动分区重复叠加玻璃效果，优先显示实际内容。

### 10.4 设置窗口

**〔建议〕** 顶部稳定设置分类导航，当前分区标题与内容对应。每项标签、控件列对齐，常规组间距 24pt；对有依赖关系的选项适度缩进。设置页不需要大量卡片和重新解释全局功能。首选 ⌘, 打开，不长期占用主 Toolbar。[A22][A23]

### 10.5 菜单栏轻应用

**〔建议〕** 菜单栏状态图标 → 单击 Popover → 第一眼展示核心状态值，之后展示 1–3 个常用动作，底部按需放「打开主窗口」和「设置」。首屏宽度可从 280–360pt 起，若需要长列表/复杂编辑，使用独立窗口，而不是不断扩大 Popover。

### 10.6 三种平台的明确差异

| 维度 | macOS 原生 App | iOS 原生 App | 桌面网页 |
|---|---|---|---|
| 主要输入 | 鼠标、触控板、实体键盘 | 手指为主 | 鼠标、键盘，兼顾触屏 |
| 常规正文 | 13pt | 17pt | 常见 14–16 CSS px，依网站而定 |
| 触控/点击基准 | 系统控件尺寸，精确指针 | 至少 44×44pt 触控区 | 按设备和无障碍目标选择 |
| 一级导航 | Sidebar / 原生 Tab / 菜单 | 底部 Tab / NavigationStack | 顶部站点导航 / 左侧导航 |
| 窗口管理 | 多窗口、可调尺寸、全屏 | 主要单屏体验 | 浏览器 Tab 和窗口 |
| 全局命令 | 系统菜单栏 + 快捷键 | 页面内操作为主 | 页面菜单 / 浏览器行为 |
| 信息密度 | 较高、分栏并行 | 较低、逐层进入 | 依产品设计系统 |
| 表格操作 | 排序、列宽、批量选择 | 通常列表化/分步操作 | HTML 表格、自定义脚本 |
| 设置入口 | App 菜单 ⌘,、Settings Window | App 内设置或系统设置 | 站点头像/设置菜单 |
| 文件管理 | Finder 拖放、文件面板、文档模型 | Files/分享/文档选择器 | 浏览器文件选择与下载 |
| 辅助动作 | 右键、Hover、Tooltip | 长按、上下文菜单 | Hover / Context Menu，因站点而异 |
| 模糊材质 | 原生 Window Material、Liquid Glass、Vibrancy | 系统 Material / Liquid Glass | CSS backdrop-filter 等模拟 |
| 过渡动画 | 快速精确，少大面积转场 | 更多手势与整屏转场 | CSS/JS 自定义 |
| 应用持续性 | 记住窗口和工作区状态 | 更常恢复页面与导航状态 | URL、会话、站点状态 |
| 全局图标 | Dock Icon + 菜单栏状态项 | Home Screen Icon | Favicon、PWA Icon |

**〔建议〕** Mac 更适合持续工作与精确编辑，宽屏优势应体现为**同时可见的对象与属性**。默认不采用网页巨型标题、网页式固定页脚和一屏一张大卡片，也不采用 iPhone 底部 Tab 直接平移到桌面的布局。
