# macOS 原生应用设计规范 · 视觉精修版

资料检索日期：2026年11月24日。完整视觉系统、组件规格与页面配方。

## 01 · 桌面视觉基调与统一参数

**适用范围。** 本规范面向macOS原生效率、文档、创作、数据与工具应用，覆盖可调整窗口、多栏布局、菜单命令、鼠标键盘、支持触摸的设备环境和辅助功能。资料检索截至2026年11月24日，采用当前 Apple Human Interface Guidelines 与 WWDC 2025/2026 的设计体系。系统窗口与标准控件跟随运行系统的实际外观，精确数值用于建立一致的自定义内容。

**三类数值的使用方式。** “Apple默认”描述平台字号、行为与语义；“本规范默认”定义产品自己的密度、间距、圆角与色彩；“示例”描述一个特定工作区的宽度演算。窗口交通灯、系统菜单、原生工具栏和原生控件遵循系统几何。内容面板、表格、对象行与自定义输入使用本规范的尺寸关系。

**默认风格：清晰、紧凑、重视持续工作。** 界面以中性背景、系统字体、稳定栏位和单一强调色组织信息。工具和参数保持合适密度，内容阅读与创作空间拥有更宽松的排版。列表、表格和检查器通过共享列线与状态表现建立秩序；图片、文档、画布或当前对象成为工作区的视觉主体。

| 设计角色 | 本规范默认 | 在工作区中的作用 |
|---|---|---|
| 主内容边距 | 20pt；阅读和完整表单24pt | 列表标题、筛选、表格共享内容轴 |
| 间距序列 | 4、8、12、16、20、24、32pt | 4/8用于控件关系，20/24用于分区 |
| 界面字体 | 系统Body，13/16pt Regular | 名称、菜单语义、属性值 |
| 分区标题 | 13pt Semibold；较大分区15/20pt | 小面板和中央区分别形成层级 |
| 内容标题 | 17/22pt或22/26pt | 标题反映对象和任务 |
| 阅读正文 | 默认16/24pt，可在15–17pt内调整 | 与密集工具区独立设置 |
| 辅助文字 | 11/14pt Regular | 时间、来源、快捷键信息 |
| 标准密度 | 表格32pt，双行摘要52pt | 密集数据28pt，舒适列表40pt |
| 自定义按钮 | 常规32pt，主动作36pt | 标签13pt Medium/Semibold |
| 常用交互目标 | 28×28pt起 | 小图标通过独立槽位提供命中面积 |
| 侧边栏 | 初始240pt，可调200–300pt | 导航与集合层级 |
| 检查器 | 初始288pt，可调260–360pt | 当前对象的属性与状态 |
| 符号尺寸 | 普通16pt，工具栏18–20pt | 与邻近文字重量和槽位协调 |
| 自定义圆角 | 面板12pt、输入/按钮8pt、缩略图6pt | 嵌套形状按实际内缩推导 |
| 强调色 | 一组语义强调色 | 选择、焦点、主操作拥有各自角色 |
| 层次表达 | 栏位、留白、语义分割线 | 悬浮面板再使用抬升与材质 |

以上按钮、行高与形状是自定义内容的初始方案。原生Small、Regular、Large等尺寸族采用系统行为；系统侧边栏跟随用户的显示偏好。自定义区域内部沿用同一种密度。

**工作区的四个视觉层级。** 顶层是当前内容或对象；第二层是控制该内容的工具与属性；第三层是去往其他内容的导航；第四层是进度、来源、同步等辅助信息。一个正在使用的检查器可以具有清楚标题，仍让主要对象获得更多视觉面积。系统菜单承担完整命令索引，工具栏承担最常用的现场操作。[MAC01]

**视觉重点以工作区域为单位。** 内容区的文档标题、画布和主要数据优先。窗口工具栏中的重要动作保持可见，局部面板使用低强调的常规按钮。选择是持续状态，键盘焦点是输入位置，Hover是指针位置；三者分别表达。整页的选中背景、焦点轮廓与按钮填色通过统一语义颜色协调。

**三种密度成套使用。** 主窗口可以同时包含工作区、阅读区和检查器，每个区域选择与任务相符的一套参数。一个区域内部的同类行、字段、图标和按钮保持一致。

| 区域配置 | 字体组合 | 几何组合 | 适用任务 |
|---|---|---|---|
| 标准桌面：默认 | 标题17；正文13；辅助11 | 32pt行/控件，20pt内容边距 | 项目、表格、属性、管理 |
| 密集专业工具 | 标题13/15；正文13；元信息11 | 28pt数据行，4/8pt紧密关系 | 文件树、参数、监控、工具面板 |
| 阅读与编辑 | 标题22；正文16/24；辅助12 | 24pt边距，500–720pt阅读列 | 长文、文档、笔记、详细报告 |

**稳定几何支撑精致感。** 相同对象的图标槽、名称起点、状态列和尾部操作槽固定；数值和日期形成清楚的比较列。选中、Hover和加载状态在原有区域内改变。窗口收窄时先调整剩余空间与辅助区域，最后切换主内容结构。用户选择、滚动位置、列宽和面板状态贯穿这些变化。

**内容表面与背景。** 文本列表、参数组和表格默认连续排列；独立媒体预览、跨任务对象或拖放目标使用独立表面。属性组通过标题、短说明和24pt分区间距组织。相邻面板使用分割线或空间边界，浮动工具和Popover表达真实覆盖关系。桌面空间用于同时呈现相关信息。

**标题与文字说明的份量。** 窗口标题帮助用户识别当前对象，正文标题帮助阅读具体内容，分区标题描述属性组。三者按各自职责出现。重复的页名可以合并到一个主要位置。字段标签常显；Tooltip解释快捷键或陌生术语；影响选择的限制、后果和状态就近显示。辅助信息采用清楚的小字号和适宜行距，保留完整阅读入口。[R05]

**品牌识别的主要位置。** 应用图标、欢迎界面、品牌图片、文档模板及少量自定义工具适合表达品牌。工作区的菜单、文本选择、焦点和窗口操作保持熟悉。插画与缩略图采用同一光源、裁切和饱和度原则；文档预览保持内容真实，缩略图角半径与相邻控件相协调。

**完整组件与完整工作区。** 组件规格同时给出内容角色、默认尺寸、字体、图标、颜色、状态及内容变化。工作区规格给出栏位职责、宽度计算、入口分布、最小可用宽度、收窄行为与持续状态。后文的几何公式和六套工作区配方共同组成默认视觉方案。

## 02 · 窗口、栏位与导航布局

本章采用统一的项目默认值：主内容边距20pt，阅读或完整表单边距24pt；侧边栏初始240pt、可调200–300pt；检查器初始288pt、可调260–360pt。系统标题栏、工具栏、菜单与安全区域使用当前系统的实际几何。示例窗口宽度均指扣除窗口外部装饰后的可用内容宽度。

**先按任务选择窗口结构**

| 主要任务 | 基础结构 | 内容主角 | 次要区域 | 收窄时的先后顺序 |
|---|---|---|---|---|
| 计算、转换、快速生成 | 单内容窗口 | 输入、结果与一个主操作 | 少量选项或说明 | 控件先纵向重排，保留结果区 |
| 管理项目、任务、资料 | 侧边栏＋内容 | 当前集合的列表或表格 | 右侧可选检查器 | 收起检查器，再收起侧边栏 |
| 阅读邮件、笔记、文件 | 侧边栏＋条目列＋详情 | 选中对象内容 | 文件夹、条目摘要 | 收起侧边栏，进一步收窄再让列表与详情分时呈现 |
| 绘图、代码、媒体编辑 | 资源栏＋画布/编辑器＋检查器 | 可连续操作的工作面 | 图层、资源与属性 | 检查器和资源栏分别可隐藏，中央区域保留 |
| 跨记录比较 | 侧边栏＋宽表格 | 同一组字段的横向比较 | 筛选、排序、非模态详情 | 收起辅助面板，保留表头及名称列 |
| 短暂查询系统状态 | 菜单栏入口＋Popover | 当前状态和高频动作 | 设置与完整窗口入口 | Popover使用固定舒适宽度，长内容纵向滚动 |

Apple 建议在Mac大屏中同时展示相关内容、减少不必要的层级和模态，提供窗口调整、菜单命令及个性化布局。[MAC01]

**栏位宽度由内容推导**

侧边栏解决“去哪里”，条目列解决“选择哪个对象”，详情解决“阅读与操作这个对象”，检查器解决“修改当前对象属性”。四种角色分别存在时，用可拖动分割线建立边界；只承担一种角色的页面保持单一主内容区。

| 区域 | 初始宽度 | 建议调整范围 | 过窄时的变化 |
|---|---:|---:|---|
| 侧边栏 | 240pt | 200–300pt | 完整收起并保留系统显示入口 |
| 邮件/笔记条目列 | 320pt | 280–400pt | 时间与状态转到次行；名称保留主体 |
| 属性检查器 | 288pt | 260–360pt | 标签在上、输入在下；再收起面板 |
| 一般详情 | 弹性剩余宽度 | 最小420pt作为此配方起点 | 从并列切换为单对象页面 |
| 文字阅读列 | 随内容缩放 | 通常500–720pt | 先收窄行长，再扩大纵向滚动 |
| 表格、画布 | 弹性剩余宽度 | 从任务最低可用面积推导 | 保留操作面，辅助区域先退出 |

三栏示例：1200 = 240＋1＋320＋1＋638。详情的638pt扣除左右24pt，得到590pt正文区域。此布局最低宽度采用200＋1＋280＋1＋420 = 902pt。低于902pt先收起侧栏；条目列和详情两栏的最低宽度为280＋1＋420 = 701pt。低于701pt时切换为列表与详情逐层呈现，返回后保留选中项和原滚动位置。

带检查器的工作台：1200 = 240＋1＋670＋1＋288。中间670pt扣除左右20pt后，实际内容宽630pt。若任务要求中央区至少560pt，其三栏最低宽度为200＋1＋560＋1＋260 = 1022pt。窗口低于1022pt时先关闭检查器，显示入口留在工具栏尾部。

阈值以各栏实际最低可用宽度重新计算。主内容的操作与阅读需求决定断点；侧栏宽度、分割线、内部边距均计入总宽度。

**标题栏、工具栏与正文标题**

系统窗口控制保留各自的默认几何与状态。工具栏前导区放导航、侧栏开关和对象名称；中区放可定制的常用工具；尾随区放重要动作、检查器入口、搜索与更多。工具分组一般控制在三个以内。文字动作与纯图标动作之间保留分组空隙，让按钮边界清楚。[MAC02]

| 情境 | 窗口/工具栏标题 | 内容区标题 | 文字层级 |
|---|---|---|---|
| 资料集合 | 当前集合名称 | 首屏可直接进入列表 | 标题遵循系统工具栏样式 |
| 集合概览 | 当前栏目 | 近期活动、本周进展等具体内容 | 17/22pt或22/26pt |
| 单文档编辑 | 文档名 | 文档本身的真实标题 | 内容语义字号，由正文结构决定 |
| 笔记已在首行写题目 | 单窗口中可省略重复名称 | 首行作为正文标题 | 22/26pt或编辑器定义 |
| 多个独立文档窗口 | 各自的具体对象名 | 按文档内容存在 | 保证窗口切换时可识别 |
| 设置窗口 | 当前设置分类 | 有分类导航时可省略重复大标题 | 分区15/20pt，字段13/16pt |
| 空状态 | 当前栏目名 | 当前状态，如“还没有项目” | 17/22pt或22/26pt |

窗口标题用于识别内容；Apple允许在重复时保留空标题区，并建议多窗口对象拥有可识别的名字。[MAC02]

**侧边栏的内部几何**

自定义侧边栏使用12pt横向内边距，常规行32pt。选中表面从侧栏x=12起，宽度216pt；行内容再缩进8pt。图标槽20pt，图标建议16pt并在槽中居中；图标槽后间隔8pt，文字起点为x=48。主名称用13/16pt，普通态Regular，选中态Semibold。单行文字上下8pt；右侧计数使用11/14pt和等宽数字，保留8pt右内边距。名称与计数至少留8pt。

组标题与组内第一行相距6–8pt；组与组之间20pt。分组标题可对齐到行内容框前缘x=20；各项目文字统一x=48。这样“组名”与“项目名称”形成可解释的层级缩进。只有文字的导航项，保留相同的文字轴或另立一个纯文字分组，整组一致。

导航层级默认两层；第二层缩进16pt。深层目录、代码文件树使用Outline并保存展开状态；名称较长时显示完整Tooltip或详情，重命名时展示可编辑的完整名称。系统侧边栏的文字、图标和行高随用户小/中/大设置变化，上述数字用于自定义区域。[MAC03][MAC04]

**Inspector与表单列**

288pt检查器使用左右16pt内边距，内部256pt。短属性行采用标签88pt＋间隔12pt＋输入156pt；输入内容更长时改为上下排列。分区标题13pt Semibold；标题至第一字段12pt；字段行间8–12pt；分区之间24pt。两列的小型数值输入可用(256－8)÷2 = 124pt每列，适合宽高、X/Y、起止值。单位放在数值旁固定位置；连锁比例按钮位于两字段之间时改为106＋8＋28＋8＋106 = 256pt；每个字段106pt、按钮28pt。重置等动作另占独立命中区。

检查器随选择更新，但分区顺序与字段位置保持稳定；多选中不同值用“混合”或系统混合状态，空值、零值和混合值采用各自清楚的表示。当前对象为空时显示“选择一个项目以查看属性”，保留面板宽度与基本结构。

**表格列宽和对齐**

表格优先满足查找、比较、编辑和批量操作。名称列可扩展，状态、日期、大小等列有稳定宽度。数值右对齐、等宽数字；表头与其数据列共享边缘。筛选信息显示在表格上方，活跃条件可单独移除。[MAC05][MAC06]

以可用宽630pt为例：选择28＋名称242＋状态92＋日期156＋操作64＋四个12pt列间隔 = 630。更简单的表格可把间隔包含在单元格padding中；同一表只采用一种口径。姓名/文件名占主要弹性；日期列的格式在整列一致，状态使用短文字；默认只显示最有价值的3–5列。新增列时优先让用户选择显示字段。

32pt标准行、28pt紧凑行、40pt舒适行分别对应13/16文字上下8、6、12pt。左右单元格内边距8–12pt，标题与数据采用同一内边距。长表固定表头；横向滚动时可固定名称列；冻结区分界使用一条轻分割线或微弱遮挡阴影，覆盖内容处保持清楚边界。用户调整列宽、排序和展开后，恢复原布局。

## 03 · 字体、字号、字重与文字构图

**规则范围。** 本章的〔官方〕指 Apple 当前字体规范与平台行为；〔本规范〕用于自定义内容的视觉体系。系统导航、菜单和标准控件优先保留平台排版，内容区域按阅读任务选择对应角色。字号均为原生界面的 pt；行高是文字行框的尺寸。

**字体选择。**〔官方〕常规界面采用系统字体。SF Pro 拥有多种字重、宽度及动态光学尺寸；系统随字号调整字形和间距。中文由平台按语言环境选择系统字形。采用可变字体的设计工具时，使用完整 SF 字体族和正确的字重即可；旧版 Text/Display 分档只用于工具能力受限的设计文件。[SRC01][SRC02]

字体按用途分成四个角色：界面操作文字用系统无衬线；长内容阅读使用独立的阅读样式；品牌字体放在少量专题标题；代码和需要逐位比较的数字采用等宽设计。品牌字体进入正文时需同时具备中文、数字、标点、粗体与斜体的协调方案。选择一套 Latin 品牌字体后，中文搭档从字面大小、笔画粗细和基线三方面匹配，常规控件仍采用系统字体。

**macOS 官方完整文字样式表。**〔官方〕下表为 macOS 内置文字样式。原生菜单、标题栏、Tooltip 与控件还拥有按用途定义的系统字体变体。项目字段标签默认 13pt，辅助文字默认 11pt，连续帮助文字 12pt；阅读内容独立采用 16/24pt。项目分组标题采用 13pt Semibold 时，属于本规范的自定义角色样式。[SRC01]

| 官方样式 | 默认字重 | 字号 | 行高 | 强调字重 |
|---|---|---:|---:|---|
| 大标题 Large Title | 常规 | 26 | 32 | 粗体 |
| 一级标题 Title 1 | 常规 | 22 | 26 | 粗体 |
| 二级标题 Title 2 | 常规 | 17 | 22 | 粗体 |
| 三级标题 Title 3 | 常规 | 15 | 20 | 半粗 |
| 标题 Headline | 粗体 | 13 | 16 | 特粗 |
| 正文 Body | 常规 | 13 | 16 | 半粗 |
| 提示 Callout | 常规 | 12 | 15 | 半粗 |
| 副标题 Subheadline | 常规 | 11 | 14 | 半粗 |
| 脚注 Footnote | 常规 | 10 | 13 | 半粗 |
| 注释 Caption 1 | 常规 | 10 | 13 | 中等 |
| 注释 Caption 2 | 中等 | 10 | 13 | 半粗 |

上述字重名称对应 Regular、Medium、Semibold、Bold、Heavy。常用内容优先选择正文、提示和副标题角色，平台小号注释用于相应的短小标注。Mac 的阅读字号通过内容偏好与布局共同安排。

**项目文字角色起点。**下表将阅读任务映射到固定默认值；后续放大按平台与内容需要进行。

| 角色 | macOS 内容建议 | 字体与视觉职责 |
| --- | --- | --- |
| 平台普通 UI 正文 | 13pt | 平台默认基准；列表、标签、常规说明 |
| 长文阅读 | 默认 16/24pt | 足够行长与阅读距离，文字优先 |
| 内容标题 | 默认 22/26pt；工作区分区 17/22pt | 独立内容页、编辑对象标题 |
| 主列表组标题 | 13/16pt Semibold 项目样式 | 连接相邻的一组列表内容 |
| 文章章节标题 | 15/20pt Semibold | 连接一段具有完整主题的阅读内容 |
| 高密度分组标签 | 默认 13pt；紧凑辅助 12pt | 使用字重与位置表达级别 |
| 辅助说明 | 默认 11pt；连续帮助 12pt | 内容补充，保持可连续阅读 |
| 时间、来源、短元信息 | 11pt | 主内容之外的事实标签 |
| 关键数字 | 默认 26/32pt；紧凑摘要 22/26pt | 数值居首，名称与单位随后 |
| 代码/精确标识 | 12–14pt | 等宽字形，提供足够字符空间 |

13pt 是 macOS 普通界面文字的默认尺寸；内容阅读与编辑采用独立字号。系统窗口标题和控件文字沿用平台样式，正文标题按对象和任务选择。[SRC01][SRC18]

**字重分配。** 正文及字段值以 Regular 为主体；可操作短标签可用 Medium；局部标题、当前选中项、主要按钮采用 Semibold；Bold 用于少量主标题和核心数字。相邻对象属于同一级时，字重保持一致。当前选中项若已经拥有色面和标记，字重只增加一级。长段正文中强调一段内容，优先单独分段或加小标题。

| 排版组合 | 主文字 | 次文字 | 元信息 | 组内关系 |
|---|---|---|---|---|
| Mac 文件表格 | 13 Regular | 12 Regular | 11 Regular | 统一行高，分列对齐，选中态用平台表现 |
| Mac 检查器 | 13 Regular 标签 | 13 Regular 值 | 11 说明，连续帮助 12 | 字段列稳定，说明与对应字段相邻 |
| Mac 阅读详情 | 22 Semibold 标题 | 16 Regular 正文 | 11 来源 | 内容与窗口操作栏形成清楚比例 |

**文字层级。** 一个内容区域使用约三种可感知层级：标题、正文、辅助信息。可通过字号、字重、颜色和留白的组合建立层级。相邻两级只改变其中一至两个因素，更容易保持平静而有序的视觉。重要说明沿用正文级别，次要标签才下降到辅助字号。页面包含多个分区时，所有同级标题共享同一字号、字重和上下间距。

**行高与段落。**〔官方〕系统文字样式包含字号、字重与行距的关系；长段内容可以使用宽松行距，三行及以上内容应保留正常或宽松的行间空间。[SRC01]〔本规范〕13/16pt 为常规 UI 正文，长文默认 16/24pt。短标题通常维持 1.15–1.3 倍行高，阅读正文约 1.45–1.6；字面较高或附带多种文字时适当增加。阅读段间默认 12pt，章节之间 24pt；工具分区通常使用 20–24pt。段落间距和行距承担不同职责：前者分开思想，后者维持连续阅读。

**中文、英文、数字混排。** 中文采用正常字距；短标签沿用系统 tracking；数字和英文保持字体自然间距。给中文标题加入大幅字距会减弱词组连续性，字距扩张只用于极短的品牌展示。中文与英文相邻时使用一致的排版策略，由文本系统或内容规范管理空隙；账户、URL、文件名、可复制标识保持原始内容。全角标点与正文共享字号，表单字段名一般省略末尾冒号，长阅读文本保持中文标点习惯。中文与 Latin 字体配对时，以可见字面高度和笔画视觉重量判断，名义相同的字号可以有不同的视觉尺寸。

**基线和单位。** 金额、百分比和单位共享基线；大数字旁的单位用正文或辅助字号。将单位放到右上角适用于科学上标或明确的专用排版。金额表格用等宽数字和小数点关系维持可扫描性；频繁变化的计时器用等宽数字防止宽度跳动。文本按钮里的图标以符号基线与文字协作，放置日期、数值和右侧操作时优先让主信息基线相齐。

**换行、宽度和长内容。** 阅读列默认在 500–720pt 之间随窗口调整，16pt 正文约能容纳 31–45 个全宽汉字；具体行长由字号和实际字面宽度推导。640pt 阅读列约能容纳 40 个全宽字。普通 UI 说明前缘对齐；居中用于短空状态、短结果或明确的品牌画面。多行标题的换行以词义完整为优先，英文长词采用平台断行；数据表主键、金额和单位作为清楚的组合呈现。

**字号改变后的构图。** 内容阅读字号可独立设置；工具栏、菜单及侧栏服从各自的平台样式。放大阅读文字时，副标题自然增高，元信息可移到主文字下方，多列内容减少列数。图文关系以基线和间距约束维持，控件高度跟随完整文字；编辑区域继续保留当前阅读位置与上下文。

**用完整的文字组合设计一个区域。** 给一段内容选择样式时，同时确定「主信息—解释—状态—操作」，使四者形成稳定秩序。列表行里的文件名采用 13pt Regular，修改时间采用 11pt Secondary，右侧短状态采用 11pt Medium，行内辅助动作保持平台按钮样式。文件名承担阅读焦点，前方符号提供类别。带介绍的功能入口用 13pt Semibold 标题和 12pt 说明，标题与说明相距 4pt，分区之间 20–24pt。同类入口共享标题、说明和尾端动作的关系。

Mac 的文字组合根据工作对象分配密度。文件管理区用 13pt 主名称、11pt 元信息，方便与多列数据同时比较；阅读详情改为 16pt 正文、22pt 标题，阅读内容成为窗口主角；属性检查器用 13pt 标签和 13pt 值，紧凑辅助标签可用 12pt，组标题以 13pt Semibold 表示。三个区域共用系统字体、颜色角色和对齐规则，尺寸随任务改变。较长帮助文字采用 12pt，放在对应字段的下一行。

| 一组完整构图 | macOS 推荐样式 | 布局关系 |
| --- | --- | --- |
| 账户摘要 | 22 Semibold 姓名；12 Secondary 说明 | 头像与整组文字居中，名称和说明前缘相齐 |
| 项目卡片 | 13 Semibold 名称；13 Regular 摘要；11 元信息 | 摘要两至三行，元信息位于同一内容列 |
| 设置行 | 13 Regular 标签；12 Secondary 连续帮助 | 标签与控件建立一行关系，帮助文字贴近对应标签 |
| 数据摘要 | 26 Semibold 数字；12 Medium 名称；11 变化 | 同组数值共用基线，单位与名称各有稳定位置 |
| 错误说明 | 12 Medium 简短结果；12 Regular 解决办法 | 状态图标对应第一行，动作放在说明之后 |

| 编辑中的字段 | 13 Regular 输入值；11 说明，连续帮助 12 | 字段名可持续识别，格式示例低于字段名层级 |

**字号的选择顺序。** 先按照阅读距离、信息密度和平台给正文选择 13pt 的基准；阅读型页面采用 16/24pt 的正文组合；标题再按内容地位增大。窗口工具栏已经清楚表达当前集合时，正文可直接进入分区或内容。独立内容标题需要与导航名称并存时，导航表达所在位置，内容标题表达具体对象。编辑器标题、文档名称和文章标题可以采用内容字号；工具栏动作与侧栏项目继续服从平台尺寸。页面各层的字号比由整体关系决定，品牌展示只占少量内容时可使用更大的展示字。

**行框、字面与基线分别处理。** 文字在设计工具里的矩形是行框，可见字形通常只占其中一部分。标题下方到正文上方的间距以行框定义，随后结合可见字面检查视觉节奏；同一字体样式的文本框高度保持一致。两个文本框名义上都为 20pt 高，实际字面可能一高一低；在同一行排列时用基线建立关系。一个 16/24pt 段落的行距由字体度量和行框共同形成，字号、行高、段落间距分别记录。多行文本的末行和下一组内容之间保留约定分组间距，末行是否含下降部字母不会改变下一组的布局位置。

把可见字面用于微调组件的视觉中心，把基线和行框用于重复布局。中文单行标签与 SF 数字相邻时，优先采用系统混排；中文标题、时间、操作同时存在的一行，选择主文字基线作为锚点。带图标按钮让图标与标签形成一个整体，再将整体放入按钮中。数字强调卡里的数值可以视觉居中；数值下的单位说明与同类卡片共享基线。行框留白产生的偏差由组件统一处理，组件各实例使用同一关系。

**字体配对细节。** 系统界面默认使用一种字体家族。选择品牌衬线作为文章标题时，正文可以保留系统无衬线；选择圆体表达轻松语气时，在标签、数字、标题中选取一个稳定的使用范围。中文品牌字与 Latin 字混排，优先匹配中等字重下的横画厚度、汉字字面高度与英文字母 x-height，然后调整相对字号；下移或上移只作用于该配对组合。对一段普通正文，中文、数字和标点的黑度应接近，英文缩写保持清楚且与前后汉字连贯。以正规字体的字重文件和字形变化进行强调，斜体用于字体拥有相应设计的文字，中文强调由字重、位置和标点表达。

**字距与标点的具体规则。** 短 UI 标签采用字体默认字距，中文密集表格通过列宽和间距控制密度。英文全大写的小型类别标签可以从 0.04–0.08em tracking 开始，但同级中文类别沿用正常字距；英文普通句子和标题使用系统字距。大号短英文品牌标题可小幅收紧，使用品牌字体自己的字偶距。括号、引号和破折号沿用语种的规范字形；中文括号与前后汉字的间隔由全角字面承担。把可点击词语、版本号与单位分段着色时，保留原来的基线和自然间距。复制内容中的空格、符号和大小写与真实值保持一致。

**阅读段落与功能说明。** 阅读段落每段表达一个主题，长段之间用段落间距分开；功能说明以一到两句解释动作对象、结果或约束。已经可从按钮名称理解的动作采用短动词短语；陌生功能的说明优先解释使用后发生什么。输入提示示例通常可用一行，长期存在的格式要求放在字段外的说明位置。需要用户依照完成的步骤采用有序内容与清楚分组，标题下的引言与步骤正文使用同一阅读级别。错误文字描述当前状态和可执行修正方式，文字大小与其他说明保持一致。

**数字、单位与表格。** 成列金额用统一货币格式、千分位和小数位数；小数位按数据真实精度显示，列宽预留常见最大值。只有部分行包含单位时，将单位放在表头或稳定的独立列，数值继续尾端对齐。进度百分数和时间读数选用等宽数字，数字变化时保持所在容器宽度。单个大数值使用比例数字可获得更自然的标题节奏；多个需要逐位比较的数值使用等宽数字。日期和时间使用本地格式，文件名和技术标识允许保留其原有字符。对比列以数量值的精度和单位统一为前提，视觉对齐体现这种逻辑关系。

**标题与字重的精细节奏。** 标题的上方留白通常大于下方留白，形成「标题属于后面的内容」的关系。内容组标题默认上方 20pt、下方 8pt；章节或检查器分区之间使用 24pt。同级组间距保持一致，紧接页面内容标题的第一组可减少额外上间距。两行大标题沿用同一字重，标题中的次要括注可以移到副标题或采用更轻的颜色。短数值单位、按钮、徽标、分区标题同时处于 Semibold 时，以位置和颜色进一步安排主次，视觉焦点通常保留在最重要的对象和动作上。

**辅助功能与内容增高。** Apple当前Accessibility尺寸表列出Mac默认控制28×28pt、较小控制20×20pt；本规范常用独立操作采用28×28pt起。32pt行高和52pt双行是默认文字的起点，多行标签或内容字号增大后，实际高度按文字行框与上下padding计算。输入字段获得焦点时保留完整标签与当前值，语音及键盘阅读顺序遵循区域内的内容关系。[SRC18]

## 04 · 功能图标、业务符号与品牌 App 图标

**图标系统的组成。** 为每种图标记录语义名称、来源、用途、渲染方式、字重、尺寸角色和选中变体。界面上的图标包含三个不同角色：平台动作符号、产品业务符号、品牌 App 图标。动作符号从 SF Symbols 选择；独有业务概念用自定义符号配合文字；品牌图标由原创图形表达产品身份。

**SF Symbols 的尺寸与比例。**〔官方〕SF Symbols 提供与系统字体对应的字重和三个相对尺度，并包含基线与边距信息。符号尺度相对字体的大写字母高度定义，外轮廓的宽高自然随形状变化。[SRC03]〔本规范〕相同功能位置使用同一 text style、weight 与 scale。长形钥匙、圆形时钟、横向云朵共享同一布局槽位，各自保留自然比例。列表文字共享起始线，图标槽位共享中心线；图形宽度由符号决定。[SRC20]

| 场景 | Mac 建议起点 | 渲染方式 |
| --- | --- | --- |
| 正文中的语义符号 | 跟随正文 13pt | 同字重、同文字基线 |
| 自定义列表导航图标 | 默认 16pt 符号 | 普通动作以 monochrome 为主 |
| 自定义独立工具按钮 | 默认 18pt；较大工具 20pt | 图形与点击容器分别设定 |
| 内容展示符号 | 24–36pt | 按内容可用 hierarchical |
| 空状态主题图形 | 32–48pt | 少量层级，配短标题和说明 |

数值用于自定义图标角色；系统 Tab、Toolbar、菜单图标采用平台自身尺寸。相邻的文字与符号视觉重量协调：常规说明配 Regular 符号，强调按钮可配 Semibold 符号。

**基线与槽位。**〔官方〕SF Symbols 有各自与文字的基线关系，某些形状可高于或低于基线；该关系用于光学平衡。自定义符号模板支持左右边距及负边距。[SRC04][SRC05]〔本规范〕图文组合优先使用符号原有基线；固定画布 SVG 图标则在自身画布里光学居中。列表采用 20pt 图标槽与 8pt 图文间距，使不同宽度图标后的正文共享起始线。带角标图标仍以主体位置确定视觉轴，角标附着在主体上。

**渲染与状态。**〔官方〕Monochrome 使用单色，Hierarchical 用同色不同层级，Palette 为各层指定颜色，Multicolor 保留对象固有颜色。描边、填充、斜线和外包形状可表达选中、禁用或特定状态。[SRC03]〔本规范〕一个工具栏内的普通命令维持单色和相同视觉重量；导航选中项采用平台提供的填充/强调样式。状态图标在含义稳定时变化：收藏从空心到实心，音频从播放到暂停，上传从箭头到完成符号。一般内容符号与相邻文字采用相同语义前景色，状态颜色只用于具有状态含义的部分。

**自制固定画布业务图标。** 选定 24×24 基础画布、约 20×20 主要图形区域，四周留 2 的安全带；初始笔画固定为 1.75pt，并在整个家族维持同一规则。统一端点形状、线连接、内圆角和斜线角度。圆形通常比同组方形略向外延伸，三角形和不对称图形可移动 0.5–1 个设计单位，以形成相近视觉体积。Figma 官方教程展示了 24 画布、20 有效区域和 0.5 微调的制作方式；这些值属于制作起点。[SRC06]

图标版本按实际显示尺寸优化。16pt 资产适当放大孔洞与间隙，删去内部装饰；20–24pt 资产保留主要结构；32pt 以上才加入必要的次级细节。同一套图形至少保持一个圆形、一个方形、一个长形和一个带角标形状的关系。画布边距、主体占比、线宽、内部留白一起决定视觉体积。IBM 当前设计体系也明确按视觉重量做光学居中，并使用资产留白修正偏移。[SRC07]

**自制 SF Symbol 业务符号。**〔官方〕以 SF Symbols 模板创建，遵循模板的字重、尺度、基线和边距；轮廓采用闭合填充路径，支持分层颜色和动态变化。Apple 当前文档说明多个源字重可插值生成其余变体。[SRC04]〔本规范〕复杂业务概念先提炼为单一可识别物体或动作，再制作符号。图形在 16–24pt 下优先保留主轮廓和关键差异。自定义符号与平台动作符号放在同一行时，以匹配字体的视觉重量为目标。

**图标与文字的职责。** 一级导航、陌生业务能力、风险动作和多含义操作常显文字标签。高度熟悉的返回、关闭、搜索和更多可以独立显示符号，当前页面给出清楚语境。Tooltip 用于 Mac 工具栏的补充说明；表单约束、风险后果、权限用途放在可见文案里。上下文菜单与右键菜单中的命令采用具体动作名称，图标作为辅助识别。

**品牌 App 图标。**〔官方〕Apple 当前 App Icon 指南鼓励以少量简单形状构成独特概念，并让各外观共享相同的识别核心。[SRC08]〔本规范〕主体只保留一个视觉焦点；背景以单色或克制渐变托住主体；主体四周有可识别的负空间；小尺寸下仍保留清楚轮廓。跨平台品牌保留相同识别骨架，Mac Dock 图标适配系统容器。层叠图形的前后关系由不同图层表达；明暗、透明及着色外观保留主体形状、关键孔洞和比例。App 图标由原创品牌图形制作；SF Symbols 的使用授权面向界面符号，其官方条款排除 App 图标、Logo 和其他商标用途。[SRC03][SRC08]

**选择符号的语义顺序。** 优先使用与平台已有动作一致的符号。分享使用系统分享形象，搜索使用放大镜，收藏使用产品既定的星形或心形，筛选与排序分别表达条件收缩和顺序改变。一个业务概念固定对应一个名称和一组符号变体。加号表示新建时，旁边文字说明新建的对象；上传和导入若在同一界面出现，文字写出操作方向与目标。颜色、徽标和圆形衬底用于补充状态，基础轮廓先承担动作含义。

| 内容角色 | 图形策略 | 标签策略 |
|---|---|---|
| 平台通用动作 | 与系统一致的 SF 符号 | 独立按钮可用 Tooltip 或辅助标签；陌生语境显示短文字 |
| 一级业务入口 | 统一类别图形 | 常显名称，确保不同入口易辨 |
| 相近业务功能 | 轮廓保留关键差异 | 常显具体对象与动作，如「导入文件」「上传附件」 |
| 危险动作 | 语义符号配危险色 | 可见动词说明作用对象 |
| 状态 | 同一家族的状态变体 | 用「同步中」「已完成」等短词明确含义 |
| 数据类别 | 固定类别符号或形状 | 名称在列表或图例中持续出现 |
| 装饰主题 | 插图或展示图形 | 与操作控件保持不同的形态与位置 |

**建立自定义图标的骨架。** 在 24×24 画布上，先定义居中的关键形状：直径 20 的圆、18×18 的方形、20×16 的横向形、16×20 的纵向形。各形状围绕同一中心形成一个起始家族，后续按视觉面积细调。主要轮廓占据 keyline 附近，局部尖端和角标可越过主区域进入预留空间。这个家族选择 1.75 单位笔画时，同组圆、方、箭头与复合对象均沿用它；16 尺寸的专用变体以约 1.2–1.4 单位作为起点，给小尺寸更多有效黑度。圆头会令可见线条比中心路径更长，线段端点位置按可见轮廓建立关系。

统一笔画还包括端点、拐角和连接规则。柔和功能图标可采用圆头和圆连接，方正工具类图标可采用平头和轻圆角连接；一家族以一种主要语言为主。45° 斜线适合常见箭头和编辑形象，其他角度服务于清楚轮廓。并排线条之间的空隙以 1.5–2 个笔画宽作为起点；复杂区域至少给主要孔洞留下接近笔画宽度的空间，16pt 版本再扩大。内轮廓的转角与外轮廓协调，窄小尖角可以略钝化，让视觉黑度更均匀。两条粗线汇合的地方适当扩开内侧负空间，减轻黑色结点。

**一套图形在不同尺寸的关系。** 16、20、24、32 四个尺寸可以共享主轮廓，细节数量随尺寸改变。小尺寸里保留识别概念的两至三个结构：文件的外轮廓、折角、一个内容标记；放大后再呈现更多结构层次。带角标图标优先保证主对象仍可识别，角标围绕主轮廓有清楚间隙。圆形头像上的状态点以头像为主，状态点从外框向外伸出，背景隔离环取相邻表面的颜色。小图标下的高光、投影与多层透明通常会干扰轮廓，功能图形以清楚的前景形状为主。

**视觉重量的修正次序。** 先比较主体占据的面积，再比较笔画与内部空隙，最后调整位置。一个云朵显得过小，通常先增大主轮廓或增加符号 scale；一个齿轮显得过重，先降低复杂度或匹配更轻字重。位置修正用来解决几何不对称，尺寸与笔画修正用来解决重量差异。圆形与正方形并排时，圆形直径略大可以形成相近的视觉量；长窄图形保持其自然长宽比，并让主体中心落在稳定槽位。字体大小改变后，SF 符号继续跟随字体角色；自定义资产采用相应尺寸变体。

**图标颜色的角色。** 常规工具图标使用与旁边文字一致的 primary 或 secondary 色；可点击性由区域、排列、标签和状态共同传达。当前选择用 selection 前景或系统强调色，选中图标的填充、标记与文字形成统一关系。信息图标可以使用蓝色，警告使用琥珀色并搭配形状和名称，错误使用红色并保留解释。独立色面图标作为业务类别时，控制为稳定的一组低饱和底色和清楚前景，所有类别拥有相近视觉重量。菜单和工具栏同一层级的图标共享渲染模式。

**图标与组件共同构图。** 正文前的符号作为语义前缀，采用正文基线；列表中的文件类型图标作为对象缩略图，与文字块居中；工具按钮的图标以按钮可见表面的中心为锚。独立图标按钮的图形尺寸、可见容器和触控区域分别规定。列表默认 16pt 图形，独立工具默认 18pt、较大工具 20pt；图形放在至少 28×28pt 的自定义交互槽位中。头像、缩略图、徽标和装饰插图分别拥有自己的组件角色，图形占比随角色变化。替换图标时保持文字列起点和组件宽度稳定。

**App 图标的母版与主体比例。**〔官方〕当前 Apple 指南为 macOS 列出 1024×1024px 的方形布局；系统对方形图层施加圆角遮罩。主内容置于官方生产模板的中心与网格关系内，图层的遮罩由系统生成。Icon Composer 支持图层摆放、材质效果及各外观变体。[SRC08][SRC19]〔本规范〕图标以一个主形状建立记忆点，第二个形状仅在共同形成独特概念时出现。一个居中徽记的构图示例可让主体宽度占画布约 60%–72%，再按细长或饱满轮廓调整；正式图形的位置沿用当前平台模板的关键线和安全区域。背景、主体、细节分开，主体的负空间和外轮廓在小尺寸依然清楚。

图标主体的轮廓可以参考产品的核心对象、动作或名称意象，提炼成具有识别度的组合。复杂场景适合作为内容插图，品牌图标聚焦于一个可记忆的形象。字母型 Logo 使用少量独特字形，笔画与负空间适合缩小。深浅变化保留同样的轮廓比例，亮色主体在深色版里可以适当降低发光感，深色主体在浅色版里保持足够边界。着色版让明度层次表达不同形状，主体之间的重叠关系在单色条件下依然清楚。

| App Icon 外观 | 图层关系 | 视觉设计要求 |
|---|---|---|
| Default | 品牌背景与主要图形 | 清楚轮廓、单一焦点、稳定负空间 |
| Dark | 保留核心主体，调整各层明度 | 主体与背景保持明度分离，局部高光克制 |
| Clear light / dark | 由系统透明外观和分层呈现 | 关键轮廓与孔洞完整，前景层相互可辨 |
| Tinted light / dark | 系统着色与单色信息关系 | 识别依靠形状和明度，细小彩色差异可转化为结构差异 |
| 小尺寸系统位置 | 系统按用途缩放 | 主体优先，重要负空间保留，细节数量精简 |

**Mac 图标的使用场景。** 品牌图标覆盖 Dock、切换器、搜索和其他系统位置，主形象在小尺寸与密集图标环境中保持清楚。文档类型图标、侧栏图标、菜单栏状态图标分别服务于具体用途：文档图标表达文件类型，菜单栏状态图标用简洁模板形状表达驻留功能和状态，侧栏符号表达目的地。App 图标提供产品身份，功能图标提供具体操作。菜单栏图形随平台明暗外观适配，状态变化维持同一主体。

**内容中的图像与文字轴。** 图文卡先定义图片框，再定义文字列，图片的主体焦点可在裁切框内微调。照片中的人物脸部、产品实体与品牌标志拥有不同视觉重量，同组素材采用一致背景、比例与主体占比。透明产品图以物体可见底部建立共同基线，物体影子保留在自己的视觉范围；头像以眼线和面部大小形成稳定关系。带图片列表的主标题与图片顶部或整个文字块中心选择一项固定规则，所有项目沿用。复杂图片上的文字通过独立衬底维持稳定起点和对比，文字的读序与主体焦点互相配合。

## 05 · 对齐、视觉重量、圆角与边界精度

**建立四条对齐关系。** 内容前缘线决定标题、正文和段落的横向起点；文字基线决定同一行标签、数字及单位的垂直关系；槽位中心线决定列表图标、头像与按钮的位置；容器边界线决定背景、分隔和内容缩进。一个列表通常以这四类关系完成布局，新增自由坐标仅用于已定义的视觉修正。

**按信息关系对齐。** 普通文字前缘对齐，数据表可比较数字尾端对齐。两行文字旁的图标有两种稳定模式：与主标题第一行对齐，适合说明、步骤和表单；与整个文本块居中，适合联系人、附件和对象列表。同一分区采用统一模式。右侧数值与主标题共享基线，右侧 Toggle 与整行的交互区域居中。长说明换行后保留自己的文本列起点，分隔线可从文本列开始，强化同组内容的连续关系。

**光学修正的应用边界。**〔官方〕Apple 描述新设计系统时，将视觉上的轻微偏移作为几何系统的一部分；IBM 也按图形视觉重量进行居中。[SRC07][SRC09]〔本规范〕先建立数学对齐，再在组件内部修正不对称轮廓。常见修正包括：圆形中的播放三角向尖端方向移动约 0.5–1.5pt；斜向箭头按实际黑色面积调整；带角标主体以其基础形状为锚；圆形与矩形并排时适当增加圆形直径。修正属于特定资产和尺寸，放入组件定义后重复使用。

| 元素关系 | 设计示例 | 视觉结果 |
|---|---|---|
| 图标列 | 20pt 图标槽 + 8pt 间距 | 密集排列仍有稳定轴线 |
| 16pt 播放三角 | 在圆按钮内向右约 1pt | 主体视觉重量更接近容器中心 |
| 标题与行内金额 | 同基线；金额用等宽数字 | 横向扫描稳定 |
| 头像与两行文字 | 头像与文本块居中 | 对象身份与说明成为同一组 |
| 步骤编号与说明 | 编号靠首行中心 | 长段说明保留开头关系 |
| 异形按钮图形 | 组件框不动，仅调整图形内边距 | 点击几何与视觉修正各自稳定 |

**可见面积与视觉重量。** 相同外接框的圆、方块和三角具有不同可见面积，图标家族应以看起来同样有分量为目标。方形内部面积更满时可以缩小外形，圆形可以略大，线条密集的符号可减轻字重或减少内部结构。文字使用 Semibold 时，旁边符号调整到同等重量；对称布局中有高饱和色块时，其视觉重量通常高于同尺寸中性色块，另一侧采用相匹配的留白或内容规模。

**圆角按角色分配。** 系统窗口、Sheet、Tab 和原生按钮保留系统形状。自定义内容采用 4pt 小标签、6pt 缩略图、8pt 输入区域和按钮、12pt 内容面板、16pt 独立大浮层。按上述组件角色统一使用圆角。需要胶囊的控件用高度的一半作为圆角；紧凑 Mac 参数区使用圆角矩形更容易保持密度。Apple 新设计专题说明了固定、胶囊和同心三类形状，并将桌面大小控件分配到不同形状。[SRC09]

**等距嵌套的同心圆角。**〔官方〕Apple 给出的同心关系为父圆角减去内边距。[SRC09]〔本规范〕当内层轮廓与外层轮廓等距内缩时，使用 `R内 = max(0, R外 − p)`；p 从外轮廓到内轮廓量取。若外层有边框 b，边框之后的间隙为 g，则 p=b+g。

| 外圆角 | 外到内的距离 | 内圆角 | 适用组合 |
|---:|---:|---:|---|
| 24 | 8 | 16 | 大面板中的图片或内容表面 |
| 20 | 12 | 8 | 带较宽内边距的预览容器 |
| 16 | 4 | 12 | 边界紧密相连的双层表面 |
| 12 | 12 | 0 | 内层已抵达外角圆心以内，矩形关系更自然 |

该关系用于共享角部中心的嵌套表面。独立的按钮、标签和浮动操作保留自己的角色圆角。连续曲率圆角使用平台给定的形状，公式作为设计起点；实际曲率由该形状维持。

**不等内边距。** 左右内边距为 px、上下内边距为 py 时，单一圆角半径只能满足一个方向的同心关系。为获得清楚的角部节奏，优先让靠近角落的内层表面使用等距留白，再用内容内部间距调整排版。设计需要不同留白时，可用椭圆角半径 Rx=R外−px、Ry=R外−py 保持角中心相同；这是椭圆角构图，边缘距离随方向变化。系统或组件仅提供一个圆角值时，以相邻的主要边缘间隙决定圆角，并让另一个方向通过较直的区域过渡。各角内边距不同时分别处理，避免把一个计算值机械套到四角。

**边框与阴影的角色。** 边框分三类：装饰分隔用于轻分组；控制轮廓帮助识别输入或选择范围；焦点轮廓表示当前键盘位置。装饰分隔可较淡，控制与焦点拥有足够对比。边框尽量绘制在组件内部，保持整体尺寸和布局占位稳定。阴影用于弹出、悬浮和拖动中的对象；正文表面通过留白、背景和分隔完成层级。相邻嵌套表面只保留最有意义的一条边界。

**点与像素的关系。**〔官方〕Apple 的逻辑坐标使用 pt，实际像素由显示倍率转换；当前 CALayer 文档举例说明 50pt 在 2× 时映射为 100px。[SRC10]〔本规范〕重要布局间距使用整 pt 或统一的子单位；细直线按设备像素边界对齐。以 2× 屏幕为例，1 个物理像素对应 0.5pt；0.5pt 宽的直线中心在 16.25pt 时，两边缘落在 16.0 和 16.5pt。一般关系为线条中心 `x=n/s+w/2`，s 是倍率、w 是线宽、n 为像素边界序号，适用于没有额外缩放的水平或垂直线。曲线、斜线和文字保留抗锯齿。系统分隔线让平台处理，精确像素规则用于自绘细线和图形资产。[SRC11]

**图片与圆角内容的边界。** 图像裁切使用统一的内容比例与焦点位置；同组缩略图的外框、圆角和视觉重量一致。透明 Logo 放入固定背景和固定槽位，再按视觉比例调整；文字标志通常需要比方形标志更宽的容器。背景图片靠近文本区域时增加稳定衬底或空间过渡，让前景标题的颜色和位置维持连续。

**从内容前缘推导整个列表。** 以 240pt 宽的自定义侧边栏为例，选中表面从 x=12pt 开始，行内容在表面内继续缩进 8pt，图标槽从 x=20pt 开始；图标槽宽 20pt，图文间距 8pt，文本起点为 x=48pt。名称、副标题与项目元信息采用同一文本轴，分组标题可以从 x=20pt 开始，表达它覆盖整组对象。内容表格的标题和单元格共享各自列的起点，主内容区默认边距 20pt。多级目录的下一层默认缩进 16pt，图标槽宽度维持一致。

两栏表单的标签列共享尾端线，控件列共享前缘线；英文标签长短不同也能形成清楚的标签—值对应。检查器可以采用标签在左、控件在右，长字段名、窄面板或较长说明采用标签在上、输入在下；说明与输入共享前缘。数值列共享尾端，文字列共享前缘，带图标值的图标置于独立槽位。靠齐策略根据阅读任务安排，整体页边距和列间距仍保持稳定。

**相邻形状之间的可见间距。** 设计中的 8pt gap 指组件布局框之间的距离；当两枚图标拥有不同内部留白时，它们的可见边缘距离会变化。普通工具栏维持均匀槽位，以动作位置的规律为主；图标加文字的短按钮维持可见图形与首字之间的平衡，以整体构图为主。自制图标的左右边距可以不同，让文字旁的实际负空间接近。气泡、箭头和角标的尖端属于视觉轮廓，测量主体与文字的关系时采用主体边缘，尖端保留在附加形状里。

**用可见轮廓解决四类偏移。** 播放三角的可见重心向厚底边聚集，在圆按钮里向尖端方向微移；斜向箭头的长尾与箭头头部构成不同重量，可以略向尾部相反方向修正；对勾的两臂长度不同，把视觉中心放在其折点与长臂形成的主体区域；汉字和数字的顶部留白不同，同排文本以基线衔接，垂直居中的单行按钮再依可见字面微调。每项微调只改变该资产的内部位置，组件槽位、点击范围和相邻内容轴保持一致。20pt 图形从 0.5pt 开始微调，常见偏移控制在约 1pt 的量级；超过该范围时重新检查资产边界与主体比例。

**上下与左右留白的感知。** 同样 16pt 的四周留白包住大写英文、中文和图片时，视觉松紧有所不同。文本容器先以行框计算上下 padding，再按相同样式的整组内容保持一致。带两行正文的卡片可以上 16、下 16；标题在顶端且尾端有动作时，标题至正文 8、正文至动作 16、动作至底部 16，空白对应不同关系。外层间距大于内层间距，使一张卡里的内容归属于同一个对象。界面顶部或完整画面的视觉重心可以略高于几何中心，短空状态的图文整体通常放在可用区域的中心偏上位置，以补偿底部操作区域和视觉重量。

**圆角与尺寸成组增长。** 圆角大小由组件体积和层级共同决定。常规 32pt 自定义输入和按钮默认圆角 8pt，内容面板默认 12pt，缩略图默认 6pt；独立大浮层可采用 16pt。每个组件采用与其角色一致的形状。交互 Chip 的胶囊形状表达完整操作单元，内容容器的圆角矩形保留更多横向排列空间。相邻圆角形状使用一致曲率语言，外部较软、内部更紧的嵌套节奏可以通过同心关系推导。

**嵌套圆角的边框计算示例。** 一个外圆角 24pt、内描边 1pt 的面板，边框内到图片的间距为 7pt，外轮廓到图片轮廓的距离为 8pt，图片圆角取 16pt。若图片本身再包一条 1pt 边框，图片内容轮廓继续向内缩 1pt，相关圆角也相应收紧。多层结构中的每个距离均从相应的真实轮廓计算。内阴影的视觉宽度不计入几何 inset，描边真实占据的宽度才参与边界关系。内层图片和外层容器只有顶部相邻时，上两角用同心关系，下两角采用图片自身角色的形状。

外圆角 R=24、水平内缩 12、垂直内缩 8 的情形，原角心在外轮廓坐标 (24,24)。内轮廓左上角位于 (12,8)，若希望共享角心，内椭圆半径为 (12,16)。它提供相同角心的视觉结构，顶部和侧面的留白各为各的值。若组件只支持圆形圆角，可让图片周围先形成 8pt 等距子容器，剩余 4pt 横向留白放在子容器内的内容排版；这样图片与外框形成清楚的角部关系，文字仍可采用不同缩进。轮廓、角心与半径共同确定这组形状的关系。

**分隔、描边与图形清晰度。** 连续列表通常把分隔线放在内容行之间，边界短于整行时与文字列起点对齐；分区之间改用较大的空白或背景关系。自定义输入框的轮廓是控件识别的重要部分，颜色和线宽保持清楚；轻卡片的细描边只补充表面边界。自绘 1px 直线优先让两侧边缘落在真实像素边界上；1pt 与 1px 分别作为不同尺寸记录。设备倍率或画面缩放改变时，像素对齐重新按真实 backing scale 推导。图标曲线、斜线和圆角依赖抗锯齿形成柔和轮廓，采用统一精度的矢量资产。

**状态颜色组合。** 组件状态按背景、边界、前景和标记四项组合：Normal 用 surface 和正文；Hover 改为 surface.hover；Pressed 改为 surface.pressed；Selected 用 selection.surface、selection.text 和选中标记；Focused 在当前状态外增加独立焦点环；Disabled 使用专属背景与标签；Loading 保留当前容器尺寸，用进度或工作状态替换部分内容。主按钮悬停时使用 accent.hover，按下时使用 accent.pressed；背景改变时文字继续使用 onAccent。异步失败采用 danger.surface 与明确的错误文字，同时保留用户原有内容。

**Mac 的状态关系。** Hover、键盘 Focus、Selection 与窗口活跃状态分别设计。选中行持续表达当前对象，焦点表达键盘下一步作用位置，Hover 提供指针反馈。系统表格和侧边栏采用平台选中/失焦外观，自定义内容采用选中表面与清楚标记；窗口失去活跃状态时，保留较低强调的当前选择。[SRC15]

**深色界面的层级。** 自定义深色内容按 canvas → surface → inset 逐渐提高明度，主要文字采用略柔和的近白。细长段落和大面积纯白区域减少过强刺激；蓝色和语义状态使用更亮而易读的前景版本。提升表面通过亮度和细边界表达；黑色重阴影在深色底上作用较弱。系统 Sheet、Popover 和窗口材质依平台层级自动适配。

**透明与混合。** 透明颜色需要与下方背景共同定义。固定的不透明文字色更容易保持视觉一致；系统材质上的文字优先使用适合该材质的语义前景。自定义 50% 的灰色在不同背景上会形成不同结果，因此辅助文字采用独立颜色 token。阴影、半透明边框和渐变必须标注它们位于哪一种表面之上。色彩叠加产生的最终颜色属于该场景的实际视觉值。

**材质选择。**〔官方〕Liquid Glass 主要用于导航与控件层，标准 Material 用于内容层结构；厚材质提供更强背景抑制，薄材质保留更多上下文。Mac 还存在窗口背后和窗口内部两种背景混合语义。[SRC17]〔本规范〕大段文字、密集数据、编辑器与长列表使用稳定背景；局部悬浮面板可采用标准材质；系统工具栏和导航保留平台玻璃；图片上方的少量操作采用可读性充分的控件材质。一个交界处由一个主要分离效果承担职责，背景、阴影、描边和模糊按层级选择组合。

| 表面内容 | 推荐呈现 | 前景处理 |
|---|---|---|
| 长正文、数据表、编辑器 | 不透明或高度稳定的语义背景 | primary / secondary text |
| 依附内容的说明面板 | regular / 较厚标准材质 | 对应的 vibrant label |
| 媒体上的少量操作 | 系统玻璃或适合媒体的衬底 | 高对比图标与短标签 |
| 滚动内容和固定控件交界 | 系统 Scroll Edge Effect | 控件前景维持平台语义 |
| 氛围图片背景 | 图像自身的模糊、暗化或渐变 | 给文字提供稳定阅读区 |
| Mac 侧栏和浮动检查器 | 按语义采用系统窗口/内容材质 | 跟随活跃窗口与选中状态 |

**Liquid Glass 的 Regular 与 Clear。**〔官方〕Regular 会调整背景亮度并抑制细节，适合一般导航、文字较多的控件与浮层；Clear 保留更多背景，只用于照片、视频等视觉丰富媒体上的悬浮操作。明亮媒体下的 Clear 配合局部暗化或其他稳定衬底，前景文字与符号保持清楚。[SRC17][SRC22]

| 材质角色 | 默认使用场景 | 前景与背景关系 |
|---|---|---|
| Liquid Glass Regular | 导航、普通悬浮控制、需要阅读文字的交互表面 | 材质自动协调背景亮度，使用语义前景 |
| Liquid Glass Clear | 照片或视频上的少量短标签与操作 | 背景内容保持突出，必要时加局部暗化 |
| 标准 Material | 内容层里的说明与结构性面板 | 按阅读量选择厚度，文字采用适配材质的前景 |
| 稳定不透明表面 | 长正文、数据、编辑区以及减少透明度模式 | 使用确定的表面色与成对文字色 |

**系统外观偏好的视觉响应。**〔官方〕Reduce Transparency 开启时，界面背景采用不透明呈现。[SRC21]〔本规范〕自定义半透明面板切换为对应的稳定 surface 色，保留圆角、边界、内容位置与层级。Increase Contrast 开启时，重要边界、输入轮廓、选中标记和文字层级更清楚：装饰性细线可继续轻量，承担识别职责的轮廓提高明度差与可见程度。选中态边界使用 accent 或持续的选中标记，焦点环保持独立位置。浅色和深色外观都沿用同一语义关系。[SRC18]

**高斯模糊与渐进模糊。** 高斯模糊控制图像或内容的失焦程度，渐进模糊让模糊程度沿空间方向变化。系统导航与滚动内容的交界采用系统边缘效果；照片说明区可自定义渐进衬底。自定义媒体的模糊半径按所需识别程度选择：保留轮廓时从 4–8pt 观察，氛围背景可从 12–24pt 开始；处理范围由文字块高度、背景细节和图片构图决定。文字和操作层保持清晰，模糊主要作用于其背后内容。普通表单和内容分组通过留白、表面与边界即可获得层级。

**色彩关系的完整职责。** 产品配色先定义中性色的温度，再选择一个主强调色，随后定义成功、警告、错误等独立状态。冷灰与蓝色可以形成安静的工具类界面；偏暖的中性色可以用于阅读、创作或生活内容，文字与表面仍保留足够明度差。使用品牌高饱和色时，把它集中到当前操作与核心识别区域。多个颜色同时出现的页面，先让文字层级和布局清楚，再使用颜色补充类别。形状、位置、文字和色彩共同建立状态，颜色在这些线索里保持一致含义。

一组浅深色 token 拥有相同语义，颜色本身随外观重新配比。浅色的蓝色按钮可用白字，深色的浅蓝按钮可用深字；成功浅底在深色里变为低明度绿底，成功文字变为明亮绿。每个前景与它的表面成对定义。把「文字色」「边框色」「背景色」拆成不同用途，浅色状态标签的文字可以很深，底色只承担轻量分组。一个强调色应用于大型图表区域时可采用更柔和的面积色，数值和标签继续使用阅读色。

**自定义组件的表面配方。**以下为项目建议，系统控件保留系统形态；所有数值按组件角色统一应用。

| 自定义组件 | 表面与边界 | 文字与图形 | 几何起点 |
|---|---|---|---|
| 普通信息卡 | surface；按需轻分隔；平面 | primary 标题，secondary 说明 | 圆角 12、内边距 16 |
| 可选项目卡 | normal 同信息卡；selected 用 selection.surface 与标记 | selected 用 selection.text；说明保持可读 | 轮廓厚度占位稳定；选中标记有独立槽位 |
| 内嵌参数区 | inset；由组标题与留白限定 | 常规字段值与辅助标签 | 输入背景圆角 8，便于密集排布 |
| 自定义输入区域 | surface；outline.control 表示编辑边界 | 输入 primary；帮助 secondary | 边界不随文字变化；focus 环置于外层 |
| 中性次操作 | inset 或透明表面；hover / pressed 独立 | primary 或 accent 短标签 | 按钮内图文间距默认 6 |
| 实色主操作 | accent；按下 accent.pressed | onAccent | 主按钮高 36、圆角 8；内容与状态替换保持几何稳定 |
| 状态标签 | 对应 status.surface | 对应 status.foreground 与短状态词 | 文字默认 11pt、圆角 4；左右留白略大于上下 |
| 局部提示面板 | surface 或 regular material；浮层级阴影 | primary 标题、secondary 解释 | 圆角随平台；文本较长时采用稳定不透明底 |
| 可拖动预览 | surface；拖动级阴影 | 主体内容保留 | 原对象位置与预览角色清楚，阴影表达离开平面 |

**状态叠加的视觉优先级。** Selected 与 Hover 可以同时存在：选中语义保持，悬停使用 selection.hover 底色或显示辅助动作；Focused 与 Selected 可以同时存在：选中底色表达当前对象，外圈表达键盘所在位置；Pressed 为短暂反馈，容器尺寸与文字位置稳定。Disabled 减弱对比与操作强调，原有内容仍有清楚名称。Loading 保留标签或结果目标，进度符号占用固定位置；长任务同时呈现可读的进度说明。错误字段的边框、错误文字和图标形成同一状态组，焦点环继续保留自己的蓝色或平台色，以表达输入位置。

| 组合状态 | 背景 | 轮廓 / 标记 | 前景 |
|---|---|---|---|
| Normal | surface | 按组件需要使用 control / decorative | primary、secondary |
| Hover | surface.hover | 原边界或轻高亮 | 保持文字层级 |
| Pressed | surface.pressed | 原边界 | primary；实色主操作用 onAccent |
| Selected | selection.surface | 选中符号或侧边标记 | selection.text 与可读说明 |
| Selected + Hover | selection.hover | 保留选中标记 | 选中前景 |
| Selected + Pressed | selection.pressed | 保留选中标记 | 选中前景 |
| Focused | 当前状态背景 | 独立 focus.ring | 当前状态前景 |
| Error + Focused | surface / danger.surface | 错误线索与焦点环各占其位置 | 字段值 primary，错误说明 danger |
| Inactive window selection | 系统非活跃选中，或中性选中底 | 保留对象选中关系 | 合适的中性前景 |

**中性阴影的三档起点。** 阴影用于表达相对高度和临时关系。轻悬浮使用 y=2pt、blur=8pt、黑色约 8%–10%；Popover 或自定义浮层使用 y=8pt、blur=24pt、约 12%–16%；拖动预览使用 y=12pt、blur=32pt、约 16%–20%。必要时加一层 y=1pt、blur=2pt、约 4%–6% 的接触阴影，使近边界更清楚。每种组件采用固定层级，整页常驻卡片以背景、间距和轻边界表达分组。深色表面采用更亮的表面与克制的边线表达层次，阴影只补充悬浮关系。这里的 blur 为设计工具中的阴影模糊参数，按最终使用的渲染模型保持视觉一致。

阴影颜色以接近中性的深色为主，饱和色阴影只用于明确的品牌或发光对象。阴影随物体移动，光源方向在同一界面保持一致。阴影范围与真实点击范围分开，浮层离容器边缘留足可见空间。物体贴近背景时阴影短而紧，离开平面时更松、更扩散；拖动中的对象可以轻微放大并改变阴影，使拾起关系清楚。Mac 弹出窗口和系统 Popover 直接使用系统阴影，自定义绘制集中于内容里的特殊对象。

**渐变的四种用途。** 渐变用于品牌氛围、图像文字衬底、表面光照和连续数据值，各自拥有不同范围。品牌背景从同色相附近的两到三个色点开始，低饱和区域承载文字；图像衬底沿内容所在方向逐渐增加遮盖；表面光照使用细微明度差表现体积；连续数据渐变保证数值增加时明度关系持续变化。一个普通设置页面优先使用稳定纯色表面，品牌渐变可以留在少量封面、头图或大型摘要区域。

品牌蓝色背景的示例可用 135° 方向、0% 位置 #285AD9、100% 位置 #4A73DF；前景按渐变最浅位置选择。大面积渐变可在 50% 增加中间色，保持颜色过渡平滑。高饱和色跨越互补色时，先增加中间节点或缩小色相跨度，保持中央区域干净。浅色表面的明度变化可以只在相近的中性颜色之间形成，深色面板用轻微顶部亮度表达朝向。UI 的可点击性通过组件结构与状态表达，渐变只服务它所属的视觉角色。

**照片上的渐变衬底。** 照片标题放在底部时，以标题及说明实际高度推导衬底范围。一个约 80pt 高的文字组，可使用约 140–180pt 高的渐变区：顶部透明，经过中段逐渐增加暗色，底部达到足以支撑文字的遮盖强度。多行说明改为稳定半透明深色面板或不透明内容区，避免每段文字都落在不同照片细节上。光线明亮的图片采用深色衬底与浅色文字，深色图片可以沿用同样策略并减轻遮盖。图像中的人脸、产品焦点和标题形成清楚的前后关系，关键主体保持完整。

**模糊、透明、磨砂与玻璃的构成。** 高斯模糊降低背景的高频细节；透明保留背景的颜色和形状；磨砂类表面通常组合模糊、颜色衬底与边界；玻璃材质还涉及高光、折射、明暗适应和动态响应。系统 Material 或 Liquid Glass 将这些视觉关系组织成可适应环境的整体。自定义照片背景只需要氛围失焦时，选择图像模糊；需要内容上方的可读面板时，选择语义材质或稳定表面；需要系统悬浮导航时，采用系统玻璃角色。

**渐进模糊的空间关系。** 渐进模糊以区域内的模糊强度变化建立自然过渡，范围由清晰区、过渡区和稳定衬底区组成。图片底部文字衬底可让顶部保留清晰图像，中段逐渐降低细节，文字背后的区域进入稳定模糊。仅改变均匀模糊层的透明度，会让清晰图与模糊图同时参与叠加；视觉上更接近透明交叉混合。需要连续失焦的表现时，为模糊程度定义连续空间变化。设计稿记录模糊方向、起止区域、最大强度和文字区衬底，而数字半径只是其中一项。

模糊区域的边缘与图像裁切范围保持连续。背景原图扩展到效果区域外再参与采样，可保持边缘色彩自然；文字、图标和操作留在清晰前景层。大范围模糊主要用于展示图片、封面和氛围背景，参数表、代码、长文章与列表提供清晰稳定表面。模糊强度变化和文字对比由各自的层共同负责，完整内容面板在浅深背景上维持一致的阅读层级。

**Mac 的内容与材质。** 侧栏、标题栏和工具栏与桌面及窗口环境形成空间关系，原生材质随窗口活跃状态自然调整；编辑画布、表格与阅读列使用稳定背景。浮动检查器采用其平台容器与系统材质；需要专业颜色判断的画布提供中性、稳定底色。浅深外观里，窗口结构和内容表面的职责保持一致。

**图片、图表和颜色信息。** 图片内容有自己的色彩空间，UI 的中性色尽量给图片留出展示空间；照片列表中标题与操作沿用语义前景，图片本身承担丰富颜色。分类图表给不同类别分配独立色组，相邻类别同时拥有名称或图例；连续数值用连续明度或连续色阶；正负变化使用相反方向和数值符号表达，再由色彩加强。状态绿与红表达完成和错误时，图表类别可选其他稳定颜色。颜色被用于筛选条件或标签时，旁边保留名称，圆点、形状或图案补足区别。

**颜色与动效的关系。** 按下和悬停的颜色变化以短暂平滑过渡呈现，触发后回到明确状态；持续选中拥有稳定背景和前景。加载时的明暗变化局限在进度对象，附近文字保持清晰；完成时可以把进度图形替换为完成符号，结果文字承担持续反馈。表面的渐变和高光跟随真实交互或系统材质变化，品牌展示的背景运动保持低强度。焦点环直接表达当前输入位置，颜色、透明度和尺寸的动画共同维持这个位置的可识别性。

## 07 · 非系统组件的完整视觉规格

以下组件延续Mac的13pt界面字体、32pt常规按钮、36pt主按钮和32pt标准行。每个组件均同时定义内容、几何、主次、状态与输入关系。系统有合适对应组件时采用其视觉行为，自定义部分聚焦产品独有的信息和操作。

**原生控件家族与自定义内容的衔接。** 用户熟悉的窗口、菜单、弹出选择、输入、开关和系统面板采用原生语义。业务对象、自定义可视化、命令面板和内容预览建立统一的产品几何。

| 用户任务 | 默认组件与呈现 | 设计关系 |
|---|---|---|
| 执行当前动作 | Button | 常规32pt、主动作36pt自定义尺寸；系统尺寸按系统 |
| 选择一个枚举值 | Pop-up Button/Picker | 持续显示当前选项 |
| 打开一组命令 | Pull-down/Menu | 入口名称表达动作集合 |
| 多个独立布尔项 | Checkbox | 标签可点击，父子关系用缩进 |
| 统领功能启停 | Switch | 当前状态明显，相关参数表达依赖 |
| 小量互斥选项 | Radio或分段控件 | 完整标签便于比较 |
| 绑定当前文档的短任务 | Sheet | 附着对应窗口，保留文档语境 |
| 需要对照内容的编辑 | Inspector/非模态Panel | 同时操作或查看当前内容 |
| 锚定一个控件的临时参数 | Popover | 保持触发来源，关闭后恢复焦点 |
| 重要的即时决策 | 系统Alert | 对象、后果和具体动作名 |
| 打开与保存文件 | 系统Open/Save Panel | 文件类型、扩展名、目标位置清楚 |

**按钮族。** 常规自定义按钮高32pt、主按钮36pt；13pt Medium，强动作Semibold；左右12pt，图文间6pt；图标16pt。输入与按钮默认8pt圆角，主要动作的宽度按标签与最宽加载状态计算。图标按钮采用28pt操作槽，槽内16pt符号；Hover、按下和焦点均保持布局。长标签优先增宽，再调整相邻布局；单窗口中主要动作保持在任务完成路径附近。

**菜单栏与命令分布。** 应用菜单容纳关于、设置与退出；文件管理创建、打开、关闭、保存与导出；编辑容纳撤销、剪贴板和选择；显示容纳侧栏、检查器、缩放与显示方式；窗口管理窗口，帮助提供使用资料。具体菜单随应用任务精简。工具栏与对象菜单包含常用命令，完整菜单索引让键盘用户持续找到它们。菜单结构、快捷键与是否可用的状态同步。[R01]

**菜单的视觉细则。** 同一组内的图标风格一致；图标优先用于有清楚视觉含义的动作。组间用分隔线表达用途。执行前还需输入或选择时使用省略号，例如“导出…”；“显示检查器”这类直接切换界面的动作保持直接名称。某个命令当前不可用时保留可识别标签和系统禁用态。右键菜单贴近当前对象，选项顺序和主菜单语义相同。[R01]

**Sheet、Panel和Alert的几何。** 自定义Sheet示例宽480–560pt、内边距24pt；简短文本、字段和底部动作按垂直顺序排列。正文13/18–20pt，字段32pt，组间20–24pt；内容高度随文本增长。与当前文档绑定的Sheet保持窗口关联，独立工具Panel可与内容并行。系统Alert保留系统布局，文字集中描述当前决定；常规可撤销动作在内容区呈现结果。[R02]

**连续值与精确值的组合。** Slider用于连续调节，旁边可以提供数值输入或Stepper以精确定位。当前值与单位常显，最小值、最大值、步进和重置入口属于同一参数组。拖动时预览原位更新，结束后保留结果；手输错误在字段附近提示，原输入保留。日期时间采用系统日期选择样式与地区格式。[R07][R08]

**组件一：对象摘要行**

适合项目、文件、笔记、任务或对话记录。单行用于快速比较，双行用于需要描述和时间的内容。把“名称、属性、状态、动作”分为固定角色。

| 部位 | 标准单行 | 双行摘要 |
|---|---|---|
| 行高 | 32pt | 52pt |
| 内容内边距 | 左右12pt、上下8pt | 左右12pt、上下10pt |
| 图标/缩略图 | 16pt图标，20pt槽 | 32pt缩略图或24pt符号 |
| 图像至文字 | 8pt | 12pt |
| 名称 | 13/16pt Regular | 13/16pt Medium |
| 次要说明 | 右侧11/14pt | 下方11/14pt，与名称间2pt |
| 右侧操作 | 28pt命中区 | 28pt命中区，垂直居中 |
| 选择表面 | 系统选中语义色 | 系统选中语义色 |

双行计算为10＋16＋2＋14＋10 = 52pt。名称右侧空间紧张时，时间移到副行尾端；描述长度增加时先截断摘要并保留完整详情。当前对象的关键名称允许两行，行高随真实文字增加。

默认态平静；Hover用低对比背景且保持几何；Pressed短暂加强背景；Selected显示持续选择；失焦后保留次一级选中表面；菜单打开期间维持目标对象识别。加载时以相同文字槽和缩略图槽保留布局；失败时用短状态文字加重试动作。

**选择、打开与操作的空间关系**

列表点击选择对象，右侧显示详情；双击可打开独立窗口或进入主要编辑，遵守当前对象类型的习惯。行内按钮只占自己的点击区，整行选择区域避开它。每行保留最多1–2个高频动作，其他动作放对象菜单。批量操作出现在列表上方的稳定工具区，显示选中数量和清除选择入口。删除行后选择相邻对象或回到清晰空态；详情与列表选择始终对应。

**组件二：高密度数据表**

适合用户跨记录比较数值、状态和时间。表头高度32pt，文字11–12pt Medium；数据默认13pt Regular。普通行32pt，紧凑28pt，舒适40pt。数字精度、千位分隔、单位写法、空值规则统一；单位可归入表头，单元格只显示值。文本名称Leading，数字Trailing，状态按列固定对齐。

| 状态/行为 | 视觉规格 |
|---|---|
| 当前排序 | 表头显示方向符号，列名保持稳定位置 |
| Hover行 | 轻底色横向连贯，支持眼睛追踪整行 |
| 已选中行 | 覆盖整行的数据区域，图标文字同步使用选中前景色 |
| 失焦选中 | 使用非活动选择背景，保留所选记录 |
| 单元格编辑 | 选中格内出现输入边界与焦点，临近记录仍可见 |
| 字段错误 | 单元格错误边界＋邻近短提示，保留用户输入 |
| 批量操作 | 表格上方显示选中数与可用动作 |
| 数据刷新 | 保留排序、列宽、选择与滚动位置；受影响值局部更新 |
| 无结果 | 表头与筛选条保留，内容区显示清除筛选入口 |

名称列最小140–180pt；日期列建议132–160pt；状态列80–104pt；数值列按最长格式留宽。金额“¥123,456.78”用最长样例推导列宽。横向空间不足时先保留用户钉住的列与当前比较所需列，低频列通过列设置收起或找回；当前排序与筛选依据保持可识别；高价值比较列允许横向滚动。深编辑使用右侧检查器或独立窗口，保持表格可参照。[MAC05][MAC06]

**组件三：搜索、范围与筛选条**

一个搜索框清楚表达一个范围。全局搜索靠工具栏尾随；当前集合搜索放列表顶部；侧边栏搜索处理侧栏内容。搜索字段32pt高，正文13/16pt；左侧图标14pt、图标槽20pt；左右padding10pt；清除按钮命中28pt。推荐初始宽220–280pt，可随可用空间增长。

筛选Chip高度28pt，左右10pt，文字12/15pt；多选状态通过文字、勾选或选中底色表达。筛选名称包含当前值，如“状态：进行中”。一个可见筛选条优先3–4项，其余用“筛选”进入完整面板。超出宽度时换行，避免把单行控件压成不同高度。

焦点状态显示系统环；输入态显示清除；建议列表与字段同轴；范围更换保留合理的查询词；查询中在结果区显示轻量进度，搜索框继续可编辑；无结果包含查询词、当前范围与清除筛选。关闭搜索回到原对象位置。搜索使用单独“查找文档内容”条时，结果数量、上一个/下一个和关闭共享一条紧凑水平线。[MAC07]

**组件四：属性字段与复合数值输入**

字段拥有持续标签，文本输入32pt高、左右10pt内边距，文字13pt。说明文字11–12pt，距离字段4–6pt；错误提示占同一说明区域或自然扩展高度。左标签右输入用于短标签、稳定表单；长标签或260pt窄面板使用上标签下输入。

| 属性类型 | 首选表达 | 视觉细节 |
|---|---|---|
| 普通文本 | 输入框 | 标签独立存在，placeholder展示示例 |
| 枚举项 | 选择器 | 显示当前值；箭头留独立尾部空间 |
| 精确数值 | 数字字段＋步进 | 数值右对齐；单位固定；范围写在邻近说明 |
| 布尔属性 | Checkbox | 文本紧邻框，整行标签可触发 |
| 统领一组功能 | Switch | 主状态视觉较明显，子项缩进表达依赖 |
| 多对象不同值 | 混合状态 | 显示“混合”或系统中间态 |
| 宽高联动 | 两个数值框＋连接控制 | 两框各106pt，中间28pt按钮，两侧各8pt间距 |
| 颜色选择 | 色样＋名称/数值 | 色样外有可见边界，透明显示棋盘底 |

输入态焦点保持；错误出现时用户已输内容保留；只读值表现为可选择文本或明确的只读字段；禁用属性仍展示值和依赖来源。恢复默认作为字段或分组的次要动作，与主值保持12pt左右距离。用户调整一个属性时，其关联的预览同步更新。[MAC08]

**组件五：命令选择面板**

适合跨功能快速查找与执行动作。窗口内居中的辅助面板初始宽560pt，可缩至440pt；左右16pt，上下12pt；搜索区域40pt高；结果行36pt；每行14–16pt图标槽、13pt名称、11pt快捷键。顶部搜索与结果之间8pt，分组标题11pt、前后8pt。

命令列表按“名称—作用对象—快捷键”排列。当前项采用明确选中表面；↑↓切换、Return执行、Esc关闭；搜索和键盘选择保持同一焦点路径。危险命令文字清楚，执行前进入恰当的确认；命令需要其他参数时显示后续步骤或弹出对象相关Sheet。列表空态给出能识别的命令例子，避免占满大段说明。面板存在时原工作区仍可辨识，结束后恢复原焦点。

项目使用⌘K等快捷键时先检查产品已有键位语义，系统菜单栏也提供对应入口。面板作为效率入口，常用主操作仍在原来的工作位置。

**组件六：附件、导入与上传队列**

附件行默认56pt：32pt预览槽、名称13pt、副信息11pt；左右12pt，图文间12pt。名称与文件类型/大小分行，状态信息靠尾部；进度条放在文字组下方或状态区，不覆盖文件名。多个附件保持统一行结构；图片预览保持相同比例，文档图标光学居中。

| 阶段 | 内容 | 操作 |
|---|---|---|
| 可接收文件 | 短用途说明、支持格式与容量 | 选择文件；拖入 |
| 拖入合法文件 | 容器边界与插入点突出 | 松手导入 |
| 拖入不支持文件 | 原因就地显示 | 离开目标即恢复 |
| 排队 | 文件名、等待状态 | 取消 |
| 传输 | 真实进度或明确阶段 | 取消 |
| 完成 | 缩略图、大小或结果 | 打开、移除 |
| 失败 | 具体原因 | 重试、更换文件 |

拖拽目标有原位置提示，多个文件展示数量；取消和移除动作位于独立28pt区域；成功后行高保持。文件名较长时保留可识别的首尾，完整名称可查看和复制。持久化错误与结果留在队列中，短暂提示只作补充。[MAC09]

**组件七：进度、状态和轻量反馈**

状态标签先以文字表达，再按含义加小符号。10–11pt状态字适合稀疏元信息；直接影响操作决策的状态使用12–13pt。视觉重量分为普通文字、文字＋符号、低饱和底色三个等级，整页同类状态统一。

普通状态标签高20–24pt、水平padding6–8pt，圆角4–6pt；它属于信息标记。可点击状态筛选采用28pt以上命中区，外观呈现可交互边界。状态由“处理中”转为“完成”时保留所在位置与宽度，避免整行水平抖动。

确定型进度展示进度量或阶段，未知型展示正在执行的任务。长任务有可用的取消/暂停；成功结果在对象本身更新，失败结果带恢复动作。轻量浮动消息建议宽240–360pt、内边距12pt，最多一个相关动作。需用户决策的内容持续显示至处理完成；计时自动消失仅用于可从其他位置再次查看的次要信息。

**组件八：空状态、错误态和就地引导**

空状态位于当前内容区域的视觉中心偏上，保留导航与筛选。示意符号32–48pt、标题17/22pt Semibold、说明13/18–20pt，说明宽度约280–360pt。图形至标题12pt、标题至说明8pt、说明至主操作16pt。主按钮36pt高；第二动作使用32pt低强调按钮或文字动作。

初次空状态说明这个区域能保存什么，并提供创建入口；搜索空状态显示搜索词和范围，提供清除；权限状态说明当前任务所需访问，提供打开设置；加载失败说明受影响内容并提供重试。相同状态使用同一骨架，不将普通错误扩展成全窗口红色警告。长期未选择对象时，用“选择一项查看详情”表达当前区域职责。

Tooltip与信息提示只补充陌生术语、数据用途和次级说明。用户提交前要知道的规则放在字段附近，说明最多先展示1–2句，再提供完整帮助入口。[MAC10]

**组件九：图表与指标概览**

指标数字采用22/26pt或26/32pt，标签11–12pt、单位12–13pt，变化值11–12pt。并列指标共享数字基线与标签起点；每个指标有固定职责，数量优先3–4个。变化方向与好坏分开表达，金额增长、故障数量增长使用不同语义。

趋势图优先让数据线/柱成为主体；网格线低对比，轴标签10–11pt。图例颜色在整页固定，筛选变化后系列颜色保持稳定。Hover读数沿数据点定位，显示时间、数值和单位；键盘与触摸支持相应取值。表格可作为精确数据视图，空数据和加载状态保留图表尺寸。内容概览使用一条连续的指标带或轻分区，独立圆角表面只用于可单独交互的分析模块。

**数据可视化的细部。** 趋势使用折线，类别比较使用条形，部分与整体使用清楚的比例关系，精确逐项比较使用表格。折线图的线宽默认2pt，选中点4–6pt；相邻系列除颜色外还可用线型与标签区分。柱形默认从零基线开始，曲线的范围与单位持续可见。面积填色只辅助识别趋势，选中读数有独立文字背景。坐标和网格服从数据层级，数据重点采用更强的对比。图例顺序、系列颜色和格式在筛选后保持，缺失值保留缺失语义，真实零值显示为零。[R03]

**数据与媒体的内容稳定性。** 占位保留最终图表、图像和摘要的尺寸；图片替换保持裁切焦点；精确数值使用等宽数字；加载前后单位、日期与精度一致。可持续刷新的数据在其原位置更新。局部失败用对应区域的错误状态承载，页面其余内容继续可用。

## 08 · 动效、焦点、指针与交互状态

**四类状态分开设计**

Hover表示指针当前所在；选择表示操作对象；键盘焦点表示输入接收位置；窗口活动状态表示当前工作窗口。这四类状态可叠加，设计稿至少展示“选中且焦点在列表”“选中但焦点在检查器”“非活动窗口中仍有选择”三种工作情境。[MAC11][MAC12]

| 情境 | 行/对象背景 | 文字与图标 | 焦点表现 |
|---|---|---|---|
| 普通 | 基础内容表面 | 主要或次要语义文字色 | 无额外环 |
| 未选中Hover | 轻微Hover底色 | 保持可读，次级动作可出现 | 鼠标状态独立于键盘焦点 |
| 选中且列表活动 | 系统活动选中色 | 系统对应选中前景色 | 整行高亮 |
| 选中但焦点已移走 | 系统非活动选中表面 | 对应非活动前景色 | 检查器字段显示自己的焦点环 |
| 窗口非活动 | 保留对象的较弱选择表面 | 系统非活动颜色 | 输入焦点不与活动窗口竞争 |
| 文本输入 | 稳定字段底色 | 输入文字色 | 系统焦点环与插入光标 |
| 禁用 | 禁用控件表面 | 禁用语义色 | 按平台焦点策略处理 |
| 错误且正在输入 | 错误状态仍可识别 | 原输入保留 | 焦点可叠加错误边界，含邻近文字 |

自定义选择背景有对应的前景文字色。禁止把高亮颜色直接叠在原色文字上导致选中后难读；设计上改为明确的成对颜色角色。菜单打开、拖动开始或触摸揭示按钮时，原对象选择保持。

**状态如何占用空间**

状态变化优先发生在预留的背景、图标或文本槽内。Hover按钮出现时使用已预留28pt操作槽，正文宽度保持；“保存”转为“保存中”保留按钮宽度；错误信息出现在字段说明区或自然增加垂直空间；排序图标有预留槽，切换顺序时列名位置保持。折叠检查器时中央区域平滑扩展，选中对象保持可见。

**自定义动效的项目节奏**

系统组件使用系统动效。自定义反馈按事件的空间尺度分级，持续时间表达可感知的变化，交互始终接受后续操作。

| 事件 | 参考时长 | 变化属性 | 运动/节奏 | 减少动态效果时 |
|---|---:|---|---|---|
| 指针进入普通按钮 | 80–120ms | 填色、描边明度 | 快速平缓 | 直接切换或短淡变 |
| 按下与释放 | 100–160ms | 按压颜色或极小形变 | 进入快、释放自然 | 仅颜色 |
| 选中行变化 | 100–160ms | 行高亮 | 基本即时，短过渡 | 直接高亮 |
| 图标状态替换 | 140–200ms | 图形/透明度 | 连续替换 | 短交叉淡变 |
| 局部分组展开 | 160–220ms | 区域高度与内容透明度 | 轻缓结束 | 展开后直接显示 |
| Inspector出现 | 180–240ms | 栏位宽度、内容位置 | 一次空间过渡 | 直接布局或短淡变 |
| 列表重排 | 180–260ms | 行位置 | 跟随目标落点 | 直接移动并维持选择 |
| 图表切换范围 | 180–280ms | 对应数据路径 | 同类数据连续变化 | 直接显示新数据 |
| 自定义浮层出现 | 140–220ms | 透明度、极小位移 | 锚定来源 | 只淡变 |

Apple动效原则支持简短、精确、可打断，并按输入方式降低间接指针交互的反馈幅度。[MAC13] 密集工具中的重复操作采用轻变化；空间层级切换才使用更明显位移。滚动使用系统惯性与弹性，手势拖动内容直接跟随位置，不叠加独立的延迟。

**Hover与鼠标光标**

普通按钮与列表沿用系统箭头；文本内容用I-beam；可拖动画布用Open/Closed Hand；分割线用横向调整光标；缩放工具用对应放大/缩小符号。指针形态只在真实可执行操作的区域变化。Hover在列表用底色，在画布对象用轮廓，在缩放/拖动工具用形态反馈；表格行保持原尺寸。

Hover出现的必要操作，在键盘焦点、对象菜单或可见工具栏中有对应入口。Tooltip响应焦点并贴近目标，文字简短，展示功能名称或快捷键；长帮助展开到明确的帮助区域。[MAC14][MAC10]

**键盘路径**

焦点按“导航→列表→详情→检查器”及区域内阅读顺序移动，具体是否遍历全部控件遵循系统完整键盘访问设置。列表方向键移动选择；输入框保留文字编辑键位；Esc退出当前临时模式，之后回到原焦点。对话框默认动作使用系统表现，破坏性操作有明确标签。⌘F用于当前语境查找，⌘,打开设置，⌘W关闭当前窗口，⌘Q退出应用；自定义快捷键显示在菜单栏命令旁。

空对象、过滤后消失的条目或被删除对象使用一致的后续选择规则：优先保留同一列表邻近项；当前编辑发生冲突时保留输入并展示可处理的状态。用户在一个字段输入时，后台更新只更新相关数据和状态，焦点仍在原字段。

**拖拽过程的五个视觉阶段**

准备阶段显示可拖动对象/把手；拿起阶段以缩略预览或对象轮廓跟随指针；悬停目标阶段显示合法容器或插入线；释放阶段对象移动至目标位置；完成后保留结果与撤销入口。非法目标有不可用反馈，松手后回到来源。多选拖动展示数量及代表性预览；长列表在拖动靠近上下边缘时自动滚动。[MAC09]

**窗口与选择的持续关系。** 文档是主要操作对象，浮动Panel取得键盘输入时，主文档仍可作为命令的作用对象；Main窗口与Key窗口的状态分别遵循系统。文档型应用可采用系统文档Tab；窗口重开恢复合适的位置、尺寸与内容，跨显示器变化后保留可见操作区。列表中⌘逐项增减选择，⇧扩展连续范围，⌘A作用于当前焦点区域。拖放预览显示移动或复制语义，修饰键遵循对象类型和系统习惯；Finder拖入与菜单导入进入相同内容流程。[MAC09][MAC11][MAC12]

**条件：支持直接触摸的Mac**

当前Apple指导保留键盘与指针使用时的基础布局，通过扩大不可见命中区及临时扩展小控件适配触摸。隐藏控制在触摸相应区域后出现，再次触摸执行；揭示操作保留原选择。Slider、Stepper等密集控制可在触摸时显示更大的暂时版本。触摸结束后按系统节奏回归基础状态；布局密度持续保持一致。[MAC15]

**多层状态与材质**

内容背景、选中行、键盘焦点和浮动材质各有清楚角色。普通选中行使用选择表面，主要浮动交互使用Liquid Glass。带自由文字标题的窗口可采用系统automatic滚动边缘；macOS27会在此情境使用更明确的hard效果。相邻玻璃控件作为同一逻辑组处理，整体反馈一致。[MAC16][MAC17]

检查器标题13pt Semibold，分区之间24pt。备注使用多行输入，高度随内容或限定可滚动区域。主工作区数据刷新时只更新对应值，列表选择和检查器焦点保留。窗口低于1022pt时收起检查器，尾部保留打开按钮；必要编辑可在独立对象窗口继续。

**配方四：创作编辑器与资源面板**

内容宽1440pt：资源栏240＋1＋画布910＋1＋检查器288。资源栏可切换文件/图层，检查器可切换对象属性/样式，画布成为视觉主体。工具栏使用三个清楚组：文档与导航、编辑工具、分享与辅助视图。

资源行32pt，树形缩进16pt；对象缩略图20–24pt，图层名13pt。可见性、锁定等次级控制在预留命中槽内，Hover、焦点或选择时可见。画布可缩放，背景使用安静的中性表面；当前对象显示选择框和操作柄，属性值与检查器同步。

画布边缘的浮动工具采用统一大小和材质，内部按钮32pt；连续工具间距4–8pt，逻辑组之间12pt。只有真正悬浮于画布上方的工具使用玻璃/浮层效果。缩小窗口先收起检查器，再收起资源栏；画布位置与缩放中心保持。坐标、缩放率、页数等放轻量状态区，并在菜单中提供相同操作。

**配方五：设置窗口与参数组**

初始内容宽760pt：分类栏200＋分割1＋内容559。右侧内容左右24pt后511pt。短字段双列为标签136＋间隔16＋输入359 = 511pt；输入可在分组内保持统一最大宽度，未占满的空间用于自然留白。

分类行32pt、文字13pt；内容标题17/22pt。标题至第一组20pt；分区间24pt；字段行32pt，相关字段之间8pt。字段说明11–12pt，位于控件下方并与控件文字轴对齐。复杂分组可用一层轻背景或分割线；有依赖关系的选项缩进16pt。

“同步全部文件”等主状态可使用Switch，子选项采用Checkbox；同一组保持同一种尺度。长说明用上下结构：标签13pt、输入32pt、说明12pt；一个设置的含义、结果及错误保持邻近。修改即时生效时持续展示状态，确需应用时提供清楚的32/36pt动作。⌘,打开，窗口标题与分类相符，重新打开恢复上次分类。[MAC18]

**配方六：单任务工具与菜单栏扩展**

单任务窗口初始内容宽640pt，左右24pt后内部592pt。顶部任务标题22/26pt，说明13/20pt；标题至说明8pt，说明至输入24pt。输入内容区域高度依实际内容，常规单行32pt、多行至少96pt；参数组之间20pt；主操作36pt高，居于输入完成路径末端。结果区与输入区相隔24pt，提供复制、保存或打开结果的明确动作。

参数少时纵向单列，结果丰富时允许与输入并排。耗时操作保留主按钮位置并展示进度，结果完成后原内容区自然更新。应用最小宽度以最长标签与输入最低宽度决定，窗口可以按工作需求调整。

菜单栏扩展建议宽320pt、左右16pt、内部288pt。核心状态数字22/26pt、说明12/16pt；主要动作36pt、次要行32pt；分区16–20pt。菜单栏只承载快速状态与少量动作，完整历史、复杂编辑和多步骤任务进入独立窗口。Popover由系统锚定并处理关闭，原窗口内容保持。

**这些配方的共同视觉规则**

每个工作区使用一种主密度，标题、表格、面板共享字体角色。主要阅读轴稳定，操作控制在其作用区域附近。内容密集时通过固定列线、语义颜色和选择状态保持秩序；内容较少时让主体居于适宜阅读宽度，留白来自布局关系。自定义内容表面的曲率与层级相符，系统窗口与导航材质保持平台外观。

**macOS原生与桌面网页、iOS的设计关系**

| 设计问题 | macOS原生 | 桌面网页 / iOS的常见方式 |
|---|---|---|
| 空间组织 | 可调整窗口、分栏、检查器、独立文档 | 网页以浏览器页面为主要容器；iOS常用逐层导航 |
| 完整命令 | 系统菜单栏＋快捷键 | 网页由站内菜单提供；iOS集中Toolbar与菜单 |
| 常规字体 | 13pt界面正文，阅读区另配 | 网页常用自身字体尺度；iOS Body17pt |
| 输入方式 | 指针、键盘与适用设备上的触摸 | 网页受浏览器行为影响；iOS以直接触摸为主 |
| 对象选择 | 单选、多选、范围选择、键盘焦点 | iOS常进入选择模式；网页自行组织交互 |
| 辅助编辑 | Inspector/Panel与内容并列 | iOS常用Sheet或下一层；网页可用侧面板 |
| 关闭与退出 | 关闭窗口和退出应用分别存在 | 浏览器标签与页面生命周期；iOS返回/关闭呈现 |
| 状态保持 | 窗口位置、面板、列宽、当前对象 | 网页路由与浏览器恢复；iOS导航和内容恢复 |
| 视觉层级 | 内容面、栏位与选中态形成桌面秩序 | 各平台采用各自控件密度和导航样式 |

**窗口行为的视觉责任。** 多文档窗口具有可识别的对象名，打开新窗口与在当前窗口切换内容保持一致语义。窗口可以调整、全屏、并排工作；最小内容宽度来自主要任务的最低可用空间。关闭当前窗口保留应用的系统行为，后台任务与草稿通过清楚状态表达。长时任务的进度关联具体对象或任务区，用户在其他窗口工作时仍可返回查看。
