# iOS 原生 App 视觉与交互设计规范

**深度研究版｜2026 年 10 月 28 日**  
**适用范围：iPhone 优先；适用于以 SwiftUI、UIKit 构建的工具、效率、社交、内容与生活类原生应用；对 iPad 和移动网页差异另有说明。**  
**研究基准：Apple Human Interface Guidelines（HIG）、WWDC 2025–2026、iOS 27 设计资源；辅以 Nielsen Norman Group、Baymard Institute 等第三方研究。**

> **标注说明**：**【系统】** = Apple 已明确说明的原则、行为或数值；**【推荐】** = 本规范基于原生设计惯例和第三方研究确立的统一设计值；**【条件】** = 仅对特定业务、组件和屏幕状态适用。规范中的尺寸均使用 iOS **pt**（点）。

**设计方向：** 以内容为主、层级明确、交互自然、界面克制。系统组件优先，留白优先于装饰边框，文本与对齐优先于过度使用卡片；使用 Liquid Glass 表达控件与导航层，使用标准背景或系统 Material 承载内容层。原生感首先来自正确的导航、滚动、反馈和系统适配。[A01][A02][A14]

## 1. 界面结构、信息层级与页面职责

### 1.1 设计的优先顺序

1. **任务与信息**：用户进入页面后，应迅速看到当前最重要的内容或操作。
2. **空间与层级**：用位置、对齐、尺寸、留白、字重表达重要程度；背景、描边和阴影作为辅助。
3. **系统行为**：遵从 iOS 的返回、滚动、拖动、弹层、键盘、选择、分享及状态反馈。
4. **品牌与精致感**：将品牌色、字体、图标、微动画集中在有辨识价值的区域。

【系统】Apple 的布局文档强调：相关内容应当分组，必要的信息要有足够空间，控件与内容形成可辨识的两个层级；当内容延伸到浮动导航下方时，用滚动边缘过渡维持可读性。[A02][A14]

### 1.2 页面类型与应有结构

| 页面类型 | 适合承载的内容 | 标题 | 内容形态 | 典型主要操作 |
| --- | --- | --- | --- | --- |
| 一级入口页 | 产品核心区域，如“记录、发现、消息、我的” | 大标题或清晰的紧凑标题 | 列表、概览、内容流 | 新建、搜索、筛选 |
| 列表/集合页 | 可重复浏览的一类对象 | 明确页面名称；一级页面可用大标题 | `List`、分组列表、网格 | 新建、排序、筛选 |
| 详情页 | 单个对象的详细内容与相关操作 | 通常为短标题；必要时可省略 | 纵向分区、媒体、属性行 | 编辑、分享、收藏 |
| 创建/编辑页 | 输入或修改一个对象 | 以对象/操作命名 | 表单、编辑画布 | 完成、保存、取消 |
| 临时任务页 | 选择范围、过滤、添加附件 | 简短标题或任务名称 | Sheet、系统选择器 | 选择、应用、完成 |
| 设置页 | 偏好、账户、通知、隐私 | “设置”或当前设置类目 | `Form` / grouped `List` | 开关、选择、进入子项 |
| 沉浸阅读页 | 文章、照片、视频、地图 | 通常用紧凑或可隐藏标题 | 全屏内容/阅读区 | 分享、标注、播放 |
| 空内容页 | 初始使用、无结果、无权限 | 传达当前状态 | 短说明 + 单一引导动作 | 创建、重新搜索、授权 |

**【推荐】单屏强调一个主任务。** 一级页面可以展示多个功能入口，但应有一个显著的阅读起点；编辑页明确“完成/保存”；详情页主要操作与当前对象相关。主操作、辅助操作、危险操作在位置和视觉重量上区分开。

### 1.3 页面层级与视觉优先级

- **第 0 层：全局结构**。Tab Bar / 侧边栏定义“我在哪个区域”；全局搜索或全局账户入口只保留清楚的固定位置。
- **第 1 层：当前页面**。页面标题、主要内容或搜索范围；操作栏用于“对当前页面做什么”。
- **第 2 层：内容分区**。分区标题、项目列表、筛选、图文对象；独立分区之间使用明显大于组内的间距。
- **第 3 层：局部信息**。正文、数值、时间、状态、辅助说明；以字体/颜色降低视觉权重，不把每个元信息做成彩色胶囊。
- **临时层：Sheet、Menu、Alert、Popover**。进入时应明确作用范围，结束后回到原上下文。

典型阅读顺序为**上→下、前缘 leading→后缘 trailing**；支持右向左书写的语言时顺序随系统变化。【系统】[A02]

### 1.4 主要内容与操作内容分层

在 iOS 26/27 的设计语言中，**内容层**呈现文字、照片、列表和可阅读对象；**控件层**承载系统导航、工具栏、Tab Bar 与浮动交互控件。控件层可以覆盖内容层，但内容须在靠近该边界时获得适当的淡出/模糊和避让。避免在同一视觉平面上叠放多个有透明背景的操作组。[A14][A15]

**【推荐】工具/效率类 App 的默认视觉风格：** 单一平静底色、系统分组列表、稳定的前缘对齐、少量强调色、低密度阴影。照片、视频、地图、可视化数据才值得使用更多全幅视觉与沉浸层次。

## 2. 尺寸系统、间距、留白、对齐与响应式布局

### 2.1 设计单位和屏幕边界

- **【系统】iOS 使用 pt** 进行界面设计，@2x/@3x 表示资源像素倍率。自定义组件的 16pt 间距在不同倍率设备上保持同样的逻辑尺寸。
- **【系统】遵守 Safe Area**：Dynamic Island、传感器区域、Home Indicator、系统导航与键盘都会影响安全范围。顶部/底部安全区高度以运行环境为准，**不统一写成固定数字**。[A02]
- **【系统】背景、摄影图和滚动内容可以延伸到边缘**，文字、主要按钮和输入控件优先对齐到安全区域内的内容边距。
- **【系统】避免固定 Navigation Bar、Tab Bar、状态栏的高度**。系统在滚动、动态字体、Liquid Glass 和尺寸变化时会调整表现。
- **【推荐】自定义常规页面左右边距为 16pt**，更具阅读感的页面可使用 20pt；分组 `List` / `Form` 优先采用系统 inset。横屏和宽屏根据内容宽度自动调整，而非把 16pt 直接同比放大。

### 2.2 全局间距等级

**【推荐】以 4pt 为基础节奏，实际使用离散间距，不在每个区域自创数字。Apple 没有要求所有 App 必须遵循 4pt 网格。**

| Token | 数值 | 最适合的关系 | 反例 / 注意 |
| --- | ---: | --- | --- |
| XXS | 2pt | 小型角标、紧密基线微调 | 不作为按钮间距 |
| XS | 4pt | 同一组小图标与短标注、状态值 | 不能承担分区分隔 |
| S | 8pt | 标题与说明、图标和标签、紧密控件 | 内容复杂时改为 12pt |
| M | 12pt | 列表行内部、输入控件与就地提示 | 大分区距离不够明显 |
| L | 16pt | 默认页面左右边距、卡片内边距 | 系统组件保留系统 inset |
| XL | 20pt | 舒适阅读边距、大对象内部 | 避免对窄屏过度压缩 |
| 2XL | 24pt | 普通不同模块之间 | 适合页面纵向分组 |
| 3XL | 32pt | 不同语义区域、标题区与正文区 | 不宜用于每一行之间 |
| 4XL | 40pt | 空状态文案上方、首屏大留白 | 应由布局关系决定 |
| 5XL | 48pt | 大型沉浸区和独立视觉区 | 应保留屏幕空间效率 |
| 6XL | 64pt | 极少数首屏主视觉/编辑画布间隔 | 工具页慎用 |

**实际组合推荐：**

- 一个图标与其文字：**8pt**；图标本身视觉大小约 **18–24pt**。
- 同一条内容的主标题与次要信息：**4–6pt**；信息行中不同组约 **12–16pt**。
- 分区标题至第一行内容：**8–12pt**；两个分区之间约 **24–32pt**。
- 卡片内边距：**12–16pt**；内容复杂的媒体/概览卡片 **20pt**。
- 分区底部到下一分区标题：优先 **24pt**，复杂内容可以 **32pt**。
- 相邻主次按钮纵向排列：**8–12pt**，应保持两者可独立点按。

这些数字用于**自定义容器与布局**；系统 `List`、`Form`、`NavigationStack`、`Toolbar` 的内边距遵守系统默认优先。[A02][A10]

### 2.3 尺寸与形状参考

| 元素 | 【推荐】视觉尺寸 / 间距 | 说明 |
| --- | --- | --- |
| iPhone 内容水平边距 | 16pt，舒适阅读可为 20pt | 与页面同侧内容共享起始线 |
| 点击区域 | **44×44pt 为默认目标【系统】** | Apple 无障碍表列 iOS 默认 44pt、特定场景最低 28pt；一般 UI 以 44pt 设计更稳妥 [A03] |
| 主要按钮 | 高 48–56pt | 一屏一个显著按钮，能随文字和动态字体增高 |
| 次要按钮 | 高 44–48pt | 系统文字按钮遵循自身内建区域 |
| 文本输入框 | 单行约 44–52pt | 多行输入自适应增长 |
| 紧凑单行列表 | 高约 44–52pt | 以系统行高与内容为准 |
| 常规图文列表 | 高约 52–64pt | 动态文字/双行信息自动增高 |
| 大型摘要列表 | 高约 72–96pt | 仅在图像、状态或说明确有需要时 |
| 图标视觉大小 | 18–24pt | 不等于可点击区域，配合 SF Symbols 字重 |
| 小型独立容器圆角 | 8–12pt | 标签、输入衬底、小预览 |
| 普通自定义卡片圆角 | 12–16pt | 有明确独立视觉身份时 |
| 大图 / 浮层圆角 | 16–24pt | 取决于媒介与容器尺度 |
| 列表分隔线 | 系统 `separator`，细线 | 无须固定为自定义灰色 |
| 表单说明与字段间距 | 4–8pt | 直接关联字段的提示 |
| 页面段落之间 | 12–20pt | 与系统字体行高协调 |

**【系统】圆角的具体数值随组件与系统风格变化。** 上表圆角只用于自定义表面，不覆盖系统 Button、Sheet、Search Field、Tab Bar 的自动形状。相邻嵌套容器应保持圆角同心、视觉上连续，而非重复使用完全相同的外圆角。[A22]

### 2.4 四条对齐规则

1. **文本以 leading 对齐**：页面标题、分区标题、列表主标题、表单标签和说明优先共享对齐轴。设置页内的右侧值、时间、计数器可以 trailing 对齐。
2. **列表建立隐形列线**：左侧图标/头像同列；标题与副标题同列；右侧箭头/开关/数值同列。图标行和纯文本行可采用不同内容起始位置，但分组内部需稳定。
3. **长文本避免居中**：长说明、正文、表单、错误消息以 leading 排列；居中适合空状态、成功反馈和一两句短文案。
4. **数字保持易比较**：金额、日期、计时等右侧数值对齐到同一末端，必要时用等宽数字；表格列对齐保证用户可以快速扫描。

避免在一行中同时塞下图标、两行标题、金额、状态、按钮和更多菜单。空间不足时让次要信息转到第二行，不要靠缩小到 11pt 硬塞。

### 2.5 留白的语义

**【推荐】留白本身属于结构信息。** 同组相关项距离应小于不同组距离。一个页面可用“12pt 组内间距 / 28pt 组间间距”产生足够层次；分割线只在有帮助时添加。

- **减法优先**：密集设置或功能入口优先 grouped list；不要把每个设置项包成独立的圆角卡片。
- **分区与标题**：有共同语义的一组控件用一个短标题与可选 Footer 说明，避免为每行都写解释。
- **容器的必要性**：内容需要独立触摸、预览、选择、拖动，或者具有明显的边界时才使用卡片。
- **上下滚动连贯**：长页使用连续内容流；避免多层高度固定的局部滚动区域争夺手势。
- **首屏视线焦点**：主要信息在安全区内优先出现；顶部大幅插画不应把核心操作挤到屏幕之外。

### 2.6 适配不同宽度与文本长度

- **窄屏**：图文并排优先让文本换行；两列操作必要时改为纵向堆叠；单个大按钮保持页面水平边距。
- **宽屏/横屏**：正文可以使用适宜的最大阅读宽度，列表/详情可以改为双栏。不要让正文横跨过宽的屏幕。
- **文字变大**：行高和卡片高度随内容增长；横向按钮可能改为竖向。动态字体不应以截断来维持固定盒子。
- **iOS 27 尺寸变化**：iPhone 镜像窗口和 iPhone App 在 iPad 上可以出现可调整窗口，布局依据实际可用宽度与 size class；原生 iPhone 底部 Tab 在宽屏时可以按产品选择适配 Sidebar。[A25]
- **本地化**：中文、英文、阿拉伯文及系统字号变化均影响布局；使用 leading/trailing 语义对齐，并为按钮标题预留扩展空间。

## 3. 字体、字号、字重、行高与标题规范

### 3.1 字体体系

**【系统】在 iOS 中优先使用系统语义字体和 Dynamic Type。** 拉丁字符使用 SF Pro 家族，中文由系统适配对应中文字体与回退机制；不建议为整个 App 强制安装或固定某一套中文字形。[A04]

- **SF Pro**：常规界面、标题、按钮、文字、列表。
- **SF Pro Rounded**：温和、亲和、轻松的产品可用于局部强调；不应把复杂办公表单统一改成圆体。
- **SF Mono / 等宽字体**：代码、日志、技术标识，或者强调字符精确排列的内容。
- **等宽数字**：金额、排行、计时、统计表；保持正文与数字的视觉一致性。
- **品牌字体**：封面、少量品牌标题、特殊创意模块可使用；一般控件和高频操作保留系统字体。

### 3.2 Apple 默认动态字号表

下表对应 iOS 默认内容大小类别 **Large** 下的语义类型。**数值作为视觉基准；真实界面随用户系统设置改变。**[A04]

| 系统文本样式 | 默认字号 | 系统默认行高约 | 默认视觉角色 | 建议使用位置 |
| --- | ---: | ---: | --- | --- |
| Large Title | 34pt | 41pt | 页面身份 | 一级页大标题 |
| Title 1 | 28pt | 34pt | 高优先级标题 | 独立页面主标题、重点模块 |
| Title 2 | 22pt | 28pt | 内容节标题 | 详细分区、空状态标题 |
| Title 3 | 20pt | 25pt | 局部标题 | 长详情模块小标题 |
| Headline | 17pt | 22pt | 强调正文，系统默认半粗 | 列表主信息、信息要点 |
| Body | **17pt** | 22pt | **普通正文基准** | 正文、列表、重要说明 |
| Callout | 16pt | 21pt | 小号主信息 | 简短说明、辅助文本 |
| Subheadline | 15pt | 20pt | 次级信息 | 列表副标题、摘要 |
| Footnote | 13pt | 18pt | 元数据 | 时间、来源、非关键状态 |
| Caption 1 | 12pt | 16pt | 细小标注 | 图表注释、可选辅助信息 |
| Caption 2 | 11pt | 13pt | 极小标注 | 极少量非关键标签 |

**【推荐】一张页面主要使用 3–4 个层级**：例如 34 / 17 / 15 / 13，或者 22 / 17 / 15 / 13。避免一页同时出现 34、28、24、22、20、18、17、15、14、13、12 等大量相近层级。

**尺寸取舍：**

- 用户要阅读或理解的正文：**17pt Body 优先**。
- 常规次级说明：**15–16pt**。
- 时间、来源、状态中的非核心元信息：**13pt**。
- 12pt、11pt 留给极少量辅助标记；对重要按钮、错误、帮助说明不采用极小字号。
- 页面内数字 KPI：根据视觉主次可采用 **22 / 28 / 34pt** 等 Title 级别，但数字标签仍用 13–16pt 形成层级。

### 3.3 字重怎么分配

| 字重 | 建议用途 | 使用频率 |
| --- | --- | --- |
| Regular（400） | 正文、普通列表、说明、输入值 | 最常用 |
| Medium（500） | 可点文本、短标签、次级重点 | 适量 |
| Semibold（600） | 关键列表标题、局部小标题、按钮、当前选中项 | 适量 |
| Bold（700） | 少量大标题、重要结果数字 | 节制 |
| Heavy 及以上 | 活动主视觉、营销或极强品牌图形 | 少量专用场景 |

**【推荐】优先通过字号和留白强调标题，字重作为第二层强调。** 过多 Semibold 会让整个页面像一片持续加粗的文字。对于层级清晰的常规正文，Regular 已经足够。

### 3.4 行高、字间距和中文排版

- 默认优先保留**系统语义字体附带的行高与字距**，正文参考 17/22pt 的节奏。
- 长段中文正文可以适度增加段落之间的空间，优先使用**段落间距**而不是人为大幅增加字间距。
- 标题与对应正文之间距离约 **8–12pt**；长内容段落之间约 **12–20pt**，章节之间 **24–32pt**。【推荐】
- 中英文混排与数字使用自然系统基线；表格数字需要可比性时使用等宽数字。
- 一般中文左对齐；避免长段文字两端强制拉伸产生不均匀空洞。
- 重要标题可换行，尤其中文对象名称；长文本中的中间省略号适合保留文件名首尾识别信息。
- 金额、账户标识、订单编号等关键可核验信息，不因视觉整齐而被不可逆截断；必要时提供展开、复制或详情。

### 3.5 标题到底要不要？

**【系统】Apple 的导航规范允许根据内容决定标题表现形式。** 标题的作用是帮助识别位置，不要求每个屏幕都重复显示大标题。[A09]

| 场景 | 建议标题 | 原因 |
| --- | --- | --- |
| 独立一级 Tab 页面 | 系统 Large Title 或明确 Inline Title | 快速识别一级区域 |
| 一级内容列表 | 常用 Large Title，可随滚动收起 | 适合列表入口 |
| 二级详情页 | Inline Title，使用对象名或简短类型名 | 节省空间并保持返回路径 |
| 编辑一条记录 | “编辑记录”或对象名 | 说明当前操作对象 |
| 临时筛选/创建 Sheet | “筛选”“新建项目”等短任务标题 | 减少用户迷失 |
| 图片/视频沉浸视图 | 可隐藏或在操作栏使用紧凑标题 | 让媒体成为主体 |
| 笔记正文/阅读页 | 内容有清楚文章标题时可省略重复导航标题 | 避免双重标题 |
| 登录/首次欢迎页 | 标题可以是任务文案而非导航标题 | 非常规层级流程 |

**【推荐】避免四种标题问题：** 同一短标题同时在导航栏和内容区重复；一级页永远只放 App 名称；每个分区都用过于醒目的 24pt 粗体；详情标题过长导致工具栏无法显示关键操作。

### 3.6 文本颜色与易读性

- 正文使用系统主要文本语义色；次级说明用 secondary label；更弱元信息可使用 tertiary label，但需验证实际对比。
- **【系统】常规小字对比应满足约 4.5:1；较大或加粗的文本在适用条件下可以采用 3:1。** 关键文本尽量使用系统语义色来随浅色/深色、高对比设置适配。[A03]
- 彩色底、照片、模糊层上的文字需要额外检查明暗关系；颜色不应成为唯一的错误/状态提示。
- 可点链接与普通正文应有可感知区别，必要时结合下划线、位置或明确的动作标签。

## 4. 导航、页面层级与功能入口分布

### 4.1 三种导航职责必须区分

| 导航结构 | 回答的问题 | 标准使用 | 建议视觉 |
| --- | --- | --- | --- |
| **Tab Bar** | “App 有哪些一级区域？” | 切换根区域，并保留各 Tab 中的浏览状态 | 底部系统 Tab，图标 + 标签 |
| **Navigation Stack** | “我在当前区域的第几层？” | 从列表进入详情、从详情进入子详情 | 系统返回、紧凑标题、自然推入转场 |
| **Sheet / Menu** | “我现在临时完成什么动作？” | 创建、筛选、选择、更多命令 | 任务完成即消失，保持原页面上下文 |

**【系统】Tab Bar 承担一级导航，页面操作使用 Toolbar 或内容区控件。** 使用“一个加号 Tab 用于新建”容易让导航和操作混淆。搜索 Tab 的特殊形式由系统设计为明确的全局搜索入口，属于可理解的专门模式。[A08][A09][A24]

**【推荐】一级 Tab 通常保持 3–5 个**，以内容语义分组决定数量。如果核心能力只有 2 类，也可以用两项；不为凑数量而增加“发现”“更多”之类弱入口。复杂产品可以把低频的账户/设置放在个人页或工具栏，不必都占一个 Tab。

### 4.2 底部 Tab Bar 的规则

- 文案使用短的名词或常见功能名，如“项目、搜索、消息、我的”，保持命名一致。
- 默认采用**图标 + 文字标签**；选中态使用系统填充/强调色和视觉权重区分，而非只依赖颜色。
- Tab 切换表示**上下文切换**；进入详情页仍位于原 Tab 的 Navigation Stack 中。
- 系统 Tab Bar 可以根据滚动和导航状态收缩/展开；iOS 27 允许设置持久可见的突出 Tab，具体取决于搜索等内容的重要性。[A08][A25]
- 跨 Tab 持续播放、录音或导航的任务，可以在 Tab Bar 上方使用系统 bottom accessory；不要把任意浮窗都塞到该位置。
- 内容应可在浮动底栏下延伸，并提供足够底部滚动余量，让最后一行完全可见与可点按。

### 4.3 顶部 Toolbar 怎么放

**【系统】Toolbar 是当前页导航、搜索与操作的容器。** 过多相邻图标会降低可区分性；操作按语义分组，iOS 新设计中系统会为图标按钮组提供共享的 Liquid Glass 背景，文字“完成/关闭”和强调按钮通常有独立视觉轮廓。[A09][A23]

**【推荐】常见布局：**

- **一级列表页**：左侧大标题/当前区域名；右侧最重要的“新建”或“编辑”，可再有一个“更多”。
- **详情页**：左侧系统返回；中间简短对象名；右侧编辑、分享等当前对象操作。
- **编辑页**：左侧取消/返回，中间任务标题，右侧完成/保存。若保存是极重要的主操作，也可使用底部醒目按钮；保持同类页面一致。
- **媒体页**：顶部少量返回/关闭/更多；媒体相关的播放、编辑、收藏可靠近内容或放底部工具栏。
- **搜索为高频任务**：在不与 Tab Bar 冲突时使用底部搜索栏/按钮，或者专用 Search Tab。

**操作优先级**：高频、即时、需要一键触达的操作留在可见栏；低频、批量、专业性操作放 `Menu`；危险操作置于明确的次级路径并使用破坏性样式。

### 4.4 功能入口选择矩阵

| 功能 | 最合适的入口 | 何时例外 | 推荐标签 |
| --- | --- | --- | --- |
| 首页、工作台、内容库、消息 | Tab Bar | 单一功能 App 可能不需 Tab | 首页 / 资料库 / 消息 |
| 返回上一层 | 导航栏系统返回 | 沉浸媒体可使用关闭 | 系统返回样式 |
| 新建当前类型的对象 | Toolbar 的 `+`、显著主按钮 | 大型创建流程可从专门的一级页面进入 | 新建、添加 |
| 保存 / 完成编辑 | Toolbar 右端“完成”或底部主 CTA | 长表单更适合固定底部按钮 | 保存、完成 |
| 全局搜索 | Search Tab；或清楚的全局搜索栏 | 内容量小可仅局部搜索 | 搜索 |
| 当前列表搜索 | 列表内容内/导航栏对应搜索 | 搜索是当前页唯一核心任务时可突出 | 搜索项目 |
| 筛选 | 搜索附近、Toolbar 筛选按钮、筛选 Sheet | 两三个高频筛选可直接用 segmented/chip | 筛选 |
| 排序 | 工具栏 `Menu` / 列表顶部菜单 | 高频的排序选项可做显式切换 | 排序方式 |
| 批量编辑 | Toolbar 编辑/选择 | 多选常驻业务可采用显式选择模式 | 选择、编辑 |
| 分享当前内容 | 详情 Toolbar 或对象操作菜单 | 媒体详情可放屏幕下方 | 分享 |
| 复制、重命名、归档 | 对象行的上下文菜单/更多菜单 | 高频操作可用滑动快捷项 | 复制、重命名、归档 |
| 删除 | 详情的危险操作区、对象 Menu / swipe | 误触成本高时附确认 | 删除 |
| 个性化偏好 | 设置页、个人资料页 | 单一设置可位于对应功能的二级页 | 设置 |
| 隐私、权限管理 | 设置里的独立分区 | 权限首次使用需就地解释 | 隐私与权限 |
| 常用状态切换 | 界面内 `Toggle` | 互斥多选使用 Picker | 自动同步 |
| 高级说明 / 帮助 | 控件旁辅助说明、信息页 | 首次操作可以显示短提示 | 了解更多 |

### 4.5 搜索入口的四种模式（WWDC 2026）

**【系统】搜索位置由搜索范围、产品导航形态和使用频率决定。Apple 在 WWDC 2026 提供以下场景：**[A24]

1. **底部 Toolbar 搜索**：适合邮件、记录、通讯录式页面。距离拇指较近，进入编辑时搜索框可以随系统转移至键盘上方；与少数其他高频工具共存。
2. **专用 Search Tab**：适合内容覆盖多个一级区域的产品；用户始终能在固定位置找到“全局搜索”。可提供搜索页与推荐内容，也可使用显著搜索入口并直接唤起键盘。
3. **顶部 Toolbar 搜索**：当底部被播放器、Sheet 或其他主功能占用，或搜索更接近当前页面工具时适用。
4. **内联搜索（Inline）**：适合当前资料库、相册、单个文件夹等局部范围；搜索框置于标题下或列表顶部，用户自然理解“搜的是这里”。

**搜索交互规则：**

- 搜索框保留放大镜、输入提示、输入后清除、获得焦点后的取消或退出机制。
- 搜索范围用标题、占位文案或清晰的筛选范围表达，例如“搜索当前项目”。
- 全局搜索起点可以显示最近记录、常用结果、类别；输入后快速展示匹配项和预测建议。
- 过滤条件显示当前选中状态并可重置；小范围互斥条件适合 Scope Bar/Segmented。
- 无结果状态应展示关键词或搜索范围、可修改建议或清除筛选入口。

### 4.6 列表、详情和编辑之间的层级

**【推荐】常规数据型 App 采用：**

```text
一级区域（Tab）
  └── 列表首页（大标题 + 搜索 / 列表）
        └── 对象详情（返回 + 紧凑标题 + 内容）
              └── 必要的子详情 / 附件 / 历史记录

临时任务：Sheet（创建 / 筛选 / 选择）
对象动作：Toolbar / Menu / Swipe Action
破坏性确认：Confirmation Dialog / 必要时 Alert
```

- **进入详情**：整行可点并有可识别的导航含义；靠右的 chevron 表示进入下一层。
- **返回详情**：保留滚动位置、筛选状态、选中 Tab，避免重新回到列表顶部。
- **编辑内容**：已有详情与编辑页可分开，也可就地进入编辑态；选择与保存必须清楚。
- **短任务**：一个明确目标、少量字段或选择项适合 Sheet。
- **多步骤任务**：复杂创建向导、付款、沉浸编辑适合专门页面 / 全屏流程。
- **外部深链进入**：无论从通知、链接还是搜索打开详情，都有清晰返回或关闭路径。

### 4.7 拇指可达性与键盘空间

- **【推荐】高频操作优先考虑中下部可达区域**，尤其创建、搜索、确认、播放；顶部放导航身份与少数全局命令。
- 底部主按钮放在安全区域之上；出现键盘时，根据编辑任务选择随键盘上移、滚动至可见区域，或暂时移除不相关底部控件。
- 主操作应当贴近它作用的内容；例如单条消息的发送按钮在输入栏，卡片收藏按钮在对象附近。
- 不以多个悬浮圆形按钮覆盖列表；底部系统 Tab Bar、播放器附属控件与页面 CTA 需要清晰的视觉和空间关系。

## 5. iOS 原生组件的具体选型与视觉细则

### 5.1 组件选型总表

| 用户需求 | 优先系统组件 / 模式 | 视觉与交互细则 |
| --- | --- | --- |
| 选择一级功能区 | `TabView` / Tab Bar | 图标 + 短标签；只负责导航 |
| 进入详情 | `NavigationStack` / `NavigationLink` | 有返回路径，保留上下文 |
| 常规记录与设置 | `List`、`Form`、`Section` | 保留系统分组和自动行高 |
| 单个主要动作 | `Button`（prominent） | 主次对比明确，一个场景一个视觉主动作 |
| 次要动作 | Plain / bordered button | 视觉上轻于主 CTA |
| 布尔状态 | `Toggle` | 直接开/关，即时显示当前状态 |
| 少量互斥视图 | `SegmentedControl` | 2–4 项最清晰；过多使用菜单或列表 |
| 枚举或多项选择 | `Picker` / `Menu` / 选择列表 | 按选项数量、说明长度选择 |
| 日期时间选择 | `DatePicker` | 根据界面选择 compact / graphical / wheel |
| 范围调节 | `Slider` / `Stepper` | 有单位、当前值、合适步长 |
| 文本输入 | `TextField`、`SecureField`、`TextEditor` | 标签、键盘类型、错误、焦点 |
| 列表局部操作 | `swipeActions` / `contextMenu` | 高频快捷项；关键操作有显式入口 |
| 当前页更多动作 | `Menu` | 行为按类别分组，危险项明显区分 |
| 轻量临时任务 | `Sheet` | 适当高度、拖动、取消/完成 |
| 长流程或沉浸任务 | 全屏页面 / full-screen cover | 逐步完成，退出方式清楚 |
| 多项动作确认 | `confirmationDialog` | 用具体动作名，危险项突出 |
| 必须打断的异常 | `Alert` | 短标题、说明后果、可选择路径 |
| 加载与进度 | `ProgressView` | 短任务即时反馈，长任务显示可理解进度 |
| 空内容、无搜索结果 | `ContentUnavailableView` | 解释状态 + 下一步 |
| 内容分享 | 系统 Share Sheet / `ShareLink` | 使用用户熟悉的系统分享入口 |
| 照片、文件、权限 | 系统 Photo / File Picker 等 | 跟随平台权限和选择习惯 |

### 5.2 按钮：形态、层级与状态

| 类型 | 适合场景 | 视觉建议 |
| --- | --- | --- |
| **Primary / prominent** | 保存、新建成功提交、主要下一步 | 48–56pt 视觉高度、明显填充、简洁动词 |
| **Secondary / bordered** | 取消、预览、次要选择 | 44–48pt、对比低于 Primary |
| **Tertiary / plain** | 工具栏命令、文字链接、行内操作 | 保留显式点击反馈，不额外包大卡片 |
| **Icon-only** | 返回、关闭、搜索、更多、添加等标准功能 | 图标 18–24pt，点击区域 ≥44pt，语义标签 |
| **Destructive** | 删除、退出、清空、移除 | 危险色与清楚后果，远离主提交 |

**【推荐】按钮的命名是动作，不是抽象概念**：写“创建项目”“保存修改”“删除记录”，少用“好的”“确定”“操作”。主次按钮并排时视觉上保留一个明显主按钮；狭窄情况下可纵向布局。图标加文字通常比孤立陌生图标更好理解。[A05][A18][T02]

**状态：** 默认、按下、禁用、加载、成功/失败按场景可区分；提交型按钮在执行中应避免重复触发。等待状态可保留按钮原位并展示进度，防止界面跳动。

### 5.3 列表、分区、单行信息与附件

- **Plain List**：通讯记录、搜索结果、文件目录等连续列表。行高由文本/图像自然决定；分隔线用于提示项目边界。
- **Grouped / Inset Grouped List**：设置、偏好、账户信息、分类表单。系统分组间距、圆角和边缘留白足以表达组别；少造额外卡片。
- **带副标题行**：主标题用 17pt Body/Headline，副标题 15pt 或必要时 13pt，二者前缘对齐；右侧值尽量不与长副标题争夺位置。
- **带图标行**：图标/缩略图统一视觉宽度和对齐轴；标题对齐到同一内容列，不按各图标大小随机改变缩进。
- **Chevron**：仅在点击后进入另一层级时显示；右侧如果已是 `Toggle`，一般不用再放 chevron。
- **Disclosure**：可展开内容用揭示样式，提供展开/折叠反馈；不将详情导航和本地展开混在同一个图标上。
- **Swipe Action**：可用于归档、删除、标为已读等高频局部快捷操作，主要功能仍能通过显式菜单或详情找到。
- **集合网格**：照片、商品、视觉作品适合 Grid；文字记录优先 List。网格单元之间约 8–16pt、整体边距与页面边距统一。【推荐】

【系统】列表内容应简短、行布局随 Dynamic Type 变化；分组标题和尾注负责解释整个分区，而非重复解释每一行。[A10]

### 5.4 选择器与设置组件

**Toggle（开关）**：用于两个互斥持久状态，如开启/关闭自动同步。标题写出功能，Footer 可解释“开启后发生什么”；不用于切换页面。状态变化即时生效或可立即感知。

**Segmented Control**：用于同一上下文下少量互斥视图，例如“全部 / 未读”、 “日 / 周 / 月”。**【推荐】2–4 项最舒适，5 项须确保短标签**；不要把 Tab 一级导航的内容塞在一个大 Segmented 中，也不要混用长短悬殊的标签。[A11]

**Menu / Picker**：低频选择、排序、显示方式适合 Menu；选项需要逐项解释或展示大列表时使用独立选择页；短枚举可使用 inline Picker。日期、时间、颜色等专用值优先系统对应选择器。

**Slider**：连续或分档范围，例如亮度、强度、音量；有可理解的当前值和范围。精确数值输入更适合 Stepper 或数字输入框。

**Checkbox / 多选列表**：用于同时选多个对象；在 iOS 中批量列表选择通常采用编辑/多选模式，而非网页式每行永久可见方框。可见的选择状态需与“完成/删除/移动”等批量操作衔接。

### 5.5 表单与输入框

**【推荐】业务表单用“可见字段标签 → 输入区域 → 说明/错误”的垂直结构。** Baymard 的移动表单研究发现，字段标签放在输入框上方有利于保持足够输入宽度；占位文本适合示例值，而不是唯一标签。[T03][T04]

| 情况 | 正确的表达方式 |
| --- | --- |
| 单一简单搜索 | `搜索`图标 + 提示文字即可，因用途与操作位置清楚 |
| 注册、地址、支付、创建项目 | 字段上方持续可见标签，文本框内给示例或格式提示 |
| 设置页内的短配置 | 系统表单行可左标签、右值/开关 |
| 输入可能不合法 | 错误信息紧贴该字段，说明具体修复方式 |
| 有长度/格式约束 | 在输入前或输入期间解释，不等提交后才暴露 |
| 输入数字、邮箱、电话 | 使用相应系统键盘；保证复制粘贴与自动填充 |
| 长文本编辑 | 多行增长或独立编辑区域，顶部简洁、内容区域宽敞 |
| 敏感输入 | 使用安全输入、恰当显示/隐藏与系统自动填充 |

**【推荐】字段布局：** 单字段与下一字段之间 **16–24pt**；标签与输入框约 **6–8pt**；输入框与直接帮助文本约 **4–8pt**；表单分组约 **24–32pt**。单行输入文字仍使用 17pt Body 作为主参考。

**内容行为：** 自动定位到错误项，聚焦字段时不能被键盘盖住；提交后成功/失败就地反馈；输入内容保留用户已完成的部分。不要在首次打开表单时无必要地自动弹出键盘，导致主要信息被覆盖。

### 5.6 Sheet、Popover、确认框与 Alert 的边界

| 形式 | 何时使用 | 高度/关闭与内容规则 |
| --- | --- | --- |
| **Menu** | 少量即时命令或选项 | 紧邻触发点，项目短而清晰 |
| **Popover** | 与某个控件紧密关联的小型说明或选择 | 轻量内容，不承载长表单 |
| **Sheet** | 新建简短对象、筛选、选择、临时编辑 | 中等或大型停靠位置；滚动、关闭、取消/完成明确 |
| **Full screen** | 沉浸内容、多步骤、密集编辑 | 适合完整导航和专注任务 |
| **Confirmation Dialog** | 需要在若干动作间明确选择，或危险操作确认 | 使用具体操作名称区分选项 |
| **Alert** | 必须立即注意的严重错误、重要系统状态 | 少量文字与清晰按钮；频率低 |

**【系统】Sheet 尺寸应由任务内容和交互决定。** 中等高度适合少量选项，大型 Sheet 适合可滚动内容或键盘输入；存在多个高度档位、需要用户拖动调整时使用清楚的拖动提示。iOS 的系统 Sheet 会处理圆角、手势和布局；减少复杂 Sheet 套 Sheet。[A12]

**【推荐】关闭语义统一：** 查看完成可用关闭；更改未提交内容时用取消/完成；危险动作名称直接显示后果。对于删除等可撤销的普通对象操作，可以优先采用撤销反馈减少频繁确认；彻底删除、清空大范围数据、注销账号等可加强确认。

### 5.7 空状态、加载、错误与权限请求

- **第一次使用空状态**：说明可以在这里做什么，并给出一个开始动作，如“还没有记录 / 新建第一条记录”。
- **搜索无结果**：显示“未找到相关结果”，保留搜索词，可提供清除筛选或重新搜索。
- **网络失败**：说明是加载问题，并有重试；已有的本地内容尽量保留。
- **加载少于短暂感知时间**：可以采用系统轻量进度反馈；内容较慢时，用占位布局稳定页面，避免整页无内容闪烁。
- **长时间任务**：进度可确定时展示进度量或阶段；可取消时提供取消入口。
- **权限前置解释**：说明访问相册/麦克风/通知/定位将为当前任务带来什么，随后使用系统权限界面；权限关闭后仍显示清楚的替代路径。
- **错误提示**：包含发生了什么和可以如何处理；字段错误尽量放字段旁，后台错误在关联内容位置显示。不要用每个小错误都弹出 Alert。[A13][A18]

## 6. 图标、文字标签、功能说明与信息密度

### 6.1 图标体系：优先 SF Symbols

**【系统】优先使用 Apple SF Symbols**。它与系统字重、基线、大小及某些状态动画有成熟的对应关系，还提供本地化变体。尽量保持同一页面图标的轮廓粗细与视觉密度一致。[A16]

| 用途 | 常用系统符号示例 | 应用原则 |
| --- | --- | --- |
| 首页 | `house` / `house.fill` | Tab 选中可使用填充变体 |
| 搜索 | `magnifyingglass` | 放大镜已高度通用 |
| 新建 / 添加 | `plus`、`plus.circle` | 所创建对象可由上下文/文字说明 |
| 更多 | `ellipsis`、`ellipsis.circle` | 低频操作的菜单入口 |
| 设置 | `gearshape` | 用于账户或设置区域 |
| 个人 | `person.crop.circle` | 个人资料、账户入口 |
| 分享 | `square.and.arrow.up` | 遵循系统 Share Sheet |
| 删除 | `trash` | 搭配危险色或明确文本 |
| 收藏 | `heart` / `heart.fill`、`star` / `star.fill` | 保持两种状态语义一致 |
| 编辑 | `pencil` | 操作对象应明确 |
| 过滤 | `line.3.horizontal.decrease` | 菜单或按钮附简短说明效果更好 |
| 关闭 | `xmark` | 独立于返回导航 |
| 展开层级 | 系统 chevron | 只表示继续进入/展开有含义的方向 |

**SF Symbols 的选择规则：**

- **outline（描边）**：常规工具栏、普通操作、列表行。
- **fill（填充）**：选中 Tab、收藏等状态或需要强调的控件；不要将全部图标做成填充以获取“高级感”。
- **笔画粗细**：与相邻文字字重协调；Headline 和图标靠在一起时不要一粗一细。
- **视觉尺寸**：自定义小工具约 18–20pt，常规工具 20–24pt，内容大图标 24–32pt【推荐】；系统组件图标保留系统默认。
- **点击区域**：图标外部扩展到合理的目标尺寸，**通常 44×44pt**。不要把 20pt 的可见图标直接等同于点击目标。
- **方向**：返回、前进、排序方向等优先系统符号，适配右向左排版与动态状态。
- **品牌图形**：自定义独立品牌符号仅用于产品独有概念；保持线宽、笔画转角和图标体积一致。

**【系统/第三方一致原则】** 图标的“好看”不能替代语义可辨识性。NNGroup 的图标研究建议重要导航使用常显文字标签，iPhone 无法依赖桌面鼠标悬停去解释陌生图标。[T02]

### 6.2 什么时候必须加文字标签

| 控件位置 | 文本标签 | 典型例子 |
| --- | --- | --- |
| 底部 Tab Bar | **建议常驻文字** | 首页、搜索、消息、我的 |
| 高度熟悉的系统导航按钮 | 可以只用图标 | 返回、关闭、搜索、分享、更多 |
| 不熟悉的业务动作 | **优先图标 + 文字** | 生成总结、发送到工作区、智能整理 |
| 对象级菜单 | **每项有具体文字** | 重命名、复制链接、归档 |
| 表单按钮 | 使用动作文字 | 保存、更改密码、完成 |
| 开关 | 必须有明确选项名称 | 同步照片、显示通知 |
| 颜色或状态标记 | 需要辅助文本或形状 | 同步失败、处理中、已完成 |
| 可理解但高风险动作 | 具体动作名 + 风险表达 | 永久删除、清空全部内容 |

**【推荐】Icon-only 的四个成立条件：** 其含义在 iOS 中高度稳定；当前场景能明确对象；操作风险低；点击目标与无障碍名称完整。只满足部分条件的功能使用文字。

### 6.3 功能说明的决策标准

用户无需阅读说明就能理解**这是什么、点了会发生什么、结果在哪里出现**时，说明文字可以省略。需要解释时，优先给**具体结果和必要前提**，长度以一行或两行为宜。[A18][T02]

| 情况 | 推荐说明方式 | 示例 |
| --- | --- | --- |
| 已有清楚名字和熟悉行为 | 仅标签 | “分享” |
| 生僻概念 / 新功能 | 一句具体作用 | “智能归档：自动整理超过 30 天的已完成事项” |
| 开关影响流量、存储、隐私 | 紧跟分区 Footer | “开启后，蜂窝网络下也会上传原始照片。” |
| 可撤销且状态明显的操作 | 轻量完成反馈，可带撤销 | “已归档 · 撤销” |
| 初次复杂操作 | 就地简短引导或一次性提示 | “长按条目可移动排序” |
| 需要权限才能使用 | 用途 + 收益 + 下一步 | “允许访问相册后，可选择图片作为封面。” |
| 输入格式有要求 | 永久可见标签 + 示例/帮助 | “邀请码（8 位字符）” |
| 没有内容 | 状态描述 + 可做动作 | “还没有收藏，浏览内容并添加喜欢的项目。” |
| 出错 | 原因或范围 + 修复方法 | “文件太大，请选择 20MB 以内的文件。” |

**不建议的说明表达：** “点击这里进入设置”“您可以使用这个功能来查看列表”“本按钮可执行保存操作”。这些文字重复可见按钮，增加阅读负担。

### 6.4 标题、按钮、状态文字如何命名

- **导航标题**：名词或当前对象，如“项目”“账单”“我的资料”；避免花哨营销口号。
- **动作按钮**：动词 + 对象，如“创建项目”“发送消息”“保存修改”。
- **选择项**：描述其当前/将要生效的状态，如“按最近修改排序”。
- **开关**：能自然完成“打开/关闭……”句式，例如“允许蜂窝网络同步”。
- **删除类**：直接写对象，如“永久删除这条记录”。
- **错误提示**：告诉用户可采取什么行动，不只输出错误码。
- **成功反馈**：短、可感知、尽量不打断，如“已保存”。

**【推荐】中文界面使用自然、具体、简短的口吻。** 同一业务动作在按钮、菜单、标题和确认内容中使用一致名称；例如都称“归档”，不要混用“保存至历史”“收纳”“整理”。

### 6.5 提示出现的位置

- **控件附近**：字段格式、开关后果、筛选范围、权限用途。
- **分区 Footer**：需要解释整组设置的共同规则。
- **轻量状态提示**：保存成功、归档完成、普通复制等立即反馈。
- **独立帮助页面**：多步骤概念、长期策略、复杂计算规则。
- **一次性引导**：确实不容易发现的首次复杂操作，尽量用真实界面上下文演示。
- **强打断弹窗**：高风险、必须立即选择的情形。

### 6.6 信息密度如何判断

**【推荐】工具类 App 的密度应“行内紧凑、分组舒适”。** 内容多不意味着每项都必须使用大卡片；列表能够天然保持较高扫描效率。信息重复、标题过大、全局留白过多会增加完成任务的滚动成本。

- **高密度适合**：邮件、文件、历史记录、日志、设置；使用稳定列线、系统列表、简短摘要。
- **中密度适合**：个人资料、单对象详情、阅读、项目概览；以清楚分区与 16–24pt 间距表达层级。
- **低密度适合**：首次使用、成功完成、空状态、媒体沉浸；突出单一任务和结果。
- **减少信息噪声**：对每项都显示五个操作图标时，收进菜单；对每项都写长说明时，归入共同的分区 Footer。

## 7. 色彩、圆角、边界、玻璃材质与模糊体系

### 7.1 颜色体系：语义先于十六进制

**【系统】优先使用系统语义颜色**，让页面跟随浅色/深色模式、高对比设置和系统状态。深浅两种模式分别审视文字、按钮、分割线、选中态和危险操作。[A17][A03]

| 视觉职责 | 推荐语义 | 用法 |
| --- | --- | --- |
| 页面底色 | System Background / Grouped Background | 选择普通或分组背景体系 |
| 内容表面 | Secondary System Background 等 | 仅用于需要显性分组的区域 |
| 主要文字 | Primary Label | 内容标题、正文、按钮文字 |
| 次要文字 | Secondary Label | 来源、时间、辅助解释 |
| 弱提示 | Tertiary Label | 非关键注释，保持可读性 |
| 细分隔线 | Separator | 列表中必要的视觉分隔 |
| 主品牌强调 | Tint / Accent | 主要按钮、可点链接、选中状态 |
| 成功状态 | 系统绿色等语义状态色 | 结合图标或文字，避免纯颜色判读 |
| 危险状态 | 系统危险红色 | 删除、严重失败、不可逆操作 |

**【推荐】单页面保持一个主要强调色，另有必要的语义状态色。** 不是每张卡片都要一个独立颜色；在常规设置列表和资料管理工具中，未染色或低饱和度图标通常更稳定。

### 7.2 背景分层和分割线

- **Level 0：主背景**。安静、连续的页面背景；大量日常 App 使用浅色/深色系统底色即可。
- **Level 1：内容分组**。通过系统 grouped list 或必要的次级背景区分。
- **Level 2：当前操作表面**。按钮、选择器、输入区域，有可感知交互状态。
- **Level 3：浮动系统控件**。Toolbar、Tab Bar、Sheet 等拥有独立的材质和遮挡关系。

**【推荐】结构的主要工具依次是：对齐 → 间距 → 字重/颜色 → 分组背景 → 分隔线 → 阴影。** 阴影用于真正悬浮的对象，普通静态列表无需每行有投影。

### 7.3 圆角、同心与视觉节奏

- 圆角是容器关系的表达：小标签约 8–12pt、普通自定义卡片约 12–16pt、较大媒体容器约 16–24pt。【推荐】
- 大容器内嵌小容器时，**内外圆角应呈自然递减关系**，并考虑内边距，视觉上形成相近的圆弧中心。
- 系统导航、Sheet、按钮和输入控件直接采用系统圆角与胶囊形状；避免把所有原生控件强行改成相同的 16pt 圆角。
- 同一页不宜同时存在大量互不相干的 8、12、17、23、30pt 圆角；自定义外形保持 2–3 个等级即可。

### 7.4 六种容易混淆的透明、玻璃与模糊效果

| 效果 | 原理与外观 | 适合用在 | 重要边界 |
| --- | --- | --- | --- |
| **Liquid Glass（regular）** | 动态透射/折射、适配背景光照的控件材质 | 系统工具栏、Tab、悬浮功能控件 | **导航/交互层**优先；系统组件自动采用 [A14] |
| **Liquid Glass（clear）** | 背景细节透过更多、透明感更强 | 照片、视频上的少量浮动控件 | 背景繁杂时补暗化，保证按钮清楚 [A14] |
| **Standard Material** | 系统磨砂、模糊和视觉融合 | 内容层的局部浮层、内容面板、说明衬底 | 遵循系统明暗与无障碍设置 [A14] |
| **Scroll Edge Effect** | 控件区与可滚动内容之间的边缘视觉过渡 | 顶部/底部浮动栏覆盖滚动内容处 | 自动样式优先；不用于纯装饰 [A15] |
| **Gaussian Blur** | 对整张图片/某个 View 均匀模糊 | 图片背景、失焦媒体、图像氛围 | 不适合模糊主要文字或操作控件 |
| **Masked / Progressive Blur** | 模糊量沿空间方向逐渐变化 | 图片边缘、媒体与文字的特定融合 | 自定义图片视觉可用；系统导航边界优先 Scroll Edge |

**这六项应按“功能职责”选择。** 普通内容区想获得一点半透明背景，使用系统 Material；内容滚动进入浮动栏时，使用 Scroll Edge；媒体图像需要氛围虚化时，用 Gaussian 或渐变遮罩；需要原生浮动控件层时由 Liquid Glass 承载。

### 7.5 Liquid Glass 的适用范围与密度

**【系统】Apple 的 Materials 文档明确将 Liquid Glass 视为导航和控件层，标准 Material 负责内容层的视觉分隔。** 系统组件可自动采用对应材质，应用不宜给所有普通卡片都叠加 Glass。[A14]

- **regular Glass**：首选。背景亮度变化时更容易保留前景文字与按钮的可读性；适合有文字的浮动控件。
- **clear Glass**：图片/视频等视觉丰富内容上方的少量控件。Apple 提到背景较亮时可考虑约 35% 暗化层，以提高对比；这是一个场景化建议，具体效果仍由系统、内容和用户透明度偏好决定。[A14]
- **容器组**：相关的系统 Toolbar 控件由系统形成共享材质组，避免每一个操作都叠一块单独玻璃胶囊。
- **层级控制**：一般页面只保留少量浮动玻璃区域，如顶部操作栏 + 底部 Tab；内容中不增加一整片玻璃卡片矩阵。
- **个性化与无障碍**：iOS 27 允许用户进一步调整玻璃透明与染色程度，设计需要适应该设置变化。[A26]

第三方 NNGroup 对 iOS 26 的分析指出，复杂背景与过量透明控件会损害可读性与可预测性；iOS 27 已对 Liquid Glass 对比与材质扩散作出改进。实际设计取舍应让内容始终居于视觉中心。[T01][A26]

### 7.6 Scroll Edge Effect：自动、soft、hard 的精确选择

**【系统】Scroll Edge Effect 用于“可滚动内容正在经过固定浮动控件下方”的交界处。** 它不同于覆盖一块固定半透明颜色或将整页模糊；它是专门解决层级可读性的系统效果。[A15]

| 样式 | 视觉特征 | 推荐使用 |
| --- | --- | --- |
| **automatic** | 由系统结合滚动、工具栏、文字和当前平台决定；iOS 27 有独立优化的视觉外观 | **默认首选** |
| **soft** | 靠近控件处有更自然的逐渐模糊，向内容区柔和消退 | 以图像、简单控件为主的轻盈过渡 |
| **hard** | 较不透明、边界清楚，能更强地把上层控件和文本与内容分开 | 工具栏控件密集、有裸露文字、固定表头等 |

**iOS 27 的重要变化：** `automatic` **不再只是从 soft/hard 中切换**，而是 Apple 为清晰度重新设计的独立默认效果；旧版本中习惯一律指定 `soft` 的视觉策略应根据当前设计语言重新考虑。[A25]

**边缘过渡的布局原则：**

- 上方有滚动标题栏/固定工具栏：交界处使用顶部系统 edge effect。
- 下方有底部工具栏/Tab 等浮动控件：由系统处理底部遮挡与过渡。
- 一块内容区原则上只使用一套滚动边缘效果，避免多个软、硬模糊层叠加。
- 如果没有浮动控件覆盖滚动内容，就不需要增加 edge effect 装饰。
- 浮动栏下的最后一行内容必须仍能滚动至完整可见的位置。

### 7.7 高斯模糊与自定义渐进模糊如何使用

**Gaussian Blur（高斯模糊）**是对所选图像/视图范围进行较均匀的视觉虚化。它适合**图片作为背景**的场景，例如专辑背景、照片详情的氛围图、模糊预览、背景弱化。

**【推荐】自定义图片虚化的起始参数（非 Apple 统一标准）：**

| 场景 | 可先尝试的模糊半径 | 注意 |
| --- | --- | --- |
| 保留形状的轻微图片柔化 | 4–8pt | 内容轮廓仍可辨识 |
| 图片背景与前景文字分离 | 8–16pt | 与暗化渐变或语义衬底配合 |
| 强氛围背景、专辑色彩扩散 | 16–32pt | 以色彩/大轮廓为主，不承担精确信息 |
| 更强的抽象背景 | 32pt 以上 | 仅在刻意追求抽象视觉时使用 |

**Progressive / Gradient Blur（渐进模糊）**指模糊强度**从 0 向某一值逐渐变化**，常用于照片底部由清晰过渡到模糊，或图像顶部自然融入文字区。它通常需要空间渐变控制或遮罩。建议过渡范围依据图片和文字块确定，常见可以从 **40–120pt** 的区域开始调整【推荐】，不要机械套在所有内容上。

**选择示例：**

- 相册详情页底部有照片说明：优先高对比文字衬底；背景仍需看见时考虑照片局部渐进模糊。
- 文章滚动到顶部工具栏下方：系统 Scroll Edge Effect。
- 项目详情中的一块普通透明说明面板：Standard Material。
- 需要创建类似系统胶囊的浮动导航：Liquid Glass 控件样式。

### 7.8 色彩与材质的透明度、阴影和对比

- **【系统】普通文字在混合背景上必须保持可读**。系统会依据用户的“增加对比度”“降低透明度”和 Liquid Glass 偏好调整材质；自定义透明区域也应有清楚的替代视觉。[A03][A14]
- **【推荐】纯色底 > 渐变底 > 玻璃底** 是普通工具页的一般优先顺序：越复杂的材质，越需要有明确的层级用途。
- 实际存在上下浮动关系时，可使用轻微阴影增强分离；Material、Glass 已提供层级感时无需再叠大幅投影。
- 不要将高饱和图片直接铺在整页正文背后；确有品牌背景时，为文本提供稳定的高对比表面。
- 卡片内不叠加多个渐变、描边、投影、玻璃与背景模糊效果来表达同一个层级。

## 8. 动画、手势、触觉反馈与状态变化

### 8.1 动画的作用

**【系统】动效应帮助用户理解动作因果、空间关系、状态反馈与内容切换。** Navigation Stack、Sheet、Tab、Toggle、Picker 默认拥有平台习惯的交互式运动；保留其原生节奏。[A19]

建议为自定义动画建立如下节奏，**这些时长是设计推荐起点，不是 Apple 强制参数**：

| 动画用途 | 【推荐】参考时长 | 推荐运动方式 |
| --- | ---: | --- |
| 轻触/按压反馈 | 100–180ms | 小幅透明度或高光/形态变化 |
| 选中态/开关旁附属提示 | 150–250ms | 颜色、图标与内容柔和过渡 |
| 图标替换、短提示出现 | 180–280ms | 淡入淡出、轻度缩放 |
| 小区域展开/折叠 | 200–350ms | 内容高度与透明度协同 |
| 卡片重排、插入/删除 | 200–400ms | 与布局变化同步，优先弹簧感 |
| 自定义面板、空间过渡 | 250–450ms | 距离与层级相符的移动/过渡 |
| 长流程、媒体主视觉 | 350–600ms，谨慎使用 | 仅在确有叙事或空间价值时 |

**【推荐】高频操作的动画要短且稳定。** 切换 Tab、列表选中、重复编辑不应持续出现夸张弹跳；系统组件的原生动画优先于统一“全站 300ms ease”。

### 8.2 动画与视觉层级的联系

- **进入下一层**：从当前位置进入详情，空间关系由原生 push/pop 表达。
- **临时覆盖**：Sheet/Popover 出现时，保留它与原页面的从属关系。
- **展开/折叠**：只改变当前对象的内容密度，不导致整页毫无规律地移动。
- **增删对象**：新条目从操作产生的位置进入列表；删除后相邻项目自然重新排列。
- **状态完成**：按钮/图标可短暂变化，任务结果在内容区更新。
- **滚动联动**：系统大标题收起、导航控件收缩等已有自然联动；避免叠加视觉无关的视差效果。

### 8.3 触觉反馈

**【系统】触觉用于强化有意义的操作与状态，而非给每一次触摸附加震动。**[A20]

| 场景 | 建议 |
| --- | --- |
| 在多个离散选项间切换 | 轻量 Selection 反馈 |
| 完成有明确结果的操作 | 一次轻量 Success 反馈 |
| 重要错误或不可继续 | 有节制的 Warning / Error 反馈 |
| 长按进入拖动/重新排序 | 进入交互态时给清楚反馈 |
| 普通列表滚动 | 通常不额外触觉 |
| 每次点击普通导航 | 原生按压视觉通常已足够 |

### 8.4 手势规范

- **侧边返回**：保留 iOS 熟悉的从边缘返回语义；避免用全屏横向拖动劫持返回手势。
- **滑动操作**：作为快捷入口，搭配可见替代路径。危险动作位置、颜色和可撤销行为明确。
- **长按菜单**：对具体对象的补充动作，例如复制、重命名、分享；主要功能不完全隐藏在长按里。
- **拖动排序**：给出拖动把手或明确可移动状态；结束后列表位置保持稳定。
- **捏合缩放**：图片、地图、画布等二维媒介适用；普通列表不需要自定义缩放。
- **下拉刷新**：适用于用户预期可手动更新的内容流，系统刷新指示自然出现；本地稳定数据无需每页强行下拉刷新。
- **滚动**：保留 iOS 弹性惯性，避免同方向 ScrollView 嵌套；有横向内容时显示局部露出的下一张卡片提示可滑动。[A21]

### 8.5 状态转移应保持布局稳定

- 按钮从“保存”变成“保存中”时保持大致位置和尺寸。
- 列表加载优先使用与最终行结构接近的占位布局，不反复触发全屏闪烁。
- 空状态 → 有数据状态，由当前内容自然过渡；避免所有元素大幅从屏幕外飞入。
- 对异步后台变化使用温和提示；重要状态改变要让用户看出发生了什么。
- 错误反馈贴近受影响对象，修复后自然恢复正常状态。
- 大型不可逆操作需要明确结果，同时让用户理解能否撤销。

### 8.6 减少动态效果与降低透明度

**【系统】尊重系统辅助功能偏好。** 用户开启 Reduce Motion 时，自定义大幅移动、重复缩放、强视差应改用更简单的淡入淡出或直接状态切换；减少透明度时保留足够清晰的不透明衬底。动态字体放大时，动效也应配合新的元素尺寸。[A03][A19]

### 8.7 主流工具类 App 的动画密度建议

- 常见导航、筛选、普通切换：**以系统原生效果为主**。
- 直接反馈（点击、选中、保存成功）：轻、短、清楚。
- 产品核心交互（可拖拽画布、项目卡片重排）：可增加针对性动作连续性。
- 首次引导和庆祝反馈：可有少量视觉个性，重复出现的频率降低。
- 持续背景漂浮、无意义光晕运动、每次都弹跳的按钮：只在明确的创意娱乐场景考虑。

## 9. iOS 原生与移动网页的设计差异

### 9.1 对比总表

| 维度 | iOS 原生 App 设计 | 移动网页 / H5 设计 | 实际设计取舍 |
| --- | --- | --- | --- |
| 尺寸单位 | `pt`、Safe Area、系统布局 | `CSS px`、`rem`、`vw`、容器/媒体查询 | iOS 的 44pt 和网页 44px 是不同坐标规范 |
| 主要运行环境 | OS 窗口、场景、系统组件 | 浏览器标签页、视口、地址栏、网页历史 | 原生考虑设备与系统控件，网页考虑浏览器容器 |
| 页面入口 | Tab、Navigation Stack、Sheet、深链 | URL、页面路由、浏览器后退 | 原生更重视稳定的导航栈与边缘返回 |
| 顶部结构 | 系统导航栏、工具栏、可折叠大标题 | 网站 Header、导航条、可自定义 Logo | 不要在原生页顶部重复完整网页站点头部 |
| 底部结构 | 系统浮动 Tab Bar、Bottom Accessory、Toolbar | 自定义 Bottom Nav、Sticky CTA | 原生优先系统底栏，避免覆盖手势区域 |
| 页面标题 | 系统 Large / Inline Title，按层级出现 | 网页标题、H1、SEO 与内容标题 | 原生页面可以省略重复大标题 |
| 字体体系 | SF Pro/系统中文字体、Dynamic Type | Web Font、CSS 字体栈、相对单位 | 原生字号跟随用户系统文字大小 |
| 主正文参考 | 17pt 的 iOS Body 语义字号 | 通常使用约 16px 或随产品设定的 rem | 不直接把网页字号抄成 pt |
| 点击尺寸 | Apple 默认 44×44pt 的触控参考 | WCAG 2.2 AA 目标通常 24×24 CSS px（含例外），AAA 增强目标 44×44 CSS px | 重要移动网页操作也推荐更舒适触控面积 [T05][T06] |
| 列表组件 | `List`、`Form`、`Section` 和系统 inset | 自定义表格、Flex/Grid、DIV 列表 | 原生列表天生拥有更完整的交互与状态习惯 |
| 选择控件 | 系统 Picker、Toggle、DatePicker、Menu | `select`、表单控件或 UI 组件库 | 不必将网页式下拉菜单带进 iOS |
| 弹层 | Sheet、Popover、Confirmation Dialog、Alert | Modal、Drawer、Dialog、Toast | 原生 Sheet 支持系统停靠位置、手势和键盘 |
| 搜索 | 搜索 Tab、Toolbar、内联搜索；系统焦点行为 | Header 搜索、搜索页、输入栏 | 原生可以把高频搜索放到底部易达区域 |
| 模糊/材质 | Liquid Glass、Standard Material、Scroll Edge | `backdrop-filter`、CSS `filter`、渐变遮罩 | CSS 毛玻璃不具备 iOS 系统材质完整语义 |
| 图标 | SF Symbols、动态字重、本地化 | SVG、Icon Font、自定义图标 | iOS 尽量延续系统图标语言 |
| 滚动 | 系统弹性、惯性、下拉、边缘效果 | DOM Scroll、滚动容器与 sticky | 避免用网页式滚动容器重绘原生主界面 |
| 输入 | 原生键盘、自动填充、焦点与键盘避让 | HTML 输入类型、软键盘与浏览器适配 | 原生要处理键盘与底部工具栏的关系 |
| 分享/文件 | 系统 Share Sheet、文件/照片 Picker | Web Share / File Input / 下载等 | 原生使用用户熟悉的系统操作流 |
| 反馈 | 原生按压、选择、弹簧转场、触觉反馈 | CSS 过渡、JS 动画、点击态 | 原生先沿用系统运动，再添加少量自定义 |
| 无障碍 | VoiceOver、Dynamic Type、Reduce Motion 等 | 语义 HTML、ARIA、WCAG、键盘导航 | 各自依赖平台的语义与辅助技术 |
| 屏幕适配 | Safe Area、trait/size class、iPhone/iPad 场景 | viewport、媒体/容器查询、浏览器 UI | 两者都要响应式，但边界条件不同 |

### 9.2 为什么“网页样式写成 SwiftUI”仍然不像原生

**以下是常见的网页感来源：**

1. **每个功能块都是独立圆角卡片**：大量圆角矩形、灰色描边和投影，让设置、记录、筛选失去系统列表的连续感。
2. **顶部同时有品牌 Header、面包屑、大标题和副标题**：重复的身份信息使首屏被占据，原生导航层级变得不清楚。
3. **自绘 Tab 和返回按钮**：按钮位置、点击区域、返回手势和系统动画与平台不一致。
4. **把网页下拉框、确认弹窗、输入框照搬**：缺少 iOS 的 Picker、Sheet、键盘和上下文操作习惯。
5. **单纯依靠图片、渐变、透明边框表达层次**：内容与操作分不清，较弱的文字对比尤其明显。
6. **固定高度和单一设备截图坐标**：系统文字放大、键盘弹出、宽屏与 iOS 27 可调整窗口时产生裁剪。
7. **图标隐去文字、交互隐藏在 hover**：触控设备缺少鼠标悬停，重要功能发现成本上升。[T02]
8. **全部元素使用自定时长动画**：导航、表单和弹层失去系统原本连贯的交互节奏。

### 9.3 相同需求在两种平台上怎样重新设计

**例 A：项目管理首页**

- **iOS 原生**：顶部系统标题“项目” + 右上“新建”；当前项目作为分组 List；点击行进入详情；底部 Tab 用于“项目/消息/我的”。
- **移动网页**：可能需要站点品牌、账户导航、URL 页面结构和自定义分页；常见 Header + 内容区 + Sticky CTA 更依赖浏览器上下文。

**例 B：编辑个人资料**

- **iOS 原生**：系统导航的“取消/完成”；基本信息 Form；头像打开系统照片选择器；保存后返回详情。
- **移动网页**：HTML Form、浏览器自动填充、按钮提交与 URL 转场；响应式调整标签和字段宽度。

**例 C：搜索已有记录**

- **iOS 原生**：根列表可内联搜索；跨多个区域时考虑 Search Tab；焦点进入后出现系统取消与键盘处理。
- **移动网页**：搜索可以是站点全局 Header 入口或单独 URL，页面滚动和浏览器地址栏会影响可视高度。

**例 D：模糊底部控件**

- **iOS 原生**：系统 Tab / Toolbar 使用 Liquid Glass，内容进入固定控件区域时由 Scroll Edge Effect 保持层次。
- **移动网页**：CSS `backdrop-filter` 和渐变遮罩需自行控制透明度、边缘行为、对比与兼容性。

### 9.4 iPhone 与 iPad 的差别

- **iPhone 窄屏**：根区域优先底部 Tab；页面通常单列；标题可从 Large 折叠为 Inline；操作靠近被操作对象。
- **iPad 宽屏**：相同内容可以侧栏 + 列表 + 详情并列；Toolbar 容纳更多可见命令；Popover 可代替部分全屏 Sheet。
- **iPhone 横屏 / 可调整大小窗口**：根据实际宽度改变列数，避免按“设备是不是 iPad”决定唯一布局。
- **iOS 27**：iPhone App 在 iPad 和 Mac 的 iPhone Mirroring 环境中更强调尺寸可调整；Sidebar 能否出现取决于界面宽度与应用设计选择。[A25]
- **同一个 App 设计语言一致**：字体语义、图标、色彩、控件行为保持统一，布局形态随可用空间变化。

### 9.5 一套适合工具 / 效率类原生 App 的默认设计参数

此表把分散在前文的推荐选择汇总为**设计系统默认值**，用于方案、视觉稿与组件库保持一致；系统组件始终优先保留系统尺寸和样式。

| 项目 | 默认建议 | 使用边界 |
| --- | --- | --- |
| 页面左右内容边距 | **16pt**；阅读型 **20pt** | 系统 List/Form 使用自带 inset |
| 间距节奏 | **4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48pt** | 组内 8–12、组间 24–32 |
| 主正文 | **Body 17pt** | 支持 Dynamic Type |
| 次级说明 | **Subheadline 15pt** / Callout 16pt | 以是否需要阅读为准 |
| 时间元信息 | **Footnote 13pt** | 保留足够对比 |
| 一级标题 | 系统 **Large Title 34pt**（适用时） | 详情通常 Inline |
| 局部标题 | Headline 17pt Semibold / Title3 20pt | 一页不过度增加层级 |
| 常规文字字重 | Regular；重点 Semibold | Bold 限少量强强调 |
| 触控区域 | **44×44pt** 的默认目标 | 视觉图标可以更小 |
| 主按钮 | 高 **48–56pt** | 内容/动态字号增长时自动增高 |
| 列表行 | 约 **52–64pt** | 系统自动内容高度优先 |
| 内容图标 | **18–24pt** | 统一 SF Symbols 字重 |
| 自定义卡片圆角 | **12 / 16pt** 为主 | 系统控件保留系统圆角 |
| 一级导航 | **Tab Bar 3–5 项（常见建议）** | 按业务数量决定 |
| 列表间分组 | **24–32pt** | 使用系统分组样式时不叠额外大空白 |
| 页面背景 | 系统语义背景色 | 默认支持浅色/深色 |
| 强调色 | **1 个主要 Tint 色** | 语义状态色按需存在 |
| 材质 | 导航层用系统 Glass；内容层用标准背景/Material | 默认为内容可读性服务 |
| 滚动边缘模糊 | **automatic** | 有明确需求再选 soft/hard |
| 图片轻度高斯模糊 | **4–8pt** 起始 | 仅图像视觉处理 |
| 图片较强高斯模糊 | **16–32pt** 起始 | 媒体氛围处理 |
| 图片渐进模糊范围 | **40–120pt** 起始 | 根据媒体和文字区调整 |
| 微交互动画 | **100–200ms 左右** | 原生系统动效无需统一覆盖 |
| 一般自定义过渡 | **200–350ms 左右** | 大幅空间转场按距离调整 |
| 文案 | “动作 + 对象”，陌生功能说明结果 | 系统标准控件无需重复解释 |
